## What was seen

1. Settings > Command line tool refused to install: a link was at `~/.local/bin/anima` and pointed into a worktree that was deleted. The orchestrating session removed the link.
2. The same row said that `~/.local/bin` is not on the login shell PATH. His login shell in the account database is `/bin/zsh`. He works in fish, where the folder is on the PATH.

## Cause, from the code

Read in the code of `dev` at `3353f648`. Not run.

1. The refusal is right. INS-006: "The application must not replace a file that it did not make." A link that points to a place outside an Anima.ing application is not a link that the application made, whether its target exists or not. The message names what is in the way and its target, and says "Move or delete it, then install." (`apps/client/src/lib/updates/command-line.ts`, `refusalText`). Not a fault. One improvement is possible: say that the target of the link no longer exists, because then the person knows that to delete it loses nothing.
2. A fault of the words, not of the check. `apps/desktop/src-tauri/src/command_line.rs`, `login_shell`: the shell is the one of the account database, else `$SHELL`. `command_line/login_path.rs` runs it with `-l -c` and reads its `PATH`. That is what a new terminal with default settings gets, so the check is correct for the question it asks. But:
   - the row says "the login shell PATH" and does not say which program that is (`apps/client/src/lib/updates/CommandLineRow.svelte`). A person who works in a different shell cannot know why the application disagrees with the terminal;
   - the line that the row gives for the shell profile, `export PATH="$HOME/.local/bin:$PATH"` (`command_line/directory.rs`), is for a POSIX shell. It is not the syntax of fish.

## Effect

A person whose terminal starts a shell that is not the login shell gets advice that is wrong for that terminal, and may add a line that is not needed. Nothing is damaged: the application never changes a profile, and the installation works.

## To do

Nothing is corrected.

- [ ] The row names the shell that it asked: "`~/.local/bin` is not on the PATH of your login shell, /bin/zsh. If your terminal starts a different shell, look at the PATH there." The shell status of the desktop shell must then carry the path of the shell.
- [ ] Give the profile line only when the login shell is a POSIX shell (sh, bash, zsh, ksh, dash). For a different shell, say only which folder to add.
- [ ] Optional: when the link in the way has a target that does not exist, say so.
