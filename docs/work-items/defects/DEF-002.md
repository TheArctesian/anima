## What was seen

The page Agent usage showed its empty state: "No use counts yet. The daemon of each device reports the use of the AI agent programs. Install the daemon on a device to start." with the link "Install daemon". His words: "isntall a dameon redirect to the home screen". He expected a way to install the daemon.

## Cause, from the code

Read in the code of `dev` at `3353f648`. Not run in the application.

- `apps/client/src/lib/agent-usage/AgentUsageScreen.svelte`: the link was `href={resolve('/devices')}`. The mockup of the page said the same: "The action leads to the Devices page, where each device has its Install daemon panel."
- `/devices` is the list of the devices. It is also the home screen: `apps/client/src/routes/+page.ts` sends `/` to `/devices`. Thus the link did what it was written to do, and no redirect failed.
- The list of the devices has no control that installs a daemon. The panel "Daemon" is in one device: the device, then Settings (`apps/client/src/lib/metrics/daemon/DaemonPanel.svelte`). The address that opens it is `/devices/<id>?tab=settings#daemon`. Nothing on the Agent usage page or on the list said so.

This is the same on each hub: a local hub, a hub on the VPN and a hosted hub.

On a hosted hub there is a second cause, which stays after the person finds the panel:

- The application reaches a hosted hub through its link, at `http://127.0.0.1:<port>`. The panel makes an enrolment code at the hub and then refuses the command: `apps/client/src/lib/metrics/daemon/command.ts` accepts only an `https` origin on port 443 (MET-020). The person saw "No install command: the hub address is not a plain https origin."
- The button "Install on this computer" is not offered: it is offered only when the host of the device is the VPN address of this computer (R-060), and on a hosted hub the host is the link address.
- The daemon itself refuses `http://127.0.0.1:<port>` since task W0 (R-172; K8 Section 1) and accepts `unix:<path>` of a socket that `anima-link device -daemon-socket <path>` makes. The link of the desktop application does not make that socket.
- A local build (`trial-bundle.sh`) does not carry `anima-daemon`; a released application does (`tauri.release.conf.json`).

Thus no path installs the daemon of a computer at a hosted hub today. That was the open decision HM-D16. The operator decided it on 2026-11-19 (R-206): the desktop application includes the daemon and installs it. The work is in [hosted-mode.md](../../proposals/hosted-mode.md) Section 7.1.

## Effect

- On each hub: a person who has no daemon gets a link that looks as if it did nothing.
- On a hosted hub: the Agent usage page, the metrics from a daemon and each other function that needs a daemon on a device cannot be used.
