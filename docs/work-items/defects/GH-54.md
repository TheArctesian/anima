**Found:** 2026-11-07, O-3, Linux desktop app (AppImage from main, WebKitGTK) on Pop!_OS 24.04 → macOS Screen Sharing.

**What happens:** pointer and input reach the Mac immediately (the Mac's own screen changes at once), but the picture inside the Anima session on Linux updates noticeably later. The VPN path is direct (`tailscale status`: direct to the hub, 34 ms round trip), so the network is not the obvious cause. The Mac app viewing the Linux machine did not show a comparable complaint.

**Not measured yet.** Suspects: WebKitGTK canvas drawing of the Guacamole display (possibly without GPU compositing), or the Linux web view's frame scheduling. Also seen at each AppImage start: `GStreamer element appsink not found` (likely unrelated: media playback).

**Next steps:**
- Measure frame-to-screen delay of the same session in the Mac app and the Linux app.
- Try the Linux app with and without `WEBKIT_DISABLE_COMPOSITING_MODE=1` / `WEBKIT_DISABLE_DMABUF_RENDERER=1` and compare.

The spec has no display-latency target for sessions (MOT-001 covers controls only; OD-11 notes latency as a later concern).
