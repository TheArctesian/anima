**Found:** 2026-11-07, O-3 (VNC to a Linux desktop), Mac app → `pop-os` running wayvnc 0.10.2.

**What happens:** the session toast says "The gateway reported an error and closed the VNC session". guacd logs only `ERROR: Unable to connect to VNC server.` The real cause, from wayvnc's side, was a rejected login: wayvnc offers `rsa-aes256, rsa-aes128, apple-dh, 3des`; guacd's libvncclient picks Apple DH, which sends the stored VNC user name. R-079 pre-fills that user name with this computer's OS user (`okita`), while wayvnc had no `username` configured (expects empty), so it rejected the login. Setting `username=okita` in wayvnc's config fixed it at once ("User "okita" authenticated").

**Problems:**
1. The operator cannot tell a login failure from a network failure: both read "Unable to connect" / "the gateway reported an error".
2. For a Linux VNC server, the pre-filled user name (R-079) can silently break login with servers that check it (wayvnc with apple-dh).

**Suggested:**
- Map guacd's authentication failures to a credential error that opens the credential prompt (GW-015) instead of the generic toast, if guacd exposes the distinction (status 0x0301/0x0303 vs 0x0200).
- For Linux devices, consider not pre-filling the VNC user name, or say in the VNC section hint that it must match the server's user (wayvnc `username`).
