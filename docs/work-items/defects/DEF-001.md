## What was seen

A build of the desktop application with the version 0.2.2 ran on the Mac of the operator. It was made on that Mac and was not published; the published version of macOS was 0.2.1. With no question, the application showed the message "Anima.ing 0.2.1 is installed". After that, `/Applications/Anima.ing.app` reported the version 0.2.1 while the process of 0.2.2 still ran. Thus the application put the older published version in its own place on the disk.

## Cause, from the code

Not run again; read in the code of `main` at `aae8831e`.

- `apps/desktop/src-tauri/tauri.conf.json`, `plugins.updater`: `"allowDowngrades": true`. The row "Rollback" of Section 3.9 of the design specification asks for it, so that the operator can go back to an older release by a change of the feed.
- With that setting, the updater takes a feed whose version is different from its own, also when it is lower.
- `apps/client/src/lib/updates/schedule.ts`: when the check finds a version, the application downloads it and installs it with no question (UPD-003).
- `apps/client/src/lib/updates/desktop.svelte.ts` starts the checks for each build that is not a development build (UPD-001). A release build that a person makes on a computer is not a development build, so it checks the public feed.

## Effect

- A version that is built on a computer and is newer than the published one cannot stay installed: at its start, or 4 hours later, it replaces itself with the published version. This is so for each build that is made to test a release before it is published.
- The same occurs for each installed application if the feed gets a lower version, by an error or by a person who can write the feed. The signature of the updater file is still checked (UPD-002), so only a version that the hub signed can be installed. An old version that has a known weakness is such a version.
