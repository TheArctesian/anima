Found by the security review of the MCP server on 2026-11-13. Shown from the code. Not run against a real hub.

The hub keeps the SNMP community and the v3 passwords of a check when the host of its device changes (`crates/hub/src/checks/rules.rs`, about lines 182 to 188). The probe then uses the new host (`crates/hub/src/checks/probe.rs`, about line 123).

Thus a person or an AI agent that can call `updateDevice` (a login token is necessary) can set the host to an address that they select in a permitted network. The next SNMP check sends the community there.

For an HTTP check, the hub already asks for the secrets again when the URL changes (SEC-005).

## To do

- [ ] When the host of a device changes, the hub must ask for the SNMP secrets of its checks again, or clear them, as it does for an HTTP check URL.
- [ ] A test that proves it.

Recorded in `docs/cli-mcp-plan.md` Section 9. Until this is done, `anima_device_update` in the MCP server is a tool for a login token only, and it is off by default.

## Comments on the issue

### 2026-11-13, TheArctesian

Fixed and on main (596bac05). SEC-010: an SNMP secret is bound to the host that it was entered for; the probe sends nothing to a different host. SEC-011: the same for the SSH, RDP and VNC credentials of a device. After a change of the address of a device, the operator must enter its credentials again.
