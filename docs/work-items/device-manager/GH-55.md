## Goal

Keep the site-local work from Phase 6 together as a later follow-up, behind the extension foundations and compute resource sharing and sharding. Phase 2 Wake-on-LAN through the SSH relay is acceptable for current use (RA-031, VPN-006).

## Site-local operations

- Evaluate replacing the SSH wake relay with an authorized local agent that sends the Wake-on-LAN packet inside the device's site. Define site assignment, operation permissions, failure reporting and the relay migration or fallback before changing the existing wake path.
- Evaluate running selected checks from inside a site. Define eligible check types, how the hub assigns them and receives results, and what happens during a disconnect. Apply the existing probe and result protections (spec Section 6.4).
- Verify a wake and a local check from the correct site. Exercise refused operations and the case where the site runner is unavailable.

## Optional traffic metadata

- Evaluate Pi-hole DNS query metadata and subnet-router flow records from `conntrack` or nftables (spec Section 4.3). Collect metadata only and exclude packet payloads and other traffic content (TRF-001).
- Limit access to the operator and keep the data inside the network (TRF-002). Collection starts only after explicit opt-in for each site. At a shared site the operator must have permission to record it (TRF-003).
- Enforce retention of 30 days for raw metadata and one year for summaries (TRF-004). Verify the site opt-in, access controls and expiry for both retention periods.

## Open design questions

- Can the existing agent or a worker from Phase 3 dispatch run these operations safely? Determine what must run on the site, which identity authorizes each operation and whether a separate process is needed. Review any transport or privilege change against R-084 and MET-013/MET-020.
- Which local operations warrant a non-SSH path, and when should SSH remain the operational fallback? Can each site capability be adopted separately?
- Which traffic sources are useful at each site, and where should the collection run? Confirm privacy boundaries before enabling collection.

Track this under the deferred Phase 6 row in the design specification. Desktop builds, R2 publishing and GitHub job dispatch remain Phase 3 work. Compute resource sharing follows its own C1–C6 acceptance and feasibility gates.
