The audit log records the operator name and the client address. It cannot tell an AI agent from the operator, or an API key from a login token.

Operator, 2026-11-13: "We can clasify agent (meaning AI agent did the work, Hub meaning code did the work and User meaning human did the work".

Specification: `docs/design-spec.md` on branch `claude/spec-cli-distribution` (commit 060f87e8). It is not on `main` yet. Section 3.8.1.

## Requirements (not built)

- LOG-012: each audit entry has an actor kind: User, Agent or Hub.
- LOG-013: each event entry has an actor kind.
- LOG-014: the hub decides in this order: Hub, then Agent, then User.
- LOG-015: an API key is made for `USER` or `AGENT`. The value is fixed at creation.
- LOG-016: `anima mcp` declares itself: the header `Anima-Actor: agent`, and the same field in `connection_init`.
- LOG-017: a request can never lower its kind. A client can raise itself to Agent. It cannot claim User.
- LOG-018: the entry records the token kind and, for an API key, its name. Never the token (LOG-007).
- LOG-019: requests with a builder token or an agent token are recorded as Hub.
- LOG-020: shown in the audit list of the client, in `anima audit list --actor`, and in `anima_audit_list`.

## Limit

The program makes the declaration. A program that runs with the login token of the operator and does not declare itself is recorded as User. The reliable way to mark agent work is an agent API key.
