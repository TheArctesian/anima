## Approved foundation: shared connections and reliable imports first

Connection/account records and sync progress are shared across trusted Anima servers. Keep one source shape for declarations, accounts, sync runs and health. Build these records and retry-safe imports first. Automatic takeover/failover and the Settings > Integrations screens are later work.

This defines shared state and ownership behaviour; it does not select a backend or claim that a distributed replication/coordinator architecture already exists.

### Connection and credential contract

- Declare each source's identifier, acquisition method, scopes and supplied records (SRC-001). Retain OAuth pull, token pull, collector push and file upload (SRC-002).
- Keep the source, account label, instance key, credential reference, sync state, last sync time/error, failure count, preferred server and active worker ownership for each connection (SRC-003). Keep source identity stable across servers; the same connection must not be recreated separately by each server.
- Reference operational credentials from the central VPS key vault in [E0-6](E0-6.md), reusing the existing `credentials` domain (SRC-008). Servers use its authenticated retrieval, versioning and protected-cache lifecycle. Do not embed values in connection records or create another credential store. Provision provider accounts only as needed through [KEYS](../extensions/KEYS.md).
- Keep sync state as one JSON value with each provider normaliser confined to its own part (SRC-004). Normalisers stay pure: provider response and state in; records, proposed new state and problems out. I/O stays at the storage/network boundary (SRC-006).

### Initial import and ownership behaviour

- Run at most one active sync worker per connection. Record the preferred server and use a short, renewable ownership lease. Define lease acquisition, renewal and ownership checks at an authoritative coordination boundary; shared copies of records alone do not establish ownership.
- A worker that loses its lease must stop. Reject commits/checkpoint updates by an expired or stale owner. Settle the lease duration, owner generation/fencing mechanism and commit checks in the contract before implementation; do not infer safe peer coordination from a timestamp in replicated state.
- Store each batch successfully before persisting its cursor/checkpoint (SRC-007). If records are stored but checkpoint persistence fails, replay must be safe. A failed/partial batch must not advance progress past records that have not been stored.
- Make retries idempotent independently of worker ownership (SRC-012): use stable source/account/record identifiers, update existing records rather than insert duplicates, and compare before writing so an unchanged replay writes nothing. Test retry and crash boundaries; one worker alone does not prevent duplicates.
- Retain original provider records in the owning domain tables so canonical mappings can be recomputed (SRC-011). Record run trigger, start/end and inserted/changed/unchanged/removed counts (SRC-005).
- Retain health states OK, Starting, Stalled, Never synced, Paused and Needs reconnect, derived from failure count/last sync time (SRC-009). Keep errors/audit output free of tokens and secret values (LOG-007).

### Device locality is preserved

A collector reading Mac-only sources or selected local folders runs on the device that can access them. Shared credentials, connection records and checkpoints do not make those files available to other servers. Bind the source to its required device/capability; if that device is unavailable, report/wait rather than assign it to an arbitrary server. [E0-3](E0-3.md) retains local collector execution, redaction, narrow ingest tokens, read positions and bounded offline queues.

### Existing provider rules retained

Request read-only scopes; document the reason in the declaration when a provider offers none (SRC-010). OAuth remains desktop loopback redirect with PKCE: the client sends the code to the hub, which exchanges it; verify provider loopback support (SRC-020). Poll sources rather than receive webhooks, defaulting to 15 minutes or a longer provider interval for rate limits (SRC-021). No source-write capability is added by this issue.

## Later work

- **Automatic takeover/failover:** after reliable imports and the authoritative lease/coordinator contract are proved, allow another eligible server to take ownership under the lease rules. Demonstrate that the old owner cannot commit after handover, including reconnect/partition cases. Local-only sources remain restricted to devices with access. Initial delivery must not advertise automatic failover; loss of an owner may pause a connection until recovery or an explicit safe reassignment.
- **Settings > Integrations UI:** retain `settings/integrations` as a Settings section, not a new navigation item, with Sources and Outputs tabs (ENG-002, ITG-001–008). Later screens retain grouping by extension, health/last sync, account/scopes, the last 20 runs/counts/problems, Sync now/Pause/Disconnect, keep-or-delete confirmation on disconnect, upload/last-file controls, and links from extension pages. Outputs retains Prometheus, API keys and notification channels; reuse their existing infrastructure.
- Retain the Stalled-for-24-hours event/reminder requirement (ITG-007), coordinating reminder delivery with [E0-7](E0-7.md). It does not require the Integrations screen to be built first.

## Acceptance criteria

- Two trusted servers refer to the same connection/account identity and stored progress without copying credentials into connection state; retrieval follows [E0-6](E0-6.md).
- Demonstrate single active ownership and renewal, stopping on lease loss, and rejection of expired/stale owner commits through the agreed authoritative boundary.
- Inject a failure before batch completion, after records are stored but before checkpoint persistence, and during retry. No records are skipped, no duplicates are added, existing records update correctly and unchanged replay writes nothing.
- Demonstrate pure provider normalisation, retained raw records, run counts/health, read-only acquisition, polling and loopback OAuth/PKCE where applicable; no secret appears in logs/errors.
- An unavailable device-local collector is not reassigned to a server without source access.
- Do not mark automatic failover complete until takeover, stale-owner rejection and partition/reconnect behaviour are separately proved. New UI is not required to accept the initial foundation.

**Open design questions:** shared-state/replication backend, authoritative lease coordinator, fencing/commit protocol, lease/renewal durations and recovery policy. These remain explicit contract decisions, not an adopted distributed architecture.
