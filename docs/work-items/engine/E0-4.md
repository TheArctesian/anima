## Approved foundation: consistent time and persistent record references

Agree the time, clock and record-identity/reference contracts first. Add concrete links and timeline adapters when real consuming features need them. History/timeline screens remain later work; do not build a speculative universal framework or new feature workflow here.

### Event instants and clock synchronization

- Use Unix timestamps universally for event **instants** exchanged/stored across Anima machines. Choose and document one wire unit/precision and conversion rules before implementation; seconds versus milliseconds (or another precision) is not decided by this approval. Never interpret a machine-local display time as the shared instant.
- Apply time zones when presenting instants. Changing a device's time zone must not change the recorded instant or rewrite historical source timestamps. Preserve source time, offset/time-zone context and precision/uncertainty where relevant to interpreting the observation.
- Participating machines must actually synchronize their clocks. A Unix representation alone does not synchronize clocks. Define how clock synchronization/skew is checked and reported, the acceptable skew and behaviour when a clock is unreliable. Do not claim exact cross-machine ordering from unsynchronized clocks.
- Distinguish source event time from ingest/receipt time where needed. A delayed import keeps the event's original time; receiving it later must not overwrite that history. Unknown/approximate source time remains explicitly uncertain rather than silently replaced by an ingest timestamp.
- Local calendar dates, recurring schedules and their time-zone metadata are not all event instants. Preserve their meaning instead of blindly converting them to Unix timestamps or inventing midnight instants. This is a representation boundary, not new scheduling scope.

### Persistent identities and links

- A record has a stable identity that persists across imports, domains and machines. References resolve to that same object rather than duplicate its source record. “Pointer” means a persistent identifier/reference, not a process memory address, machine-local row identity or a selected ORM/backend.
- Define identifier namespace/uniqueness, source identity mapping, reference resolution and behaviour for absent/deleted targets in the contract. The actual ID encoding and distributed replication mechanism remain open.
- Retain the shared record-link semantics: source reference, target reference and link kind (LNK-001). A project may refer to its Claude session; a lent book may refer to a person. These illustrate the contract, not approval to implement those feature workflows now.
- A target may not exist/be available yet; retain the fallback label and unresolved reference rather than copying another domain's record or making one extension wait for another (LNK-002).
- Retain shared subject keys such as repository identity, place/person identity and a date without importing another domain's storage (LNK-004). The older `table:id` notation describes reference semantics; its concrete portable encoding must be agreed, not assumed to be a machine-local database address.

### Timeline evidence rules retained

- Domains retain their own records; adapters expose evidence without copying domain data into a second timeline store (TML-001).
- Evidence retains its record reference, source, category, start/optional end time, basis and uncertainty notes (TML-002/006). Basis remains observed, planned, operator-reported or inferred (TML-003).
- Retain the existing closed category list and change it only through the plan/contract process (TML-004). The device-manager event log remains an intended source, added through its concrete adapter when consumed (TML-007).
- Legitimate observations of the same event from different sources remain separate evidence. Retain the lower-ranked observation and point `superseded_by` to the higher-ranked one (TML-005). This is distinct from retry idempotency in [E0-2](E0-2.md): replaying one source record must not create duplicates, but importing a different source's observation must not erase evidence.

## Acceptance criteria

- Document one event-instant wire unit/precision and demonstrate round trips between machines with different time zones without changing the instant; preserve source uncertainty/context and event versus ingest time for delayed imports.
- Document/prove the clock synchronization and skew-detection policy, including unreliable-clock behaviour. Timestamp formatting alone is not evidence of synchronized clocks. Do not rewrite old source events to hide skew.
- Demonstrate stable identity/reference resolution across machines and repeated imports without copying the target domain record; an unresolved target retains its identity/label and does not block its source workflow.
- Demonstrate that a replay of the same source record is idempotent while separate overlapping source observations both survive with basis/uncertainty and the appropriate supersession reference.
- Keep date-only/time-zone semantics intact; add only the minimum real-consumer adapters/links needed to validate the contracts, with no new screen implementation.

**Open design choices:** wire unit/precision, clock synchronization/skew policy, portable identity encoding/resolution and absent/deleted-reference behaviour. Shared-state/replication architecture remains undecided; this issue does not select a database, ORM or coordinator.
