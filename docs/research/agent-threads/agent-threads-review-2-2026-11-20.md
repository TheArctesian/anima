I was given version 2 of `docs/proposals/agent-threads.md` and was told to read only its new parts: Section 1.2 (THR-065), Section 4.11 (THR-066 to THR-084), Section 6.8 (TH80 to TH96), rows P16 to P19 of Section 8, the open decisions OD-THR6, OD-THR7, OD-THR8 and OD-THR21 whose recommendations were turned, and OD-THR25 to OD-THR30. I also read the first review (`docs/research/agent-threads/agent-threads-review-2026-11-20.md`, findings F1 to F28) and do not repeat it. I opened `contracts/work-route.md` (K10 Sections 2, 3 and 6), `docs/plans/cli-mcp-plan.md` (MCP-002 to MCP-006, MCP-013, MCP-024 to MCP-026), `docs/proposals/bots.md` (BOT-020, BOT-021, BOT-025, BOT-032, BOT-033, BOT-066), `docs/proposals/agent-layer.md` (AGL-003, AGL-027), `docs/proposals/cloud-machines.md` (CVM-001 to CVM-024), `docs/proposals/hosted-mode.md` (HMD-071 to HMD-074, Sections 6.11 and 6.12) and `docs/proposals/jobs.md` (ROU-001 to ROU-016). I was not given the view of the author. I ran no program of the product, changed no file other than this one, and read no secret file. The frame is that of the product owner: "maximum agent reach is a good thing". So no finding asks for less reach for the agent of the owner. Each finding is a way by which a different party uses that reach, or by which reach becomes a cost or a loss that cannot be undone.

## 1. Findings

Severity: High = a different party can run code on a machine of the owner, can read or change what a tree of threads carries, can spend the allowance or change the plan, or a loss that cannot be undone has no guard. Medium = a guard that is weaker than the text says, or a conflict with a text of a different document. Low = a wrong or missing sentence.

## 2. The four turned recommendations

**OD-THR6 (the default mode is Full access).**

- What guard goes away: the approvals of the program as the stop between text that an agent reads and a command (P2, P4). The second sentence of THR-033, "The runner must refuse a start from the hub that asks for Full access". The meaning of THR-048 for "choose Full access": a window of the operating system guards a choice that is now made by default.
- What still relies on it: P2 and P4 name the approvals and "Full access is a choice" as their guards. P5 and THR-034 (the signed answer to an approval through the hub) guard nothing for a thread that asks no approval; the careful signature of F6 is then beside the point, and the start and the prompt carry all the weight (F4). F9 ("nothing stops the hub from sending Full access") is no longer a fault of a field; it is the default. P16 says this itself: "a child is full access too".
- What makes it safe: the condition that the row already has ("a start that comes through the hub is full access only when OD-THR20 is answered with a signature of a client"), made complete in three points. (1) It must cover each prompt, not only the start: a hub can send a prompt to a Full access thread that the person started at the machine. (2) It must cover a start that an agent makes on a different machine, which has no client to sign (G1). (3) The runner must take the mode from its own setting and from the signed grant, never from a field of the item. With those, the default gives the owner's agent full reach and gives the hub none.

**OD-THR7 (the environment of the person).**

- What guard goes away: the allow list of THR-040, and its sentence that `SSH_AUTH_SOCK` and the variables of a cloud account pass "only when the person names them".
- What still relies on it: P6 (its accepted state is "the agent gets the variables that the person names"). P1 and P3: what a hub controller gains from one prompt grows from the machine to each server and cloud account in reach of it (G15). THR-043 (the runner keeps "the variables of THR-040 by name" out of the event log) has no list of names any more. The sentence of THR-065 on things that cannot be undone: the keys of a cloud account are the tools for them (G6).
- What makes it safe: the same condition as OD-THR6, which this row does not have. The full environment for a thread whose start and prompts are proven to be from the person or from his tree; the allow list when only the hub says so. Never carry an environment between machines; a pool machine gets none (G15). Keep "without the values of Anima", and say in P6 that this is true for the environment only (F5).

**OD-THR8 (an agent may start threads and send messages).**

- What guard goes away: the line of MCP-006, AGL-003 and AGL-027 that no tool and no agent starts or types into a session. The guard of P3 that "only the operator's login or an API key with the scope for threads sends a prompt". The guard of P4 that an agent does not read the thread of a different agent through Anima (G9).
- What still relies on it: THR-049 ("nothing starts again without the person"; one `claude` task for each login). THR-042 and THR-044: the source label and the actor of a prompt are now often "an agent", and for a child on a different machine they are what the hub says. THR-031 in spirit: a parent that steers a Full access child does what an approval was meant to keep with a person. ROU-014: the review RT7 was asked for exactly this case. F10 was closed by the recommendation A; it is open again, and wider: with MCP-002 the new tools run with no question by design.
- What makes it safe: the binding must hold against the child, not only in the tool (G10): a capability for each thread at the socket, the limits counted by the hub on each path, the settings out of reach of the agent. Messages and reports as labelled data, with a limit on turns (G8). Across machines only with the grant of G1; until then the sentence of P17 as a requirement. The separate security read that TH82 names should be RT7, or should name RT7. And the row must be in Section 10 (G18).

**OD-THR21 (honour the settings of the project).**

- What guard goes away: the closure of F2 (start the program with the settings of the project off). The promise of THR-046 that the runner "does not call a thread Supervised when it cannot prove that the settings of the project or of the user do not answer before it". With option B the runner can never prove it.
