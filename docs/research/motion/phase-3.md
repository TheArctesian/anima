# Phase 3 motion audit (Section 5.8, MV-001 to MV-008)

Audit of the Phase 3 client at `b0af921e` (branch `wp/53-acceptance/motion`, worktree `.claude/worktrees/wp-53-motion`). Task: WP-53 T6, acceptance criterion 23. The builder wrote no application code. No application file changed. All data is synthetic (CON-003, Section 5.8). Under reduced motion an instant change in place or a fade is the specified form and is not a finding (MOT-040, MOT-041).

**Verdict for acceptance criterion 23: NOT MET as worded.**

- Sentence 1 holds for every role that the client has. Theme change, menu and popover, modal, session tab open and the in-app setting all have a measured reduced form: fade only, scale 1 in every frame (MOT-040, MOT-041, MOT-043). Toast has no code to measure (section 6). The update banner uses `fade` and exists only on the desktop shell.
- Sentence 2 holds in part. The audit ran in WebKit and Chromium, in both themes, on the web build. The desktop client was measured as the same web build at desktop widths (section 1 lists the desktop-only paths that this cannot reach).
- Sentence 3 fails on the letter. One layout jump is open: **M-1** (API key create dialog: the shown-once secret replaces the form and the dialog loses 272.5 px in one frame). One "wrong motion" is open: **W-1** (last session tab closes: the exit is played at zero width, so it cannot be seen). **W-2** (menu exit scales from the panel centre, not from the control) is a smaller wrong motion (at most 2.4 px).
- Sentence 4 holds. In 16 configurations (2 engines x 2 themes x 4 motion modes) and at 3 widths, nothing animates, filters or covers a live display (MAT-008). The modal scrim is a flat colour.
- The Phase 2 ruling (WP-34 D-5) said a jump under 100 px goes to issue #1 as a could. M-1 is 272.5 px, so that clause does not cover it. The text of criterion 23 does not repeat D-5. The orchestrator decides whether D-5 applies to Phase 3. Fix M-1 and W-1 first (section 5).
- Withdrawn, not measured: the watch page and playback (R-111, R-113).

### Not findings (checked and recorded)

- **Harness artefact at 900 px.** At 900 x 700 the outside-click point of `menus.ts` (`Add device` x minus 30) falls inside the Sort panel, so the Sort menu stayed open on the `outside@100` trial (`.../out/w900-menus-0.json`). The menu is right to stay open for a click inside it. At 1280 and 1440 the same trial closes it.
- **Page scroll at 900 x 700.** The session open at 900 x 700 scrolls the page to the top inside the frame where the session pane covers it (stage y -644 to 56). The pane covers the page, so nothing is seen. The scroll position after the tab closes was not examined.
- **Negative first-frame values on exit.** `first` and `op99` below zero in the summaries are an artefact of the exit trial (the recorder starts before the click). The doc uses the time to gone.
- **`dispDrift` 905.33 in the two-tab flow.** A selector artefact (the `canvas` selector matched a different display). MAT-008 uses the per-tab data in section 4.

## 4. Passed checks

- **MAT-008 (nothing animates, blurs or covers a live display).** 16 configurations, SSH, VNC and RDP: display rect drift 0 px over 93 to 95 frames; 17 hit-test points per frame with 0 elements over the display (`elementsOverDisplay` empty); `badStyles` empty (no `filter`, `backdrop-filter`, `transform` or non-1 opacity on the display or an ancestor); `ancestorsWithEffect` empty; 0 running animations in the pane. The menu panels (`material-overlay`) have `backdrop-filter` and sit outside the display: they never cover one in the flows measured.

- **MV-003 (interrupts).** Orphans 0 after every Escape, second click, outside click and theme double choice. Max scale step 0.0146. No scale value outside the role range.
- **MOT-007 (CLS).** CLS 0 in all 32 loads (Devices and Settings, Chromium); landmark drift 0 px in both engines.
