## 1. Why

The operator will use only the hosted hub (R-130) and starts fresh on it (R-140). The hub on the VPS stays only to sign releases, until the release server of R-158 has published one release. It runs `408bbbab`, a commit before the rename of R-126, and it is not deployed again for macOS 0.2.2. Many checks were written for the VPS hub and the VPN.

The orchestrating session asked the operator on 2026-11-18: "should the open human checks be sorted for hosted-only before you start on them?" The options were: an agent goes through each open check and proposes keep, change or withdraw, for him to approve; or do them all as written. His words: "Yes, sort them". The orchestrating session recommended that nothing is withdrawn.

This report was a proposal. The operator approved it on 2026-11-18 (R-169). No entry is deleted. This report itself changes no entry: a later commit does that in [need-human-testing.md](../../need-human-testing.md).

## 2. The rules, and one gap

- An entry is never deleted. Only the operator sets Passed or Failed (`AGENTS.md`, "Human testing"; PLN-014).
- The states of an entry are Open, Passed and Failed. A row of the section "Checks that other documents hold" can also say "Blocked" with the reason.
- No rule gives a state for a check that is put aside. Decision OD-W24 in [decisions.md](../../plan/decisions.md) proposed the smallest change: a state "Deferred", with the reason and the ruling. The operator approved it (R-169), and PLN-014 has the rule.

## 7. What the operator approved

The operator approved the sorting on 2026-11-18 with the words "Approve the sorting" (R-169). The text below is what was put to him.
