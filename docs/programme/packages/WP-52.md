## Decisions

- **E-1 The notify subnet is in the deny list except the Apprise address.** The NET-001 rule (R-030) puts
  every network the hub joins into `ANIMA_PROBE_DENY`. P3-003 applies the same list to notification
  targets, so a plain `172.30.3.0/24` entry would refuse the hub's own Apprise service. Leaving the subnet
  out would let a check or channel reach the host through the bridge gateway `172.30.3.1` and the hub
  itself. So `apprise` gets the fixed address `172.30.3.10`, and the deny list holds the eight CIDRs that
  cover `172.30.3.0/24` without that one address. The subnet and the address are literals (no variable):
  the carved list cannot follow a variable. A test proves the union is exactly the subnet minus the
  address. No contract change.
- **E-2 Apprise is optional through a compose profile.** `profiles: [apprise]`: a plain `docker compose up
  -d` starts no Apprise; `--profile apprise` starts it. The hub joins `notify` in both cases, so turning
  Apprise on later needs no hub restart. The hub does not depend on it.
- **E-3 Recordings volume seeded by the image.** The hub image creates `/var/lib/anima/recordings`, owner
  10001:10001, mode 0700; a new named volume copies that owner and mode (the WP-23 D-6 pattern). The root
  file system stays read-only.
- **E-4 Egress proof from the hub's own network namespace.** The hub image is Debian slim, which has bash
  and coreutils `timeout`. `deploy/bin/egress-check` runs `docker compose exec -T hub timeout … bash -c
  'exec 3<>/dev/tcp/HOST/PORT'` for 443, 465 and 587. The gate test runs the script with a fake `docker`
  on `PATH` against local listeners; the live run is a step for the operator.
- **E-5 The web build installs only what the client needs.** The bun stage copies the root manifest, the
  lock file and every workspace manifest, then `bun install --frozen-lockfile` filtered to the client, then
  `vite build`. The binary stage is unchanged.
