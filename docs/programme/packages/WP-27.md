## Decisions

- **D-1 The link checks every resolved address with the `AddressPolicy` it is given.** K3 passes the policy
  to `link`. The link resolves the host once, refuses the whole host when any address fails the policy or
  `TargetRule::STRICT` (R-032), and connects only to a checked address. A test proves the default policy
  refuses everything `TargetRule::STRICT` refuses, so in-crate tests can reach loopback with
  `AddressPolicy::allowing_loopback()` alone.
- **D-2 The link reuses the terminal's SSH pieces.** `ssh::Observer` (pin in the key exchange, refuse every
  channel the device opens), `ssh::authenticate` and `ssh::preferred`. No credential leaves the hub before the
  presented key equals the accepted key (SEC-007). The terminal keeps its own opening; moving it onto the link
  is a could for issue #1 (`terminal/` is not owned here).
- **D-3 `FixedCommand` holds only `&'static str` and hub-rendered values.** `new(program)`, `arg(&'static str)`
  (WP-29's listing commands, D-3 of the plan) and `mac(MacAddress)`. The rendered line is the static text and
  the MAC as `aa:bb:cc:dd:ee:ff`; nothing else can enter it, so no operator text reaches a shell (CHK-012). One
  `exec` per `run`, on its own channel; standard error is dropped unread; standard output is capped.
- **D-4 The wake program is `wakeonlan <mac>` on the site's relay device.** One static command over the link
  (D-2 of the plan, provisional under R-065). The relay must not be the device itself and must have SSH on and
  an accepted host key. `wake` sends whatever the device's state; the Down test belongs to `startSession`
  (WP-22). Exit status 0 counts as sent; anything else is an error with no device text.
- **D-5 Files tickets live in `files/`, held by `Live`.** `PendingTicket::admits` keys tunnel paths by
  protocol, so a files ticket cannot share the session ticket table without letting a `/terminal` ticket open
  `/files`. `files::Tickets` reuses `tickets::TicketToken` and `hash_of`. `Live` gets one field and one
  accessor for it, and one method that subscribes to a session tunnel's end signal, so the files tunnel ends
  when its SSH session ends (K4 §9). These are handoff edits to WP-22's `live.rs`.
- **D-6 CR-1: `files_router` takes the deny list.** K3's `files_router(db, vault, bus, clock, live)` has no
  `AddressPolicy`, and the files tunnel connects through the link (P2-004). Contract change request:
  `files_router(db, vault, bus, clock, live, policy: AddressPolicy)`. If WP-22 T7 puts the policy into `Live`
  first, the programme may drop the extra parameter in favour of `live`.
- **D-7 SFTP through `russh-sftp` 3.0.1.** Protocol only, Apache-2.0, on tokio; its server half serves the
  test SSH server's `sftp` subsystem. Dependency lines are handoff edits (R-032 E-3 pattern).
- **D-8 GraphQL resolvers live in each owned folder.** `openFiles` in `files/`, `wakeDevice` in `wake/`, each a
  `MergedObject` part joined in `schema.rs` with one line (handoff), behind the same guard as
  `sessions::graphql`.
