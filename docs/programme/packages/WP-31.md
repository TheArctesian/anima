## Decisions

- **D-1 The spike is a standalone crate.** `apps/desktop/src-tauri/spikes/od7/` has its own `[workspace]`
  and a copy of the workspace `Cargo.lock`, built with the workspace `target/`. It needs Objective-C
  calls (`unsafe`), which the workspace forbids (`unsafe_code = "forbid"`); outside the workspace that
  rule does not apply and no gate runs on it. It is committed so the operator can run it on Linux.
  It runs headless: hidden windows, macOS activation policy `Accessory`, no focus taken, local servers
  on 127.0.0.1 only, a 60-second limit.
- **D-2 Data store per device (WEB-006).** macOS: `data_store_identifier` = the 16 bytes of the
  `DeviceId` UUID (WKWebsiteDataStore(forIdentifier:), macOS 14+, the bundle minimum is 14.2). Linux:
  `data_directory` = `<app data>/web/<device id>`. The main window keeps the default store.
- **D-3 No IPC for web views (WEB-007).** Device web views get labels `web-<tab id>`; no capability
  names them, every capability keeps `"webviews": ["main"]` and none has `remote`. Navigation is
  allowed only to `http` and `https`; new windows open in the same web view.
- **D-4 Pin decision is a pure function** of (pin, pinned origin, challenge host and port, presented
  SHA-256, system trust): `Default`, `Accept`, `Untrusted(fp)`, `Mismatch{expected, presented}`. A pin
  wins over system trust; a host or port other than the pinned origin gets the system's handling.
  Mutation testing applies to it (R-066).
- **D-5 Fingerprint form.** The hub's form (H-4): 64 lower-case hex. The shell parses the same form and
  the client shows it as colon pairs, upper case (as SEC-007 host keys).
- **D-6 Mode choice (D-9).** The shell answers `web_view_pinning()`. Embedded when the URL is `http` or
  the platform can pin; otherwise the system browser with the pinned fingerprint beside the button.
  Until the operator runs the spike on Linux, Linux answers `false`. The macOS answer depends on T1
  and on D-7.
- **D-7 macOS trust hook needs `unsafe`.** If T1 shows pinning works only through
  `webView:didReceiveAuthenticationChallenge:completionHandler:` (wry does not implement it), the shell
  needs one Objective-C module with `unsafe`. That overrides the workspace `forbid`, so it is a change
  request to the programme orchestrator, not a package decision. T4 is built on its own branch and is
  merged only after the ruling; until then macOS answers `false` (system browser, D-9).

## Shell interface (T3 and T5 build to this)

Commands, allowed for the `main` web view only (capability `desktop`):

| Command | Arguments | Answer |
| --- | --- | --- |
| `web_view_pinning` | — | `boolean` |
| `web_view_open` | `tabId`, `deviceId`, `url`, `pin: string \| null`, `bounds {x, y, width, height}` (CSS px in the main window) | `null` |
| `web_view_place` | `tabId`, `bounds` | `null` |
| `web_view_show` | `tabId`, `shown` | `null` |
| `web_view_go` | `tabId`, `to: "BACK" \| "FORWARD" \| "RELOAD"` | `null` |
| `web_view_pin` | `tabId`, `pin` (64 lower hex) | `null`; reloads |
| `web_view_pop_out` | `tabId` | `null`; moves the web view to its own window, same store |
| `web_view_close` | `tabId` | `null` |
| `system_browser_open` | `url` (`http`/`https` only) | `null` |
| `web_certificate_read` | `url` (`https` only) | `{ fingerprintSha256 }` of the leaf |

Errors are `{ code }` only, no URL or page content (LOG-007). Event `web-view`, emitted to `main` only:
`{ tabId, kind: "LOADING" | "LOADED", url }`, `{ tabId, kind: "UNTRUSTED", fingerprintSha256 }`,
`{ tabId, kind: "MISMATCH", expected, presented }`, `{ tabId, kind: "FAILED", reason }`.

Builders are Opus by the brief and AGT-002 (pinning, process boundary).

**T1 od7-spike.** Goal: answer OD-7 on macOS with a runnable harness; write the Linux path for the
operator. Files: `apps/desktop/src-tauri/spikes/od7/**`. Checks: (1) two device web views with their
own stores and the main view share no cookie or `localStorage`; (2) `invoke` from a device web view
fails while the main view's succeeds; (3) an untrusted certificate's leaf SHA-256 reaches Rust and
equals the server's; with that pin the page loads; a new certificate on the same host and port is
stopped as a mismatch; (4) navigation to a non-http scheme is refused. Prints PASS/FAIL per check.

**T2 pin.** Goal: the pure pin core and the certificate probe in the shell. Files:
`src/web_view.rs`, `src/web_view/{fingerprint,pin,certificate,tests}.rs`. Spec: WEB-008, D-4, D-5.
Tests: fingerprint parse (H-4 forms), origin rule (https only; scheme, host, port), every verdict,
probe against a local rustls server with an rcgen certificate.

**T3 shell.** Goal: the commands and event above, per-device store, no IPC, navigation filter, pop
out, system browser. Files: `src/web_view/**`, `src/main.rs`, `build.rs`, `capabilities/desktop.json`,
`permissions/autogenerated/*`, `Cargo.toml` (tauri `unstable` for child web views). Spec: WEB-004–007,
REPO-003. Tests: pure parts (bounds, store id from device id, scheme filter, command argument checks).

**T4 macos-trust.** Goal: the navigation delegate proxy that answers server-trust challenges with the
D-4 verdict and emits `UNTRUSTED` / `MISMATCH`. Only after the D-7 ruling.

**T5 web-tab.** Goal: the tab body. Files: `lib/desktop/webView.ts` (+ test), `lib/sessions/web/**`.
Toolbar (WEB-005), the area the native view is placed over (ResizeObserver; hidden when the tab is
hidden or an overlay is open), the first-visit fingerprint prompt and accept (hub
`acceptWebCertificate`, then `web_view_pin`), the mismatch stop (as SEC-007), the Down page with the
reason and Reload (WEB-010), the system-browser mode with the pinned fingerprint (D-9). No motion
in the view area (MAT-008). Tests: pure state machine, event parsing, component tests with a fake shell.
