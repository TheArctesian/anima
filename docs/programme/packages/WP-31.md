## Decisions

- **D-1 The spike is a standalone crate.** `apps/desktop/src-tauri/spikes/od7/` has its own `[workspace]`
  and a copy of the workspace `Cargo.lock`, built with the workspace `target/`. It needs Objective-C
  calls (`unsafe`), which the workspace forbids (`unsafe_code = "forbid"`); outside the workspace that
  rule does not apply and no gate runs on it. It is committed so the operator can run it on Linux.
  It runs headless: hidden windows, macOS activation policy `Accessory`, no focus taken, local servers
  on 127.0.0.1 only, a 60-second limit.
- **D-2 Data store per device (WEB-006).** macOS: `data_store_identifier` = the 16 bytes of the
  `DeviceId` UUID (WKWebsiteDataStore(forIdentifier:), macOS 14+, the bundle minimum is 14.2). Linux:
  `data_directory` = `<app data>/web/<device id>`. The main window keeps the default store.
- **D-3 No IPC for web views (WEB-007).** Device web views get labels `web-<tab id>`; no capability
  names them, every capability keeps `"webviews": ["main"]` and none has `remote`. Navigation is
  allowed only to `http` and `https`; new windows open in the same web view.
- **D-4 Pin decision is a pure function** of (pin, pinned origin, challenge host and port, presented
  SHA-256, system trust): `Default`, `Accept`, `Untrusted(fp)`, `Mismatch{expected, presented}`. A pin
  wins over system trust; a host or port other than the pinned origin gets the system's handling.
  Mutation testing applies to it (R-066).
- **D-5 Fingerprint form.** The hub's form (H-4): 64 lower-case hex. The shell parses the same form and
  the client shows it as colon pairs, upper case (as SEC-007 host keys).
- **D-6 Mode choice (D-9).** The shell answers `web_view_pinning()`. Embedded when the URL is `http` or
  the platform can pin; otherwise the system browser with the pinned fingerprint beside the button.
  Until the operator runs the spike on Linux, Linux answers `false`. The macOS answer depends on T1
  and on D-7.
- **D-7 macOS trust hook needs `unsafe`.** If T1 shows pinning works only through
  `webView:didReceiveAuthenticationChallenge:completionHandler:` (wry does not implement it), the shell
  needs one Objective-C module with `unsafe`. That overrides the workspace `forbid`, so it is a change
  request to the programme orchestrator, not a package decision. T4 is built on its own branch and is
  merged only after the ruling; until then macOS answers `false` (system browser, D-9).

must wait until WebKit has started.

### (2) No Tauri IPC for device web views (WEB-007): works

```
PASS ipc-main-allowed the command ran for label main, from ["main"]
PASS ipc-device-denied command calls from device labels: []; page saw {"fetch":"status 500","internals":"object","invoke":"rejected: spike_probe not allowed on window \"harness\", webview \"web-ipc\", URL: http://127.0.0.1:56419/\n\nallowed on: [webviews: \"main\", URL: local]\n\nreferenced by: capabil","raw":"posted"}

### (3) Certificate pinning (WEB-008): works on macOS, only with `unsafe` Objective-C

```

How it works: a navigation-delegate proxy (`objc2` `define_class!`) implements
`webView:didReceiveAuthenticationChallenge:completionHandler:` and forwards every other
selector to wry's delegate (`respondsToSelector:` and `forwardingTargetForSelector:`). It is
installed with `setNavigationDelegate:` from `Webview::with_webview` and retained by the shell,
because the property is weak. It reads `protectionSpace.serverTrust` and the leaf from
`SecTrust::chain()`, takes SHA-256 of the DER, and answers `UseCredential` with
`NSURLCredential(trust:)` on a pin match and `CancelAuthenticationChallenge` on Untrusted or
Mismatch. `install` confirmed that the proxy is the delegate. The server serves each request on a
new connection: one pinned page load gave 3 accepted challenges, and a new connection after the
server restarted on the same port gave the mismatch. WebKit did not reuse the earlier decision.

**D-7:** yes, `unsafe` Objective-C is required. wry 0.57.1, tauri 2.12.5 and tauri-runtime-wry
have no certificate or challenge API (searched: no `AuthenticationChallenge`, `serverTrust`
or TLS-error hook). `WryNavigationDelegate` implements no challenge method, so without the proxy
WebKit applies system trust and an untrusted certificate fails with nothing reported to Rust.
The `unsafe` code is in one file, `src/trust/macos.rs`: 122 code lines with 10 `unsafe`
blocks. The ruling is a change request to the orchestrator.

Not proven by this spike (for T4 and its review):
- **Pin over system trust (D-4)** with a certificate the system trusts. This needs a trusted
  root on this Mac, and the spike does not change the keychain. The verdict is computed in Rust,
  so it should hold, but it was not observed.
- **First load before the proxy is installed.** `with_webview` runs after the web view exists.
  If a device web view is created directly on its `https` URL, that first load goes through
  wry's delegate with system trust and no pin check. The spike opens on an `http` blank page,
  installs the proxy, then navigates. T4 must do the same, or must create the view without a URL.
- TLS session resumption and long-lived keep-alive connections were not tested separately (the
  restart closes both). `SecTrustEvaluateWithError` runs on the main thread and blocks; Apple
  advises against this. Non-server-trust challenges (HTTP Basic, client certificates) get
  `PerformDefaultHandling`, which shows no prompt, the same as wry today. Pop-out (moving the
  web view to another window) with the proxy attached was not tested.

### Linux (WebKitGTK): written, not compiled or run, needs the operator

`src/trust/linux.rs` (`load-failed-with-tls-errors` → `GTlsCertificate` DER → SHA-256; on Accept
`WebContext::allow_tls_certificate_for_host` and load the URI again) and the `data_directory`
store in `src/checks/device.rs` were written against webkit2gtk-rs 2.0.2. They were **not
compiled and not run**, because this machine is macOS. The operator runs the same harness on
Linux (README: `xvfb-run -a cargo run`). The Linux path has known limits whatever the result: the
allowance is per host (not per port) and per web context, and the signal never fires for a
system-trusted certificate, so a pin cannot win over system trust there (D-4). Until the operator
runs it, D-6 stands: Linux answers `web_view_pinning() = false`.

The crate's `Cargo.lock` began as a copy of the workspace lock. Cargo pruned the packages the
spike does not use. It adds no package version that the workspace lock does not have.
