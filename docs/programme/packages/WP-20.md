### T1 — CON-002 `@pending` rule

- **Goal.** K1 may carry Phase 2 additions marked `@pending` before the hub serves them (D-1). The
  comparison drops a `@pending` declaration, member (field, input field, enum value, argument) or union
  member only while the hub does not declare it. A hub that declares a name K1 still marks `@pending`
  fails with one line per name. The `@pending` directive definition is K1-only. Non-pending comparison is
  unchanged.
- **Owned files.** `crates/hub/tests/it/contract.rs`.
- **Test plan.** Behaviour tests on small synthetic SDL pairs: pending type/field/enum value/input
  field/union member absent from the hub gives no difference; each present in the hub gives a
  "still `@pending`" difference; a non-pending K1 member absent from the hub still fails. The real
  CON-002 test still passes on Phase 1 K1.

### T2 — Contracts into `contracts/`

  "frozen for Phase 2"; K1 gains the `@pending` directive and marks every addition; K1 header comment
  line 4 names `contracts/schema.graphql` as the client's generation source guarded by CON-002 (K7, WP-17
  E-2). K5 chart colours go into `design/tokens/` and the K5 table in one commit (R-049 pattern) with the
  generated outputs rebuilt. Client generated types (`apps/client/src/lib/hub/generated/`) are rebuilt

- **Owned files.** `contracts/*.md`, `contracts/schema.graphql`, `design/tokens/color.tokens.json` (K5
  rows only), generated token outputs, generated client types, `docs/programme/phase-2-contracts.md`
