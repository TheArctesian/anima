# WP-49 — Client sharing, recording players and the watch page

Package branch: `claude/wp-49-sharing` from the local `phase-3` at 4ee029fe. Worktree: `.claude/worktrees/wp-49`.
Task branches: `wp/49-sharing/<task>`, each in its own worktree `.claude/worktrees/wp-49-<task>`.

Goal: the operator shares a live session from its tab and stops the share; a viewer opens the link in a browser
with no sign-in and watches read-only (or controls, when the operator allowed it); the client shows the
"Recording" badge; the operator plays RDP and VNC recordings with `Guacamole.SessionRecording` and SSH recordings
with an asciicast player, and deletes them; the Sessions tab shows the client address and a playback row.

Spec: RA-034 (H-2 `clientAddr`), RA-035, RA-040, RA-041, SEC-002, MAT-008, MOT-005, MOT-040, MOT-041, Section 5.7.3
"Session tab open", LOG-007. Plan: phase-3-plan.md WP-49 row and note ("a page with no navigation bar and no
GraphQL call except `joinShare`"), D-7 to D-15, acceptance rows 14, 16, 17, 18, 23, carry-over "Show
`Session.clientAddr` in the Sessions tab". Rulings: R-045, R-046 (vendor file unchanged; only `tunnel/` imports
it), R-066 (two review rounds; only musts block; mutation runs on security code), R-067 (send each accepted task),
R-068 (client-only gates 4–12), R-079, R-082, R-083, R-091 (Handoff commits; `@pending`), R-096, R-101, CR-16,
CR-19.

Contracts used (read only): K1 `ShareAccess`, `SessionShare`, `ShareLink`, `ShareInput`, `shareSession`,
`endShare`, `Session.shares`, `Session.clientAddr` (served); `joinShare`, `WatchTicket` (`@pending`, WP-47 T4);
`RecordingState`, `RecordingFormat`, `Recording`, `RecordingConnection`, `recordings`, `openRecording`,
`deleteRecording`, `Session.recording`, `SessionTicket.recording` (`@pending`, WP-48 T5a/T5b); K4 §1 (`/watch`,
`/recording` tickets), §10 (watch tunnel), §11 (formats), §12 (playback tunnel); K6 `phase3.json` shares,

## Decisions

- **W-1 Base.** The package branch starts at the local `phase-3` head 4ee029fe.
- **W-2 Signed-out route.** `/shared` is already a bare route on `phase-3` (WP-44 T1 and T4, E-3:
  `lib/access/routes.ts` `BARE_ROUTES`; the root layout renders only the page there, with no operator hub,
  socket, navigation bar, session strip, update banner or guard). `claude/wp-44-web-client` has no commit beyond
  `phase-3`, so nothing parked is needed. The route's `load` stays pure (WP-44 E-10): no `+page.ts` work; the
  token and `joinShare` live only in the page script.
- **W-3 Signed-out transport.** The watch page sends `joinShare` through `lib/hub/request.ts` `sendRequest` with
  a token provider that answers `null`, a `fetch` with `credentials: 'omit'` (an operator's `__Host-anima` cookie
  in the same browser must never authorize the viewer's call, SEC-002, D-7), and the address from
  `servedHubAddress(location.origin)` (a refused origin shows the fixed `ORIGIN_REFUSED` text and sends nothing).
  `joinShare` is the page's only GraphQL document; no subscription socket is opened. A test proves one request, to
  the hub's `/graphql`, operation `joinShare`, no `authorization` header, credentials omitted.
- **W-4 The token.** Read once from `location.hash` when the page mounts, then dropped from the address bar with
  `history.replaceState` (so it is not in the history entry, a later copy or a bookmark), and kept only in memory
  for a rejoin. Nothing is sent on load: the viewer presses "Watch" (optional name, at most 32 characters), so a
  link preview never spends a viewer place. Never in storage, a log, an error text or the DOM. A missing or
  malformed fragment shows one fixed text and sends nothing.
- **W-5 Watch tunnel.** RDP and VNC reuse `tunnel/guacamole/openTunnel` with the watch ticket (subprotocol
  `guacamole`, K4 §10). SSH gets an `anima-watch` client in `lib/sessions/watch/` (`joined`, replay and live
  binary frames, `resize`, `ping`, `end`; VIEW sends only `ping`; CONTROL also sends binary input). The viewer
  never sends `resize`; the terminal takes the owner's size. Close 4004 shows "The share ended" (no rejoin);
  4002 shows "The connection was lost" with "Watch again"; 1002 a protocol error. FORBIDDEN from `joinShare`
  shows K4's one text for every cause.
- **W-6 Viewer input.** VIEW forwards no key, mouse or touch from the page (the hub drops them too; defence in
  depth). CONTROL forwards keys, mouse and touch only. A viewer never gets clipboard, file, audio or `argv`
  handlers (D-9). Nothing moves or blurs over the display (MAT-008); the page is solid surfaces only.
- **W-7 The vendor rule.** Only `lib/sessions/tunnel/` may import `vendor/` (R-045, ESLint). The `/recording`
  socket (K4 §12 is a tunnel) and the `Guacamole.SessionRecording` adapter live in a new folder
  `lib/sessions/tunnel/playback/`, owned by WP-49 for Phase 3 (Q-1). The `SessionRecording` declarations go into
  the hand-written `vendor/guacamole.d.ts` (not the vendor file) as a Handoff commit; WP-48 T1 may add the same
  lines for its proof test, and whichever merges second rebases.
- **W-8 Playback opens in a session tab.** A recording opens in a session tab that grows from its Play button
  (Section 5.7.3 "Session tab open", MOT-005; reduced motion: fade), as web tabs do: a `PLAYBACK` tab kind in
  `lib/sessions/tabs.ts`, its pane in `strip/SessionPanes.svelte`, as Handoff commits (Q-2). The pane holds the
  player and solid controls below the display; nothing animates the recorded display (MAT-008).
- **W-9 Pending fields stay out of existing documents** (WP-50 F-3). Each feature uses its own documents in its
  own folder. The badge's wiring into `StartSession` (`SessionTicket.recording`) and the live sessions
  subscription (`Session.recording`) waits for WP-48 T5a to merge and clear `@pending`.
- **W-10 Sessions tab path.** The plan names `routes/devices/[id]/detail/`; the Sessions tab is
  `routes/devices/[id]/sessions/` (WP-33). The client address column (RA-034 H-2) and the playback rows go there
  as one Handoff commit, last on the T7 branch.
- **W-11 Badge location.** `lib/sessions/view/` holds 12 files (the folder limit), so the badge goes in
  `lib/sessions/view/recording/RecordingBadge.svelte`: "Recording" while on, "Recording stopped" after a stop
  (D-14), static (no pulse, MOT-011), solid, in the toolbar row, never over the display. The watch page shows the
  same badge from `WatchTicket.recording`.
- **W-12 Share entry point.** A "Share" button in the session toolbar (terminal and remote), shown while the
  session is open, opens the share dialog from `lib/sessions/share/` on the shared modal shell
  (`lib/forms/modal/Modal.svelte`). The two toolbar mounts are a Handoff commit in `lib/sessions/view/`.
- **W-13 Review.** Two rounds per task (R-066); only must findings block. Security tasks get reviewer-security
  (Opus, scoped mutation run, 20 minutes) and reviewer; UI tasks also get reviewer-interface, which measures only
  this package's screens, once, in WebKit and Chromium (MV-001).
