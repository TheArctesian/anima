## Decisions

- **D-1 Deny list lives in `Live`.** `Live` already carries the target rule (R-032) and reaches every
  session connection: the terminal, the Guacamole tunnel, the SSH probe and `testConnection`. It gains
  the `ANIMA_PROBE_DENY` policy (`targets::AddressPolicy`) through one builder method that `main.rs`
  calls after `sessions::open`. K3's `open` and router signatures stay.
- **D-2 Drive root as a `tunnel_router` argument.** K3 fixes the parameters and has none for config.
  `drive-path` needs `config.guacd_drive_root`. Contract change request CR-1: `tunnel_router` gains
  `drive_root: String` after `guacd`. Chosen over `Live`, which holds live state, not gateway config.
- **D-3 Before WP-21 lands.** Tasks that need `devices::RdpSettings`, `VncSettings`, `TransferPolicy`
  or `credentials::load_password` (T5, T6, T4 part b) wait for the rebase. Until T5, `start` refuses RDP
  and VNC with `Conflict` (the protocol is off: no device has RDP or VNC settings yet), so a declared
  `Protocol.RDP` never reaches a tunnel that cannot serve it.
- **D-4 guacd fixtures from the local image.** `guacamole/guacd:1.6.0` is already on this machine; T2
  runs it locally (no pull, no VPS) and records `args` for `rdp` and `vnc`.

## guacd 1.6.0 args (T2)

**How they were recorded.** The local `guacamole/guacd:1.6.0` image (no pull) ran on
`127.0.0.1` only. A short script sent `6.select,3.rdp;` and then `6.select,3.vnc;` on separate
connections and saved each reply, byte for byte, up to the closing `;`. A strict parse found
exactly one `args` instruction in each, with no trailing bytes and no trailing newline. The
container was then stopped and removed. The fixtures are
`crates/hub/src/sessions/tunnel/tests/fixtures/guacd-1.6.0-{rdp,vnc}-args.guac`, and
`tests/rdp_vnc_args.rs` decodes them with `guac-protocol`'s `Decoder`. Both send
`VERSION_1_5_0` first.
