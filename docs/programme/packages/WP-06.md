## Decisions

- **D-1. Order.** Tasks that need no other domain go first: migrations, model and pure rules, store, public face, read queries. Tasks that call `events`, `access` or `credentials` start only after those slices are on `phase-1` and merged into this branch. No stand-ins for another domain's interface.
- **D-2. Folder shape.** `devices.rs` (public face: `Device`, `SshSettings`, `get`, `list`, `in_maintenance`, `Error`), `devices/model.rs` (domain types), `devices/rules.rs` (pure validation: DEV-010 host, VPN-001 subnet, SSH settings, tags), `devices/page.rs` (pure cursor pagination, API-006), `devices/store.rs` (all SQL on schema `devices`), `devices/graphql.rs`, `devices/loaders.rs` (data loaders, API-005), `devices/tests.rs`. Integration tests under `crates/hub/tests/it/devices/`.
- **D-3. Validation is two-layer.** Pure rules reject bad shapes before SQL (DEV-010: host is an RFC 1123 host name of at most 253 characters with labels of 1–63 characters, or an IPv4 or IPv6 literal; port 1–65535; SSH username required when SSH is on; tags trimmed, not empty, de-duplicated). The database enforces what needs all rows: unique device name, unique site name and non-overlapping site subnets (VPN-001) with an exclusion constraint `EXCLUDE USING gist (subnet inet_ops WITH &&)`. A violated constraint maps to `VALIDATION` with the field name, not `INTERNAL`.
- **D-4. Pagination.** Keyset on the sort key. For `NAME` the key is the unique name, so the cursor is the opaque encoding of the last name. `totalCount` counts the filtered set. Pure helpers in `page.rs` (encode, decode, `first` bounds 1–200).
- **D-5. Data loaders (API-005).** `Device.site` uses a `SiteById` loader. `Site.devices` uses a `DevicesBySite` loader and the pure page helper. Tags and SSH settings come in the same query as the device (join and `array_agg`), never one query per device.
- **D-6. Test database.** `#[sqlx::test]` with `migrations = "migrations"` on a throwaway database, fixtures from `crates/hub/tests/fixtures/devices.sql` (K6 rows written as SQL, loaded with `#[sqlx::test(fixtures(...))]`); a test compares the loaded rows with `contracts/fixtures/phase1.json`, so the SQL cannot drift from K6. `bun run gates` starts a throwaway PostgreSQL for `cargo test` (R-009); every test run leaves `DATABASE_URL` unset so it gets its own server (R-019: sqlx names test databases by test path, so worktrees sharing a server destroy each other's databases). Database tests never skip.
- **D-7. Root `Cargo.toml` lines.** sqlx needs the features `runtime-tokio`, `migrate`, `macros`, `chrono`, `ipnet`; async-graphql needs `chrono` and `dataloader`. These are minimal wiring lines in a WP-01 file: handoff H-1.
- **D-8. `Device.ip`.** K1 has `ip` on `Device` but no `ip` in `CreateDeviceInput` or `UpdateDeviceInput`. Phase 1 stores it (fixtures) and never sets it from the API. Open question Q-2.

- **D-9. `Site.devices` pages in memory.** The `DevicesBySite` loader loads every device of the requested sites and pages with `page_after`; fine for Phase 1 scale (hundreds of devices). Revisit if a site grows past a few hundred devices (deferred item for issue #1, R-007).
- **D-10. INTERNAL errors keep their cause.** The `sqlx` or `CidrError` cause stays on the GraphQL error as an unserialized source; logging it waits for WP-05's tracing layer (handoff H-5).
- **D-11. Audit key `signIn`.** The audit `change` names the SSH sign-in method `signIn`, not K1's `auth`: the events redaction treats any `auth` key as a secret (handoff H-6).
- **D-12. Input caps.** At most 32 tags per device, tag 32 characters, names 64, SSH username 64; no control or bidi override characters in operator text (the audit log keeps every value for a year, LOG-006, and event messages must not forge lines, LOG-004).

## Escalations (contract change requests, CON-001)

Sent to the programme orchestrator. The affected parts (T4 status fields, T6) wait for the ruling; the rest proceed.

- **E-1 (resolved by R-011). `Device` fields owned by other domains.** K1 puts `status`, `checks`, `uptime` (checks data), `ssh.hostKey` (`sessions.host_keys`) and `ssh.credentialStored` on `Device`/`SshSettings`, plus `DeviceFilter.status` and `DeviceSort.STATUS`/`UPTIME`. K3 lets `devices` import only `events` and `credentials::has_ssh`, and R-004 forbids `devices → checks`. In async-graphql one object type has exactly one resolver impl, so `devices::graphql` cannot resolve `checks: [Check!]!` (a `checks` type) or `hostKey: HostKey` (a `sessions` type) without the forbidden imports. Options: (a) the composed `Device` output type and the device queries move to a composition module allowed to import `devices`, `checks`, `sessions`, `credentials`; (b) `devices` reads status and uptime through a value in the schema data that `main.rs` injects (leaf types only) and `Device.checks`/`hostKey` move off `Device` (K1 change: new root queries `checks(deviceId: ID!)` owned by `checks` and `hostKey(deviceId: ID!)` owned by `sessions`); (c) another ruling. Until the ruling, T4 resolves only the fields `devices` owns and supports `NAME` sort and the name, tag and site filters.
- **E-2 (resolved by R-010). `setSshCredential` and `clearSshCredential`.** They need `credentials::store_ssh` and a "clear" function that K3 does not have, but K3 lets `devices` import only `has_ssh`. Request: allow `devices` to import `credentials::{Vault, Secret, SshSecret, store_ssh, has_ssh}` and add `pub async fn clear_ssh(conn: &mut PgConnection, device: DeviceId) -> Result<(), Error>` to K3 `credentials`, or give these two mutations to WP-07.
- **E-3 (resolved by R-011). `createDevice(addDefaultCheck: true)`.** WP-06 accepts the input field and does not act on it; WP-09 adds the behaviour. It must add one ICMP check (spec 6.2), but `devices` may not import `checks`. Request a ruling: who creates the default check (for example `checks` owns a `createDevice` wrapper, or the client calls `createCheck` after `createDevice` and the input field is ignored by the hub).
