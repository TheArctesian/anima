## Decisions

- **D-1 Components take data and callbacks; the route wires the hub.**
  - The form, check editor, header and tab panels are Svelte components with props: the values they show and callbacks such as `onSave(values)` and `onTest(values)`.
  - Each returns a `HubResult`, so a component shows K7 errors without knowing the hub.
  - Only `routes/devices/[id]/+page.svelte` (and the Add device modal's host) calls `useHub()` and the domain clients.
  - So the components are testable without a fake hub, and they do not wait for E-1.
- **D-2 Pure form core (`lib/forms/`).** Pure functions handle:
  - `Device` → form values;
  - values → `CreateDeviceInput`, or an `UpdateDeviceInput` with only the changed fields;
  - validation → `{ field, message }[]`;
  - K7 `VALIDATION` `extensions.fields` → the same field errors, so hub and client errors show in one place.
  
  Svelte files hold no rules.
- **D-3 Host validation (DEV-010).** The host is valid when it is one of:
  - an IPv4 literal (four decimal octets 0–255, no leading zeros);
  - an IPv6 literal (with optional brackets, which are removed);
  - a DNS name: labels of 1–63 characters from `[A-Za-z0-9-]`, no leading or trailing hyphen, at most 253 characters, and not all-numeric in the last label.
  
  The value is trimmed. Validation runs on blur and on save, and Save is refused while any field error exists. The hub still validates, and its `VALIDATION` fields show on the same inputs (D-2).
- **D-4 Credentials (DEV-011, DEV-012).**
  - SSH auth is a choice between Password and Private key (`SshAuth`).
  - The password and passphrase are `<input type="password">`, with `autocomplete="new-password"` on them and on the key textarea. Engines ignore `off` on password fields (T2 review S2).
  - The private key is a `<textarea>` with `spellcheck="false"`. It is checked for a PEM or OpenSSH armour line (`-----BEGIN … PRIVATE KEY-----`) and is not parsed further.
  - The form never receives a stored secret (K1 `credentialStored` only). With a stored credential and empty inputs, the saved form sends no `setSshCredential`.
  - "Remove credential" calls `clearSshCredential`.
  - Secret values are never logged, put in a URL or kept after save (LOG-007). The form clears them on success.
- **D-5 Connection test (DEV-013, SEC-006/007).**
  - "Test connection" sends `testConnection`. The hub accepts `deviceId` alone (with an optional credential) or `host` + `ssh` + an optional credential, never both.
    - A saved device whose host and SSH settings are unchanged sends `deviceId`, plus any newly typed credential.
    - Anything else sends the unsaved host, SSH settings and credential with no `deviceId`. The stored credential is then not used, and the form says so (T1 review M1).
  - A pure reducer turns `ConnectionTestResult` into one of: reachable/authenticated, unreachable (`message`), authentication failed, host key new, or host key changed.
  - A new or changed host key opens the host key modal. It shows the algorithm and the SHA-256 fingerprint; "changed" is a warning.
  - "Accept" calls `acceptHostKey`, and only for a saved device, because the hub pins a key to a device. An unsaved device shows the fingerprint and says it can be accepted after saving.
- **D-6 Add device (Section 5.7.3 Modal; WP-12 H-1).**
  - `AddDeviceModal.svelte` in `lib/forms/` wraps the form in create mode. It uses the `modal` transition and a scrim, traps focus, closes on Escape, and returns focus to the opener.
  - On save, it calls `createDevice` with `addDefaultCheck: true` (Section 6.2 default: one ICMP check). If a credential was entered, it then calls `setSshCredential`.
  - It then navigates to `/devices/{id}`.
  - WP-12's page opens it from `onAddDevice()` (handoff H-1). WP-13 does not serve `/devices/new`; the `[id]` route answers it as "Device not found".
  - The site picker lists `sites`. With one site, the picker is hidden and that site is used.
- **D-7 Delete (DEV-014).**
  - Settings has "Delete device". It opens a confirmation modal that names the device and says that its credentials, checks and history go too (DEV-015 wording).
  - The confirm button is labelled "Delete <name>" and is not the default button.
  - On success, the client goes to `/devices`.
- **D-8 Header line (DEV-020–022).** One flex line, in this order:
  - Left: the "Devices" back link, the name, the status pill, the host, the IP (only when it differs from the host), the kind, the OS and the tags.
  - Right: SSH, RDP and Edit.

  Overflow:
  - The name, pill and buttons never shrink. The host-to-tags group is `min-inline-size: 0` with `overflow: hidden` and a fade mask at its end edge (DEV-021).
  - Each text item has a `title` with its full text, and the group has one with all of it.
  - The mask applies only when the group overflows, measured with a `ResizeObserver`.

  Buttons:
  - SSH is solid when `ssh.enabled`. It then calls WP-14's `openSession({ deviceId, deviceName, protocol: 'SSH', origin })`.
  - If SSH is enabled but has no accepted host key, the button opens the connection test instead (WP-14 H-1).
  - If SSH is not enabled, the button is dashed with a "+" and opens the Settings tab at the SSH section (DEV-022).
  - RDP is always dashed with a "+" in Phase 1. It opens Settings at a "Remote Desktop (RDP)" section that says RDP comes in a later version. It never starts a session.
  - Edit opens the Settings tab.
- **D-9 Tabs (Section 6.7).**
  - The tabs are Overview, Checks, Sessions, Logs and Settings. The tab and its section are URL search parameters (`tab`, `section`), so Back restores them. An unknown value is Overview.
  - It is an ARIA `tablist` with roving focus (arrow keys, Home, End).
  - The selection indicator moves with `spring-snappy` (tab selection role); with reduced motion it moves instantly.
  - Panels load lazily on first show, with the Loading role: a skeleton after `threshold-loading`, held for at least `threshold-loading-min`, then a cross-fade.
- **D-10 Tab content in Phase 1.**
  - **Overview:** status, maintenance flag, uptime for 24 hours, 7 days and 30 days (`DAY`, `WEEK`, `MONTH`; null is "—"), check count by status, and the SSH host key fingerprint. No metric charts (Phase 2): the panel shows no empty chart slots.
  - **Checks:** the check list. Each row shows the name, type, status, last response time, certificate days (CHK-007) and a pause toggle (CHK-005). A row opens the heartbeat history: a page of 100 with "Load older", and a response-time chart (an SVG polyline with the Chart update role). Add, edit and delete use the check form (T3).
  - **Sessions:** `sessions(deviceId)`, newest first: start, end, duration, operator and end reason.
  - **Logs:** `events(filter: { deviceId })` with `eventAdded` filtered to this device, through WP-12's `eventsApi`. Messages are shown as text only.
  - **Settings:** the device form in edit mode (D-2 to D-5), the check defaults note, and Delete (D-7).
- **D-11 Live updates.**
  - `deviceStatusChanged(deviceId)` updates the pill with the Status change role.
  - `heartbeatAdded(deviceId)` updates check rows and the open history with the New heartbeat role.
  - Subscriptions stop when the route unmounts.
- **D-12 Card to detail (Section 5.7.3).**
  - A `sharedItem(key)` attachment in `lib/motion/shared/` (a WP-11 H-7 subfolder) works as follows:
    1. On mount it looks for another connected element with the same `data-shared` key.
    2. That element is the outgoing page, still in the DOM during the layout's `crossFade` out.
    3. It FLIPs from that element's rect with `spring-move`.
  - With reduced motion it does nothing, so the page cross-fade is the reduced form.
  - The header name and pill use it. WP-12's card adds the same attachment for the reverse path (handoff H-2).
- **D-13 Heading height (WP-11 H-7).** The header line has a fixed `block-size` from tokens, so no font change or late data moves the tabs.
- **D-14 Typed IDs (K7).** Route params are parsed into a branded `DeviceId` at the route edge. A malformed ID shows "Device not found" with no request.
