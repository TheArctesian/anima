## Design notes (orchestrator, before the build)

- sqlx 0.8.6 `sqlx-postgres/src/testing/mod.rs`: `test_context` runs `create database "<name>"` with no
  `TEMPLATE`, so every test database copies `template1`. The master connection uses database `postgres`
  (from `socketDatabaseUrl`), so `_sqlx_test` bookkeeping never lands in `template1`.
- Every `#[sqlx::test]` in the workspace passes `migrations = "./migrations"` (421 single-line, 751 multi-line,
  none with `migrations = false`). `Migrator::run` skips versions already in `_sqlx_migrations` whose checksum
  matches, so a template migrated with byte-identical files and sqlx's own checksums is a no-op per test.
  A checksum or version mismatch fails every database test loudly; it cannot pass silently.
- sqlx 0.8.6 never calls `cleanup_test_dbs` on its own; each test drops only its own database, so one process
  per test (nextest) cannot delete another test's database.
- No migration uses `-- no-transaction`, `current_database()` or `ON DATABASE`; roles are cluster-wide anyway.

## Decisions

- D-1 (orchestrator): one task, one builder slot, builder-heavy; reviewer is the code reviewer (no secrets touched).
- D-2 (orchestrator): installs go to `~/.cargo/bin` with `cargo install --locked` and a scratch `--target-dir`, so
  the shared `~/.cache/cargo-target` (R-101) is never written.
- D-3 (builder): the Rust tests become three gates, so the gate count is fourteen. Gate 3 `cargo nextest run --workspace`
  (through `with-postgres`), gate 4 `cargo test --workspace --doc`, gate 5 `cargo test --workspace --test pinning`.
  The workspace has no doctests today (all five library crates report 0), but gate 4 costs seconds once gate 3 has built,
  and it keeps a future doctest from going unrun. `anima-desktop::pinning` is `harness = false` (R-069): nextest cannot list
  it (its output is not libtest's), so `.config/nextest.toml` excludes it with `default-filter` (nextest then skips the
  binary without running it) and gate 5 runs it as `cargo test` did. `--workspace` on gates 4 and 5 keeps the feature
  resolution of gate 3, so nothing rebuilds (`-p anima-desktop` would resolve features for one package and rebuild).
- D-4 (builder): `.config/nextest.toml` sets `retries = 0` and `fail-fast = true` explicitly; no slow-test timeout that
  terminates (nextest's default only reports slow tests), no test groups.
- D-5 (builder): a gate may name executables it needs on `PATH` (`Gate.requires`); a missing one throws, so the gate
  fails with the install command (CQ-024). Only `cargo-nextest` is required; `sccache` is optional.
- D-6 (builder): `template1` is migrated with one `psql -X -q -v ON_ERROR_STOP=1 -c BEGIN -c <file text> -c <ledger row>
  -c COMMIT` per migration. `-c` text is sent with `PQexec` unchanged (no `:variable` expansion, no meta-commands unless
  the text starts with a backslash, which the plan refuses); stdin and `-f` would go through psql's lexer. libpq's
  `PG*` variables are dropped and sqlx's session settings (`DateStyle`, `client_encoding`, `TimeZone`,
  `extra_float_digits`) are set, so the migration runs in the same session state as under sqlx. The plan refuses
  `-- no-transaction`, reversible (`.up.sql`, `.down.sql`) files, invalid UTF-8, NUL bytes and repeated versions.
- D-7 (builder): sccache is set for every gate when it is on `PATH` and `RUSTC_WRAPPER` is unset (only cargo reads it);
  an empty `RUSTC_WRAPPER` (cargo's "no wrapper") is kept. sccache 0.19.0 keys rust compiles on the compiler, the
  arguments, every dep-info source file and env dependency, the dependency rlibs' contents, every `CARGO_*` variable
  and the cwd; it caches only rlib and staticlib crates (never a test binary, build script or proc macro) and never a
  failed compile. Measured: with `CARGO_TARGET_DIR` in the environment, a fresh target folder got 0 Rust hits, because
  the variable is in the key. So `RUSTC_WRAPPER` is `quality/bin/compile-cache.ts`, which runs sccache without
  `CARGO_TARGET_DIR`/`CARGO_BUILD_TARGET_DIR` (rustc never reads them; cargo keeps them, so R-101 is unchanged). A
  `/bin/sh` wrapper broke the hub's integration tests: dash drops `CARGO_BIN_EXE_anima-hub` (a hyphen in the name).
  Clippy on workspace crates (`sccache clippy-driver rustc ...`) is never cached ("multiple input files"), proved with a
  deliberate `ptr_arg` warning in a scratch copy: clippy failed with sccache on, passed after the revert.
- D-8 (builder): the template plan refuses rather than guesses; a test that wants an empty database
  (`migrations = false`) would now get a migrated one. None exists today (all 1172 `#[sqlx::test]` attributes name
  `migrations = "./migrations"`); reviewers should reject `migrations = false` or move it off the
  template (open risk in the report).
- D-9 (builder): the template is opt-in (`with-postgres.ts --migrated-template <command>`; gate 3 passes it). The first
  full gate run failed in gate 9: `@anima/deploy`'s tests also run through `with-postgres` and install
  `deploy/postgres/roles.sql`, which creates `anima_runtime`; migration 0001 had already created that cluster-wide role
  while migrating `template1`. Without the flag the cluster stays as `initdb` made it, as before WP-55.
