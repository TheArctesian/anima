## Decisions

- **F-1 Base.** The package branch starts at the local `phase-3` head 83747e5f (WP-40 T2 and T4 merged).
- **F-2 Moved form paths.** The plan row names `lib/forms/check/` and `lib/forms/device/`; WP-42 D-3 moved them to
  `lib/checks/form/` and `lib/devices/form/`. WP-50 owns only the named parts there. Additive documents in the
  domain's existing client (`lib/checks/api.ts`, `lib/devices/api.ts`) are part of those parts: one GraphQL client
  per domain (AGENTS.md, Idiomatic).
- **F-3 Pending fields stay out of existing documents.** K1 Phase 3 fields are `@pending`; a hub that does not yet
  declare one rejects any document that selects it, and the whole document fails. So each Phase 3 feature uses its
  own documents, loaded by its own section, and no existing document (`Device`, `DeviceChecks`, `UpdateDevice`
  variables) gains a pending field before its hub package merges. A section whose query fails shows its own error
  state and leaves the rest of the page working. When the hub package merges, a follow-up folds the fields in if
  that is simpler.
- **F-4 Token generator.** Emitting the K5 light blocks needs `design/src/` (the generator) to learn modes. The
  plan row gives WP-50 the light values "and the generated outputs"; WP-50 takes the generator change that produces
  them, with no change to any existing output line in dark mode (golden test).
- **F-5 Sessions stay dark.** The terminal (RA-010, `terminal.*` tokens) and the remote desktop canvas show the
  device's own screen. They keep the Nord dark values in light mode; TOK-011 concerns semantic tokens, which
  components read. The session chrome (tabs, toolbar) follows the theme.
- **F-6 Theme on the device.** The choice is stored in `localStorage` as `anima.theme` (`dark`, `light`, `system`;
  default `dark`, UI-005), as the typeface choice is (UI-020). `lib/theme/` sets `data-theme` on `<html>`; CSS alone
  follows the system (`prefers-color-scheme`), so no script listens for the system change. Applying it at start is
  one line in `routes/+layout.svelte` (handoff).
- **F-7 Reduced motion in the app (D-28, MOT-043).** "Reduce motion: System, On, Off", stored as `anima.motion`,
  applied as `data-motion` on `<html>` (`reduce` or `full`; absent means System). The generated CSS applies the
  reduced block for `[data-motion="reduce"]` and keeps the media query except under `[data-motion="full"]`;
  `lib/motion/preference.ts` reads the choice (MOT-041). `lib/motion/` has no Phase 3 owner: this needs a ruling
  or a handoff commit (asked in the first report).
- **F-8 Secrets in the client.** Secret fields (webhook URL and header values, ntfy topic and token, SMTP password,
  Apprise URLs or key) are write-only: the form never shows a stored value, sends `null` to keep it and `""` to
  clear an optional one (K1). An API key secret shows once, in a field the operator can copy, and is dropped from
  memory when the dialog closes; it is never logged, stored, put in a URL or in an error (LOG-007, K7).
- **F-10 Page order.** Settings is one page of sections, each a `<section aria-labelledby>` with an `h2`, in this
  order: Account (signed in as, Sign out), Hub (desktop), Appearance (Theme, Reduce motion, Interface font,
  Monospace font), Notifications, Default check settings, Data retention, Updates (desktop), API keys.
  (Amended for R-096 in T13: API keys, whose list length is unknown until it loads, ends the page, so its growth
  moves nothing.) The route
  only composes; each section lives in its domain folder and loads its own data (F-3). T3 sets the heading
  pattern; each later task adds one import and one element to `+page.svelte` and its own tests in its folder.
- **F-11 Colour scheme of native controls.** `global.css` says `color-scheme: dark`. Light mode needs
  `color-scheme: light` for native controls and scroll bars, in the same selectors as the K5 light blocks. That is
  a non-token property in an unowned file: a handoff line in T3.
- **F-9 Review.** Two rounds per task (R-066); only must findings block. Security tasks (T5, T8) get
  reviewer-security (Opus) with a scoped mutation run (20 minutes) and reviewer; screens get reviewer-interface,
  which measures only this package's screens, once, in WebKit and Chromium against a fake hub with K6 fixtures
  (MV-001, CON-003).
