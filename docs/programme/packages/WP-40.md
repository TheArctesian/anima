## Scope

From the plan row, the WP-40 package note and the programme orchestrator's brief:

1. Copy the K1–K7 deltas of [phase-3-contracts.md](../phase-3-contracts.md) into `contracts/` in one commit;
   headers "frozen for Phase 3"; `@pending` on every K1 addition (P3-002).
2. `ids.rs`: `ApiKeyId`, `ChannelId`, `DeliveryId`, `ShareId`, `RecordingId`. `config.rs`: the four K7
   variables, parsed with K7 defaults, used by nothing yet.

   later as a WP-41 handoff.

5. The R-081 spec changes in `docs/design-spec.md`.

Programme files (`schema.rs`, `main.rs`, `lib.rs`, `upkeep.rs`) are not edited (PKG-001).

## Decisions

- D-WP40-1. Builders share one `CARGO_TARGET_DIR` in the package scratchpad; cargo's lock serialises the
  builds, which keeps R-068's one cargo run at a time.
- D-WP40-2. T1: codegen includes `@pending` enum values, so `CheckType.DOMAIN_EXPIRY` broke client
  exhaustiveness (`lib/forms/check/model/*`, `routes/devices/[id]/checks/rows.ts`). Chosen: the minimum that
  compiles in T1 (label, error entry, kept out of the type picker), not a codegen change that hides pending
  API. The editor is WP-50's (D-29).
- D-WP40-3. T1: two contract texts that the deltas contradict are aligned with them: the K1 header names
  `login`, `signInBrowser` and `joinShare` as signed-out (D-4, D-7), and K4 §5 "never records" gains the
  RA-040 exception. The Phase 2 `sessions` K3 entries stay until WP-41 moves them.
- D-WP40-4. T5: UI-005 carries the light theme (UI-001 gains only the derived-primitive note); the spec has
  no change log, so no row is added.
