## Decisions

- **D-1 Key file format (SEC-004).** The file holds the 32-byte key as standard base64 (`openssl rand -base64 32`), surrounding ASCII whitespace ignored. Any other length or encoding is `Error::KeyFormat`. The file is read once at start by `Vault::from_key_file`; the path and the key bytes never appear in an error message or log. No file-mode check: Docker secrets are mounted world-readable inside the container, so a mode check would refuse the normal deployment.
- **D-2 Key id.** `key_id` = first 8 bytes of SHA-256(`"anima/credentials/key-id/v1"` ‖ key), as 16 lowercase hex characters. It names the key without revealing it, and lets `open` refuse a value sealed by another key before decryption (`Error::WrongKey`). It prepares key rotation (not in Phase 1).
- **D-3 Cipher.** XChaCha20-Poly1305 (`chacha20poly1305` crate), a fresh random 192-bit nonce from the OS for each `seal`. Associated data always includes a format tag and the `key_id`, so a changed `key_id` also fails authentication.
- **D-4 Context binding (R-010).** `seal(&self, plaintext, context: &[u8])` and `open(&self, sealed, context: &[u8])` bind `context` as associated data. Fixed contexts: `credentials.secrets:<device_id>:<kind>` (store) and `access.operators.totp:<operator_id>` (WP-05). A ciphertext copied to another row or device does not open.
- **D-5 `Sealed` shape.** Private fields with accessors (`nonce()`, `ciphertext()`, `key_id()`), `Sealed::from_parts(nonce, ciphertext, key_id) -> Result<Sealed, Error>` (checks the nonce length), and `to_bytes()` / `from_bytes()` with a versioned layout (`0x01 ‖ len(key_id) ‖ key_id ‖ nonce ‖ ciphertext`) for single-column storage such as `access.operators.totp_secret_enc`. `Sealed` holds no plaintext, so it may derive `Debug`, `Clone`, `PartialEq`.
- **D-6 `Secret`.** `Secret::new(Vec<u8>)`, `From<String>`, `expose(&self) -> &[u8]`. Inner `Zeroizing<Vec<u8>>`. No `Debug`, `Display`, `Serialize`, `Clone`, `PartialEq` (timing). Proved by a trait-absence test (`static_assertions::assert_not_impl_any!`, dev-dependency).
- **D-7 `Vault`.** `Clone`; key held as `Zeroizing<[u8; 32]>` (each clone zeroized on drop). Manual `Debug` that prints only `key_id`. `Vault::from_key(bytes)` is `pub(crate)`/test-only so tests do not write files for every case; `from_key_file` is the public constructor.
- **D-8 Errors.** One `credentials::Error` (`thiserror`): `KeyFile(std::io::ErrorKind)`, `KeyFormat`, `WrongKey`, `Decrypt`, `Malformed`, `Database(sqlx::Error)` (Task 2). Messages are plain sentences with no path, key, nonce or plaintext.
- **D-9 Database tests (R-009).** `bun run gates` starts a throwaway PostgreSQL for `cargo test`; `#[sqlx::test]` needs no setup and a missing database fails the gate. No stub tables in another schema: T2 waits until WP-06's `devices` migration is on `phase-1`.

## Tasks

### T1 `vault` — Vault, Secret, Sealed (pure crypto, no tables) — first to accept

- Branch: `wp/07-credentials/vault`. Builder: `builder-heavy`. Reviewers: `reviewer`, `reviewer-security`. Tags: security.
- Files: `crates/hub/src/credentials.rs` (public face, `Error`), `crates/hub/src/credentials/vault.rs` (`Vault`, `Sealed`), `crates/hub/src/credentials/secret.rs` (`Secret`), `crates/hub/src/credentials/tests.rs`.
- Handoffs (PKG-001): `pub mod credentials;` in `crates/hub/src/lib.rs`; workspace deps `chacha20poly1305`, `zeroize`, `sha2`, `base64` (and dev-dep `static_assertions`, `tempfile`) in root `Cargo.toml` and `crates/hub/Cargo.toml`.
- Spec: SEC-003, SEC-004, LOG-007. Contract: K3 `Vault`, `Secret`, `Sealed`; K7 errors.
- Test plan (named by requirement):
  - `sec_003_other_context_fails` (R-010).
  - `sec_003_seal_then_open_returns_plaintext`; sealing the same secret twice gives different nonces and ciphertexts.
  - `sec_003_wrong_key_fails` (different key → `WrongKey`); same `key_id` forced with a different key → `Decrypt`.
  - `sec_003_changed_nonce_fails`, `sec_003_changed_ciphertext_fails` (flip one bit; also truncated), `sec_003_changed_key_id_fails`.
  - `Sealed::to_bytes`/`from_bytes` round trip; malformed bytes (empty, bad version, short nonce) → `Malformed`, no panic.
  - `sec_004_key_from_file` with a throwaway key in a `tempfile` (generated in the test); trailing newline accepted; wrong length, non-base64, empty, missing file → error whose `Display` contains neither the path nor key text.
  - `log_007_secret_has_no_format_traits`: `assert_not_impl_any!(Secret: Debug, Display, Serialize, Clone)`; `Vault` `Debug` output contains the `key_id` and not the key bytes.
  - Deterministic key id for a fixed test key (value pinned).

### T2 `ssh-store` — `credentials.secrets`, `store_ssh`, `load_ssh`, `has_ssh`, `clear_ssh`

- Branch: `wp/07-credentials/ssh-store` (from the package branch after T1). Builder: `builder-heavy`. Reviewers: `reviewer`, `reviewer-security`. Tags: security.
- Files: `crates/hub/migrations/0200_credentials_secrets.sql`, `crates/hub/src/credentials/ssh.rs` (`SshSecret`; the pure mapping between `SshSecret` and secret rows), `crates/hub/src/credentials/store.rs` (only SQL for `credentials.*`), additions to `credentials.rs`, tests in `crates/hub/tests/it/credentials.rs` (+ `mod credentials;` in `tests/it/main.rs`).
- Handoffs: `sqlx` features `migrate`, `chrono` (if needed) in root `Cargo.toml`.
- Spec: SEC-003 (only ciphertext stored), SEC-005/CLI-004 (no API returns the secret; `SshSecret` has no format/serialize traits), LOG-007. Contract: K2 `credentials.secrets` columns and `unique (device_id, kind)`, FK `on delete cascade`; K3 `SshSecret`, `store_ssh`, `load_ssh`, `has_ssh`.
- Behaviour: `store_ssh` replaces all SSH rows of the device in the caller's connection (delete, then insert one row per part: `ssh_password`, or `ssh_private_key` + optional `ssh_passphrase`), sealed with `(device, kind)` context. `load_ssh` returns `None` when no rows, rebuilds `SshSecret`, and returns `Malformed` for an impossible row set (password and key together, passphrase alone). `has_ssh` is an `EXISTS` query. `clear_ssh(conn, device) -> Result<bool, Error>` deletes the device's SSH rows and returns true if any were removed (R-010).
- Test plan: `sec_003_stored_row_holds_no_plaintext` (read the row: ciphertext ≠ plaintext and does not contain it); store/load round trip for password, key, key + passphrase; replacing a key with a password leaves no key rows; `has_ssh` before/after; a row copied to another device fails to open (`Decrypt`); a different vault key → `WrongKey`; device delete cascades the rows (DEV-015); `log_007_ssh_secret_has_no_format_traits`.

## Escalations

- **E-1 (answered by R-009).** Gates start no PostgreSQL and set no `DATABASE_URL`; `#[sqlx::test]` cannot run in `bun run gates` as it is. The FK target `devices.devices` (WP-06) is not on `phase-1` yet.
- **E-2 (answered by R-010: accepted, K3 updated).** K1 has `setSshCredential`, `clearSshCredential` and `credential` on device inputs, but K3 lets `devices` call only `has_ssh` and has no `clear_ssh`. Proposed: devices owns the resolvers and may call `store_ssh` and a new `clear_ssh(conn, device) -> Result<bool, Error>`. WP-07 adds `clear_ssh` only after a ruling.
- **E-3 (answered by R-010: context binding now in `seal`/`open`).** K3 `seal`/`open` bind no row context; a sealed TOTP value can be swapped between operator rows by someone with DB write access. Possible later K3 addition: `seal_for`/`open_for` with a context.
