### Decisions

- **D-1 Guacamole tunnel kept, not mounted.** Only `Protocol::Ssh` exists, so after this package nothing uses `/tunnel`. The `tunnel` module, its tests and the client's vendored `guacamole-common-js` stay for RDP and VNC (Phase 2, R-062 "guacd stays for RDP and VNC"). `main.rs` mounts `terminal_router` instead of `tunnel_router`, so no SSH ticket can reach guacd. The guacd tests keep using SSH tickets as their fixture protocol; they test the relay, which Phase 2 reuses. The programme may rule to delete it instead.
- **D-2 Opening before the upgrade, PTY after.** As in the Guacamole tunnel, the hub connects, pins the key and signs in before it answers the request, so unreachable devices get 503 and the session ends `GATEWAY_ERROR` (K4 §2 pattern). A changed key or a refused credential still upgrades, so the client hears `end` and the close code (4001, 1011). The PTY and shell wait for the client's first `resize`, so the first prompt is drawn at the real size.
- **D-3 No stored credential is `AUTH_FAILED`.** guacd prompted for a password inside the terminal; the hub does not (no typed secret passes through the hub). See E-1.
- **D-4 xterm.js 6.** `@xterm/xterm` 6.0.0 with fit 0.11.0, webgl 0.19.0, search 0.16.0, web-links 0.12.0, unicode11 0.9.0, pinned exactly. xterm 6 removed the canvas renderer (`@xterm/addon-canvas` 0.7.0 needs xterm 5), so the fallback when WebGL is missing or its context is lost is xterm's DOM renderer, not canvas.
- **D-5 Keyboard-interactive.** When a device offers `keyboard-interactive` and not `password`, the hub answers its prompts with the stored password, as libssh2 (guacd) did, so devices that worked through guacd keep working.
- **D-6 Shared pieces move, not copy.** The ticket redeem, the end table, the end record, the target resolution and the `russh` sign-in are shared between the two tunnels and the probe; where one lives in `tunnel/` it moves to a module named for its concept.

### Escalations

- **E-1 (to the programme, not blocking).** GW-015 / the guacd in-terminal password prompt has no equivalent on the terminal tunnel: a device with no stored credential ends `AUTH_FAILED` with an event that says to store one. An in-terminal prompt in the hub (read the typed line, no echo, never kept) is possible later; proposed for issue #1.
