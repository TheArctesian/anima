## Hard rules for every agent in this package

- No command against the Hostinger VPS, the Hostinger account or CLI, Cloudflare, or any Headscale server, not even a read. No SSH to the VPS. No `hostinger`, `wrangler`, `flarectl`, `curl api.cloudflare.com`, `tailscale`, `headscale` against a real server (VPS-005, DNS-008).
- Never read secret files. Keys, tokens and passwords appear only as placeholders such as `${HEADSCALE_NOISE_KEY_FILE}` or as paths to files the operator creates.
- Commit only on your task branch. Never push or merge.

## Facts checked against Headscale v0.29.7 (2026-10-30, latest)

Source: `juanfont/headscale` tag `v0.29.7` (`config-example.yaml`, `docs/ref/*.md`, `cmd/headscale/cli/*.go`).

- `node.expiry` is the default key expiry for **non-tagged** nodes only; "Tagged nodes are exempt and never expire". It parses with `model.ParseDuration` (`180d` works); a value that fails to parse is silently treated as "no expiry" (warning in the log only).
- Policy: HuJSON, `policy.mode: file`, `policy.path`; Headscale recommends `grants` over legacy `acls`. A policy file without `acls`/`grants` allows everything. Since v0.29.0 `*` means only the Tailscale CGNAT and ULA ranges. Reload with SIGHUP.
- `headscale policy check --file <f>` validates against the live server; with `--bypass` it opens the database directly and runs the policy's `tests` block. It needs a stopped server for `--bypass`.
- Routes: `headscale nodes list-routes`, `headscale nodes approve-routes --identifier <id> --routes <cidr,...>`. Without `autoApprovers`, routes stay unapproved until the operator approves them.
- Pre-auth keys: `headscale preauthkeys create --user <USER_ID> [--tags tag:x] --expiration 1h` (single use and 1 h by default). Personal registration: `headscale auth register --user <USER> --auth-id <AUTH_ID>`.
- `headscale nodes expire --identifier <id> [--expiry RFC3339] [--disable]`.
- TLS: built-in Let's Encrypt with `tls_letsencrypt_challenge_type: TLS-ALPN-01` on `listen_addr` port 443 (no port 80 needed).
- `listen_addr` serves the Tailscale control protocol, DERP and the REST API `/api/v1` (API key required). `grpc_listen_addr` and `metrics_listen_addr` default to `127.0.0.1`. The CLI uses the unix socket.
- Container image `docker.io/headscale/headscale:0.29.7` is distroless; health check `headscale health`.

## Decisions

- **D-1 Client identity (VPN-003).** Client computers are **personal nodes** of the Headscale user `operator`, not tagged nodes, because Headscale never expires tagged nodes. `node.expiry: 180d` then gives client keys a 180-day expiry; hub and routers are tagged and never expire. The policy names clients as `operator@`. There is no `tag:client`: a client tagged by mistake would lose its expiry. (Deviation from the brief, which listed `tag:client`; reported to the programme orchestrator.)
- **D-2 Tags.** `tag:hub` (the VPS host, which runs the hub), `tag:router` (every subnet router) and one site tag per router: `tag:site-home`, `tag:site-office1`, `tag:site-office2`. All tag owners: `operator@`. A router carries `tag:router` and its site tag.
- **D-3 Sites (VPN-001).** home `10.10.0.0/24` (router: home Linux PC), office 1 `10.20.0.0/24` (no router in Phase 1; the Mac there is a client), office 2 `10.30.0.0/24` (router: office 2 Linux PC). Policy `hosts` aliases: `site-home`, `site-office1`, `site-office2`.
- **D-4 Access rules (VPN-004).** `grants` only, no `acls`, no `*`, no `autogroup:danger-all`, no `autoApprovers`:
  - `operator@` → `tag:hub` on tcp 443 (hub API) and tcp 22 (VPS administration over the VPN).
  - `operator@` → all three site subnets, all ports.
  - `tag:hub` → all three site subnets, all ports.
  - `tag:site-<s>` → `site-<s>`, all ports (each router to its own subnet only).
  - Nothing else: no rule has a subnet, `tag:router` or `tag:hub` as source towards `operator@`, so devices and appliances cannot start a connection to a client; return traffic of permitted connections is allowed by WireGuard state.
  - The same table is written as the policy `tests` block (run by `headscale policy check --bypass` on the server) and checked by the package's own evaluator in `bun test`.
- **D-5 Hub address (NET-005, DNS-001, DNS-005).** The VPS host joins the VPN with hostname `hub` and `tag:hub` (MagicDNS name `hub.net.anima.ing`). The public record `hub.anima.ing` is an A record to that node's `100.64.0.0/10` address. The hub listens on that address, port 443 (handoff to WP-04; K7 `ANIMA_LISTEN`). No `extra_records`: the node name already gives `hub.net.anima.ing`, and the public record is the primary name.
- **D-6 Headscale TLS and admin (VPS-003).** Headscale terminates TLS itself with Let's Encrypt TLS-ALPN-01 on `0.0.0.0:443`; no reverse proxy (one less component, and a proxy must special-case the control protocol). Admin is only the CLI over the unix socket through `docker exec` in an SSH session, and SSH is open only on the VPN interface. `grpc_listen_addr: 127.0.0.1:50443`, `metrics_listen_addr: 127.0.0.1:9090`, no OIDC, and **no API keys** (the guide checks `headscale apikeys list` is empty), so `/api/v1` is unusable from the internet.
- **D-7 DERP.** Embedded DERP only: `derp.server.enabled: true`, region 999 `anima`, STUN `0.0.0.0:3478`, `verify_clients: true`, `derp.urls: []` (no Tailscale public relays, so relayed traffic stays on the operator's VPS; VPN-005 shows relayed paths). Public IPv4 from `${VPS_PUBLIC_IPV4}`.
- **D-8 DNS in the VPN (DNS-006).** `dns.base_domain: net.anima.ing`, `magic_dns: true`, `override_local_dns: false` (split DNS: the VPN answers only `net.anima.ing`; other queries use the local resolver, so the Pi-hole and site DNS keep working).
- **D-9 VPS layout.** Ubuntu 24.04 LTS (verify before step 1). Docker Compose project in `/opt/anima/headscale` with `config/` (read-only mount) and `lib/` (database, keys, ACME cache). Headscale runs with `network_mode: host`, read-only root, `no-new-privileges`, `cap_drop: [ALL]`, `cap_add: [NET_BIND_SERVICE]`. Image pinned to `0.29.7`; the guide pins the digest at install.
- **D-10 Firewall (VPS-002).** nftables `inet` table, input policy drop: established/related, loopback, ICMP (rate-limited echo, required ICMPv6), public 443/tcp, 3478/udp, 41641/udp, and 22/tcp **only on `tailscale0`**. The forward chain is left to Docker. Docker-published ports bypass the input chain, so `/etc/docker/daemon.json` sets `"ip": "127.0.0.1"` as the default bind address (handoff to WP-04: publish hub ports only on the VPN address). Applying the firewall arms an automatic rollback after 180 s unless the operator confirms from a second SSH session over the VPN. Hostinger's panel firewall mirrors the same rule set (defence in depth, operator change).
- **D-11 SSH and updates (VPS-001, VPS-004).** sshd drop-in: `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no`, `AuthenticationMethods publickey`. The script refuses to apply it unless a non-root sudo user has a non-empty `authorized_keys`. `unattended-upgrades` with security origins, automatic reboot at 04:30 UTC. Recovery path when SSH over the VPN fails: Hostinger browser console (operator).
- **D-12 Backup (VPS-006).** Daily systemd timer on the VPS: consistent SQLite snapshot (`sqlite3 … "VACUUM INTO"`), plus `noise_private.key`, `derp_server_private.key`, `config.yaml` and `policy.hujson`, sent with `restic` to a `rest-server` on the **home Linux PC** in `--append-only --private-repos` mode, reached over the VPN (hub → home subnet is permitted). restic encrypts on the VPS with a password file the operator also keeps offline. A compromised VPS cannot delete old snapshots; pruning runs on the home PC. Handoff to WP-04: the Anima database backup can use its own repository on the same `rest-server`.
- **D-13 Public DNS (DNS-003, DNS-004, DNS-008).** `deploy/dns/anima.ing.records.json` in Cloudflare API v4 record shape: `hs` A (not proxied) → `${VPS_PUBLIC_IPV4}`; `hub` A (not proxied) → `${HUB_VPN_IPV4}`; `updates` AAAA `100::` proxied (the redirect rule itself is WP-04 stage B); CAA `letsencrypt.org` on the apex. Not applied by agents. Tokens are scoped to "Zone DNS Edit" for `anima.ing` only and passed to `curl` from a header file, never on the command line.
- **D-14 Tests.** One bun workspace package `deploy/headscale/` (`@anima/headscale`) tests policy, config, compose, VPS scripts and backup; one `deploy/dns/` (`@anima/dns`) tests the records. Shell scripts take a `--root <dir>` and command overrides so tests run them against a temporary folder and fake `nft`/`systemctl`/`restic`/`sqlite3`. `shellcheck` runs from the tests (installed on the operator's machine; a missing `shellcheck` is a failure, CQ-024). Handoff to WP-01/programme (PKG-001): add `"deploy/headscale", "deploy/dns"` to root `workspaces` and refresh `bun.lock`; until then the tests run with `bun test deploy/`.
