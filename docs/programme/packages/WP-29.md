## Decisions

- **D-1 One migration adds all four identifiers.** `0310` replaces `checks_type_check` with the seven Phase 1
  ids plus `docker`, `systemd`, `snmp`, `tailscale_ping` (CHK-009). Parallel tasks then need no migration of
  their own, so T2 and T3 cannot conflict on the constraint. A type the hub does not yet read is refused by
  the code (`Unreadable`), not by the database.
- **D-2 Probe outcomes Degraded and Unknown.** `ProbeResult` gains one field that says how the probe judged
  itself: answered (today), `starting` (an ok result the evaluation records as Degraded; Docker
  `health: starting`) and `unjudged` (the hub cannot test: no LocalAPI proxy). `evaluate` records an
  unjudged result as Unknown with its message, resets failures and schedules the next probe after the
  interval; invert does not apply to it. An inverted `starting` result is a failure (the container runs).
- **D-3 Docker and systemd go through the SSH link with the D-3 commands, unchanged.**
  `docker ps -a --no-trunc --format '{{json .}}'` and `systemctl list-units --all --plain --no-legend --no-pager`,
  built with `FixedCommand::new(..).arg(..)` from `'static` text only (CHK-012). The parsers are pure and take
  the output bytes and the configured name. The output is never logged or stored; only fixed messages reach
  the heartbeat (LOG-007, WP-23 H-5).
  - Docker: a line matches when one of its `Names` (comma-split) equals the container. Up: `State` running
    and `Status` without `(unhealthy)` or `(health: starting)`. Degraded: running with `(health: starting)`.
    Else Down, with a fixed message naming the state class. No match: Down "the container was not found".
  - systemd: a bare name gets `.service`. Up: the unit's ACTIVE column is `active`. No row: Down "the unit
    was not found".
  - Name rules match the client editor (WP-25): container `^[a-zA-Z0-9][a-zA-Z0-9_.-]*$`, unit
    `^[A-Za-z0-9:_.@\\][A-Za-z0-9:_.@\\-]*$`, each at most 255 bytes; timeout 100–60000 ms.
- **D-4 Tailscale ping.** `Probing` gains `localapi: Option<String>` (K7 `host:port`); `main.rs` passes
  `config.tailscale_localapi` (handoff H-2, K3 change request CR-1). None: Unknown "Tailscale ping needs the
  LocalAPI proxy (ANIMA_TAILSCALE_LOCALAPI)". The target (config or device host) is resolved once; only an
  IPv4 address in 100.64.0.0/10 that the `AddressPolicy` permits is sent (the proxy accepts only that).
  The hub calls `POST /localapi/v0/ping?ip=<ip>&type=disco` on the proxy, no redirects, a 64 KiB body cap.
  The proxy address is operator infrastructure on the deny list, so it is not checked against the policy.
  `LatencySeconds` is the response time; a non-empty `Err` is Down with a fixed message (the text is not kept).
- **D-5 SNMP (D-13).** v2c and v3 authPriv only, with HMAC-SHA-256-192 (RFC 7860) and AES-128-CFB (RFC 3826),
  written over `hmac`, `sha2` and `aes` (no SNMP crate). UDP to the device host, resolved once and checked
  against the policy. Expected null: Up when the OID answers with a value (not `noSuchObject`,
  `noSuchInstance`, `endOfMibView`); else Up when the value's text form equals `expected`.
  - Secrets (community; v3 auth and privacy passwords) are sealed in `secrets_sealed` with context
    `checks.checks.snmp:<check_id>`, bound to the version and user name they were given for; a read never
    returns them (SEC-003, SEC-005). An omitted secret on update keeps the stored one only for the same
    version and user name; else a field error asks for it.
  - Limits: community and passwords 1–256 bytes, v3 passwords at least 8 characters (RFC 3414), user name
    1–32 bytes, OID dotted numbers with at least two arcs, `expected` at most 1024 bytes.
- **D-6 Models.** Builders per the brief: Sonnet, Opus for SNMP v3. Reviewers: Sonnet; Opus security for T3
  (secret sealing and the USM code). T1 is reviewed by Sonnet with mutations on the Docker and systemd
  parsers (brief); its commands are static by type, which the reviewer checks against CHK-012.
- **D-7 One cargo run at a time (R-068).** Every builder, gate run and reviewer wraps `cargo` and
  `bun run gates` in `lockf -k /private/tmp/claude-501/wp-29-cargo.lock …`.

**T2 tailscale-ping.** Goal: the Tailscale ping check (D-4). Files: `probe/tailscale.rs`, `scheduler/attempt.rs`,
`config.rs`, the GraphQL files, `main.rs` (one field). Test plan: a local fake proxy (request line, query, no
headers beyond the basics), latency, `Err`, non-200, oversize body, no proxy (Unknown), a target outside
100.64.0.0/10 or refused by the policy (Down, nothing sent).

**T3 snmp.** Goal: the SNMP check (D-5). Files: `config/snmp.rs`, `probe/snmp.rs` with `probe/snmp/` (BER,
message, USM), `store/sealed.rs` (or `store/snmp_sealed.rs`), `checks.rs`, `rules.rs`, GraphQL files,
`Cargo.toml` (`aes`). Test plan: RFC 7860 and RFC 3826 vectors (key localisation, HMAC, CFB), BER round trips,
a local UDP agent for v2c and v3 (discovery, report, authPriv get, wrong auth, wrong OID, timeout), sealing
bound to check id, version and user name, keep-on-empty rules, no secret in any read, error or message.

**T4 http-urls.** Goal: `checks::http_urls` (K3, WEB-002) in one query, and the one-line swap in
`web_interfaces.rs` (WP-30 H-1). Test plan: an integration test over devices with HTTP and other checks, a
device with none absent, one statement.

**T5 batching-test.** Goal: `api_005_status_last_heartbeat…` deterministic under load (phase-2-coulds). The
checks test harness gives the batching tests loaders with a batch window long enough that one query is one
batch. Test plan: the test passes; the window is named and its reason stated.
