## Protocol facts used (verified from the guacamole-server sources)

- Element: `LENGTH.VALUE`; elements are separated by `,` and the instruction ends with `;`. The first element is the opcode. `LENGTH` counts Unicode code points of `VALUE`, not bytes (the guacd parser counts UTF-8 characters).
- guacd parser limits (`src/libguac/guacamole/parser-constants.h`, 1.6.0): `GUAC_INSTRUCTION_MAX_LENGTH 8192` (bytes), `GUAC_INSTRUCTION_MAX_DIGITS 5`, `GUAC_INSTRUCTION_MAX_ELEMENTS 128`.
- guacd 1.5.5 and 1.6.0 both send `VERSION_1_5_0` as the first `args` value (`GUACAMOLE_PROTOCOL_VERSION`). Known versions: `VERSION_1_0_0`, `VERSION_1_1_0`, `VERSION_1_3_0`, `VERSION_1_5_0`.
- SSH `args` (from `GUAC_SSH_CLIENT_ARGS` in `src/protocols/ssh/settings.c`): 38 names in 1.5.5 and 42 in 1.6.0 as compiled in the official `guacamole/guacd` image (GW-001), which does not pass `--enable-ssh-agent`; with that option `enable-agent` is added (39 and 43). 1.6.0 adds `timeout`, `public-key`, `typescript-write-existing`, `recording-write-existing`. The fixtures `tests/it/fixtures/guacd-<tag>-ssh-args.guac` are the official-image wire forms, built from the source (not captured from a running guacd); `guacd-<tag>-ssh-agent-args.guac` are the agent-enabled forms.

## Decisions

- **D-1. Branches.** The package branch is this session's branch. Task branches are local `wp/08-guac-protocol/<task>`; nothing is pushed. Tasks are serial (T2 uses T1's types), so builders work in this worktree on the task branch; reviewers mutate in detached worktrees.
- **D-2. Limits.** The decoder enforces guacd's own limits, as public constants: `MAX_INSTRUCTION_BYTES = 8192` (whole encoded instruction, including lengths and separators), `MAX_ELEMENTS = 128` (opcode + args), `MAX_LENGTH_DIGITS = 5`. Reason: guacd rejects larger instructions, so the hub never needs to buffer more; a hostile client cannot make the hub buffer more than 8 KiB per tunnel direction.
- **D-3. Strict grammar.** Digits only before `.` (leading zeros allowed, as guacd accepts them), no whitespace, value must be valid UTF-8 and contain no NUL byte (guacd ends an element at its first NUL, so a NUL would make the hub and guacd read different opcodes or values), element must be followed by `,` or `;`. A declared length that cannot fit in the remaining byte budget is rejected at its `.`. An empty opcode is valid (the internal instruction `0.,36.<uuid>;`). Any violation is a `DecodeError`; after an error the `Decoder` stays failed (every later `feed` returns the same error) because the tunnel closes (GW-011, close 1002).
- **D-4. No secret in `Debug` or errors (LOG-007).** `connect` carries passwords and keys, so `Instruction`'s `Debug` prints the opcode and the argument count only. `DecodeError` and `HandshakeError` carry no argument values: only positions, limits, opcodes and argument names (cut to 32 characters), the gateway status, and the gateway's `error` message cut to 128 characters (gateway text for the process log only, never sent to the client). `HandshakeStep::Ready` redacts `connection_id` in `Debug` (GW-014: it lets anyone who reaches guacd join the session). `ArgValues`, `ConnectParams` and `Handshake` do not implement `Debug` or `Display`.
- **D-5. Client values are typed (GW-012, GW-013).** The only client-supplied input to the handshake is `Display` (width, height, DPI) and the time zone string, the K1 `DisplayInput` fields. Every `connect` value comes from `ArgValues`, which the hub fills from the database and the credential store. There is no API that turns client name/value pairs into `connect` values, so a forbidden name cannot be set by the client. Property tests prove that no client input changes any `connect` value and cannot inject an extra instruction. The client values are also bounded: `Display::within_bounds` (1..=8192 px, 48..=480 DPI, the K4 §4 `size` bounds; `InvalidDisplay`) and an IANA-shaped time zone (`is_zone_name`, exported for WP-10: ≤ 64 characters of `[A-Za-z0-9_+-/]`, first an ASCII letter, no empty `/` segment; `InvalidTimezone`), because the time zone reaches the SSH server as `TZ` and glibc reads a leading `/` as a file path. Both are checked before anything is sent. Any emitted value with a NUL (`NulInValue`) and any emitted instruction over guacd's limits (`InstructionTooLarge`, e.g. a very large private key) fail the handshake.
- **D-6. Version negotiation (K4 Section 3 step 2).** The first `args` value must be `VERSION_X_Y_Z` at or above `VERSION_1_5_0`, else `HandshakeError::UnsupportedVersion`. The hub answers with the version guacd sent when it is `VERSION_1_5_0` (guacd 1.5 and 1.6: the same version, as K4 says). For a later, parseable version the hub answers `VERSION_1_5_0`, the newest version this crate implements (the Guacamole rule: the client answers with the highest version both sides support). Raised as open question Q-1.
- **D-7. Handshake output.** `Handshake::new` returns `select`. On `args` it returns `HandshakeStep::Send` with, in order: `size` (width, height, DPI), `audio` (no args), `video` (no args), `image` (`image/png`, `image/jpeg`, `image/webp`), `timezone`, `name`, `connect` (version, then one value per `args` name in the same order; a name without a value in `ArgValues` gets `""`). On `ready` it returns `HandshakeStep::Ready { connection_id }` (GW-014: the caller keeps it). `ready` without a non-empty connection ID is `MissingConnectionId`. An `error` before `ready` is `HandshakeError::Gateway { status: Option<u16>, message }`. `nop` before `ready` returns `Send(vec![])`. After a failure the handshake returns the same error for every later instruction. Any other opcode, a second `args`, or any instruction after `ready` or after a failure is an error.
- **D-8. Tests.** One integration test crate, `crates/guac-protocol/tests/it/main.rs` (AGENTS.md). `proptest` is a dev-dependency of this crate only. The fuzz-style test is a proptest over arbitrary bytes and over mutated valid encodings, fed in random chunk sizes, asserting no panic and that every result is `Ok` or `Err` (no nightly `cargo-fuzz`).
- **D-9. Proptest regression files.** `crates/guac-protocol/.gitignore` ignores `tests/proptest-regressions/`: those files appear only while a mutation or a failing change runs, and a real failure becomes a named example test instead.

### Test plan

- **T1.** Unit-level behaviour through the public API: known encodings (`4.size,4.1024,3.768,2.96;`, `0.,36.<uuid>;`, `4.ping,13.<ts>;`), multibyte values counted in code points (`2.é€` = 2 chars, 5 bytes; emoji). Property tests: round trip `decode(encode(i)) == i` for arbitrary Unicode opcodes and args within limits; the same encoded stream split at every byte boundary (and in random chunk sizes) gives the same instructions; several instructions in one feed. Rejection tests, each named for GW-011: non-digit length, too many digits, length longer than the value, length shorter than the value (missing `,`/`;`), invalid UTF-8, instruction over `MAX_INSTRUCTION_BYTES` (rejected before the terminator arrives), more than `MAX_ELEMENTS`, failed decoder stays failed. Fuzz-style: arbitrary bytes and byte-mutated valid streams never panic. `Debug` of a `connect` instruction does not contain its argument values.
- **T2.** The `args` fixtures for guacd 1.5.5 and 1.6.0 (official image, built from the source; plus `--enable-ssh-agent` variants) decode with the T1 decoder and give a `connect` with one value per name, in order, the version first, K4 Section 3 values at the right positions and `""` for every name without a value. Order of the `Send` instructions and their exact encodings. Version: `VERSION_1_3_0` and a non-version first arg are refused; `VERSION_1_6_0` answers `VERSION_1_5_0`. `error` before `ready` → `Gateway`; unexpected opcode; instruction after `ready`. GW-013 property test: for arbitrary in-bounds client `Display` and valid zone names (including names spelled like `hostname`, `port` and `wol-send-packet`) and arbitrary hub `ArgValues`, every `connect` value for `hostname`, `port`, `username`, `password`, `private-key`, `passphrase`, `public-key`, `recording-path`, `drive-path`, `sftp-root-directory`, `typescript-path` and `wol-*` equals the hub value (or `""`), and the encoded handshake output decodes back to exactly the same instructions (no injection). Time zones with `;`, `4.port,2.22;`, control characters, multibyte text or a bad shape are refused before anything is sent (example and property tests).

## Handoffs (PKG-001)

- **To WP-10 (relay).** Cap the WebSocket maximum message and frame size at a small multiple of `MAX_INSTRUCTION_BYTES` (for example 4 × 8192). One `feed` returns every instruction its bytes complete; `0.;` (3 bytes) becomes a 48-byte `Instruction`, so the tungstenite default of 64 MiB per message would let one client message allocate about 1 GiB (T1 security review, F-2). `guacamole-common-js` sends one instruction per message.
- **To WP-10 (relay).** `Decoder::feed` is all-or-nothing: if a feed contains a bad instruction, the instructions before it in the same feed are not returned; close with 1002 (K4 §4).
- **To WP-10 (sessions).** Resolve the time zone before building `ConnectParams`: K4 §3 says `DisplayInput.timezone`, else the device site's zone, else UTC. The handshake refuses a time zone that is not IANA-shaped (`InvalidTimezone`) instead of falling back, so `sessions` must check the client value with `guac_protocol::is_zone_name` (or use the site zone or `UTC`) first, or a client typo fails the session.
- **To WP-10 (relay).** guacamole-common-js `Client.sendSize(width, height)` (1.5.5 and 1.6.0) sends `size` with width and height only, no DPI. Check width and height against `MIN_SIDE_PX..=MAX_SIDE_PX` and a DPI only when present (`MIN_DPI..=MAX_DPI`); see Q-2. Rust's `u32::from_str` accepts a leading `+`; parse digits only.
- **To WP-10 (relay).** guacd can send `ready` and its first display instructions in one read, so one `feed` can return `ready` and more. After `HandshakeStep::Ready`, pass the rest of that feed to the relay; `on_instruction` refuses anything after `ready`.
- **To WP-10 (relay).** The internal open instruction is `encode(&Instruction::new("", [uuid]))` (`0.,36.<uuid>;`); the internal ping is an empty opcode with `args[0] == "ping"`. Re-encoding is canonical, not byte-identical (`004.ping;` comes back as `4.ping;`), which is the same instruction to guacd and the client.
- **To WP-10 (tests).** The `args` fixtures are built from the guacamole-server source, not captured. Compare one real `args` from the official `guacamole/guacd` image with `tests/it/fixtures/guacd-<tag>-ssh-args.guac` in the fake-guacd relay test or at deploy (K4 §7 asks for a recorded list).
- **To WP-10 (sessions).** Never log `HandshakeStep::Send` arguments Never log `HandshakeStep::Send` arguments (only `Instruction`'s redacting `Debug`); never send `connection_id` or the `Gateway` message to the client (GW-014, LOG-007). guacd's SSH `args` include a `timezone` name: its `connect` value comes only from `ArgValues`; leaving it `""` makes guacd use the `timezone` instruction.
- **To WP-01 / programme (root `Cargo.toml`).** `proptest = "1.12"` is declared in `crates/guac-protocol/Cargo.toml`, while the hub takes dev-dependencies from `[workspace.dependencies]`. When another package needs proptest (for example the K4 §7 ticket tests), move it to `[workspace.dependencies]`.
- `Cargo.lock` gains `proptest` and its dependencies (dev-dependency of `guac-protocol` only). The workspace member line for `crates/guac-protocol` already exists (WP-01). Root `Cargo.toml` is not changed.

## Open questions (for the programme orchestrator)

- **Q-1 (K4 §3 step 2, CON-001).** K4 says the hub "answers with the same version". The crate answers `VERSION_1_5_0`, the newest version it implements, which is the same for guacd 1.5 and 1.6 (both send `VERSION_1_5_0`). For a later guacd version, answering that version would claim features the hub does not implement. Request: reword K4 to "answers with the highest version both sides support (`VERSION_1_5_0` in Phase 1)".
- **Q-2 (K4 §4).** K4 forwards a client `size` only when width and height are 1..8192 and DPI is 48..480, but guacamole-common-js sends `size` without a DPI. Request: reword to "DPI, when present, is 48..480".
