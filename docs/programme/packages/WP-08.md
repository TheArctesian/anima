## Protocol facts used (verified from the guacamole-server sources)

- Element: `LENGTH.VALUE`; elements are separated by `,` and the instruction ends with `;`. The first element is the opcode. `LENGTH` counts Unicode code points of `VALUE`, not bytes (the guacd parser counts UTF-8 characters).
- guacd parser limits (`src/libguac/guacamole/parser-constants.h`, 1.6.0): `GUAC_INSTRUCTION_MAX_LENGTH 8192` (bytes), `GUAC_INSTRUCTION_MAX_DIGITS 5`, `GUAC_INSTRUCTION_MAX_ELEMENTS 128`.
- guacd 1.5.5 and 1.6.0 both send `VERSION_1_5_0` as the first `args` value (`GUACAMOLE_PROTOCOL_VERSION`). Known versions: `VERSION_1_0_0`, `VERSION_1_1_0`, `VERSION_1_3_0`, `VERSION_1_5_0`.
- SSH `args` (from `GUAC_SSH_CLIENT_ARGS` in `src/protocols/ssh/settings.c`): 39 names in 1.5.5, 43 in 1.6.0 (1.6.0 adds `timeout`, `public-key`, `typescript-write-existing`, `recording-write-existing`). Recorded wire forms are the fixtures `tests/it/fixtures/guacd-1.5.5-ssh-args.guac` and `guacd-1.6.0-ssh-args.guac`.

## Decisions

- **D-1. Branches.** The package branch is this session's branch. Task branches are local `wp/08-guac-protocol/<task>`; nothing is pushed. Tasks are serial (T2 uses T1's types), so builders work in this worktree on the task branch; reviewers mutate in detached worktrees.
- **D-2. Limits.** The decoder enforces guacd's own limits, as public constants: `MAX_INSTRUCTION_BYTES = 8192` (whole encoded instruction, including lengths and separators), `MAX_ELEMENTS = 128` (opcode + args), `MAX_LENGTH_DIGITS = 5`. Reason: guacd rejects larger instructions, so the hub never needs to buffer more; a hostile client cannot make the hub buffer more than 8 KiB per tunnel direction.
- **D-3. Strict grammar.** Digits only before `.` (leading zeros allowed, as guacd accepts them), no whitespace, value must be valid UTF-8, element must be followed by `,` or `;`. An empty opcode is valid (the internal instruction `0.,36.<uuid>;`). Any violation is a `DecodeError`; after an error the `Decoder` stays failed (every later `feed` returns the same error) because the tunnel closes (GW-011, close 1002).
- **D-4. No secret in `Debug` or errors (LOG-007).** `connect` carries passwords and keys, so `Instruction`'s `Debug` prints the opcode and the argument count only. `DecodeError` and `HandshakeError` carry no instruction content (only positions, limits, opcodes and gateway status). `ArgValues` and `ConnectParams` do not implement `Debug` or `Display`.
- **D-5. Client values are typed (GW-012, GW-013).** The only client-supplied input to the handshake is `Display` (width, height, DPI) and the time zone string, the K1 `DisplayInput` fields. Every `connect` value comes from `ArgValues`, which the hub fills from the database and the credential store. There is no API that turns client name/value pairs into `connect` values, so a forbidden name cannot be set by the client. Property tests prove that no client input changes any `connect` value and cannot inject an extra instruction.
- **D-6. Version negotiation (K4 Section 3 step 2).** The first `args` value must be `VERSION_X_Y_Z` at or above `VERSION_1_5_0`, else `HandshakeError::UnsupportedVersion`. The hub answers with the version guacd sent when it is `VERSION_1_5_0` (guacd 1.5 and 1.6: the same version, as K4 says). For a later, parseable version the hub answers `VERSION_1_5_0`, the newest version this crate implements (the Guacamole rule: the client answers with the highest version both sides support). Raised as open question Q-1.
- **D-7. Handshake output.** `Handshake::new` returns `select`. On `args` it returns `HandshakeStep::Send` with, in order: `size` (width, height, DPI), `audio` (no args), `video` (no args), `image` (`image/png`, `image/jpeg`, `image/webp`), `timezone`, `name`, `connect` (version, then one value per `args` name in the same order; a name without a value in `ArgValues` gets `""`). On `ready` it returns `HandshakeStep::Ready { connection_id }` (GW-014: the caller keeps it). An `error` before `ready` is `HandshakeError::Gateway { status, message }`. `nop` is ignored. Any other opcode, a second `args`, or any instruction after `ready` or after a failure is an error.
- **D-8. Tests.** One integration test crate, `crates/guac-protocol/tests/it/main.rs` (AGENTS.md). `proptest` is a dev-dependency of this crate only. The fuzz-style test is a proptest over arbitrary bytes and over mutated valid encodings, fed in random chunk sizes, asserting no panic and that every result is `Ok` or `Err` (no nightly `cargo-fuzz`).

## Public interface (K3, extended only with the names K3 leaves open)

```rust
pub struct Instruction { pub opcode: String, pub args: Vec<String> }      // Clone, PartialEq, Eq; redacting Debug
impl Instruction { pub fn new(opcode, args) -> Self; }
pub fn encode(i: &Instruction) -> String;
pub const MAX_INSTRUCTION_BYTES: usize; pub const MAX_ELEMENTS: usize; pub const MAX_LENGTH_DIGITS: usize;
pub struct Decoder;  impl Decoder { pub fn new() -> Self; pub fn feed(&mut self, bytes: &[u8]) -> Result<Vec<Instruction>, DecodeError>; }
pub enum DecodeError { .. }                                                // thiserror, no content
pub struct Display { pub width: u32, pub height: u32, pub dpi: u32 }
pub struct ArgValues;  // set(name, value), FromIterator<(String, String)>; no Debug
pub struct ConnectParams { pub display: Display, pub timezone: String, pub name: String, pub values: ArgValues }
pub struct Handshake; impl Handshake { pub fn new(protocol: &str, params: ConnectParams) -> (Self, Instruction); pub fn on_instruction(&mut self, i: Instruction) -> Result<HandshakeStep, HandshakeError>; }
pub enum HandshakeStep { Send(Vec<Instruction>), Ready { connection_id: String } }
pub enum HandshakeError { .. }                                             // thiserror
```

### Test plan

- **T1.** Unit-level behaviour through the public API: known encodings (`4.size,4.1024,3.768,2.96;`, `0.,36.<uuid>;`, `4.ping,13.<ts>;`), multibyte values counted in code points (`2.é€` = 2 chars, 5 bytes; emoji). Property tests: round trip `decode(encode(i)) == i` for arbitrary Unicode opcodes and args within limits; the same encoded stream split at every byte boundary (and in random chunk sizes) gives the same instructions; several instructions in one feed. Rejection tests, each named for GW-011: non-digit length, too many digits, length longer than the value, length shorter than the value (missing `,`/`;`), invalid UTF-8, instruction over `MAX_INSTRUCTION_BYTES` (rejected before the terminator arrives), more than `MAX_ELEMENTS`, failed decoder stays failed. Fuzz-style: arbitrary bytes and byte-mutated valid streams never panic. `Debug` of a `connect` instruction does not contain its argument values.
- **T2.** Recorded `args` fixtures for guacd 1.5.5 and 1.6.0 decode with the T1 decoder and give a `connect` with one value per name, in order, the version first, K4 Section 3 values at the right positions and `""` for every name without a value. Order of the `Send` instructions and their exact encodings. Version: `VERSION_1_3_0` and a non-version first arg are refused; `VERSION_1_6_0` answers `VERSION_1_5_0`. `error` before `ready` → `Gateway`; unexpected opcode; instruction after `ready`. GW-013 property test: for arbitrary client `Display` and time zone (including strings shaped like `hostname`, `;`, `4.port,2.22;` and multibyte text) and arbitrary hub `ArgValues`, every `connect` value for `hostname`, `port`, `username`, `password`, `private-key`, `passphrase`, `public-key`, `recording-path`, `drive-path`, `sftp-root-directory`, `typescript-path` and `wol-*` equals the hub value (or `""`), and the encoded handshake output decodes back to exactly the same instructions (no injection).
