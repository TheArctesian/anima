## Decisions

- **D-1 Scope.** The brief narrows the plan row: GPU discovery and GPU metrics (MET-006–MET-009,
  MET-010) are not built. The K2 tables `gpus` and `discovery` and the K3 face `gpus` are built (one
  migration, no later change), so `gpus` returns what is stored: nothing yet. `GPU_*` and `VRAM_*` kinds
  exist in `MetricKind` and are never written. Open could C-1.
- **D-2 Sources.** A device is collected when `metrics_source = Ssh` and `os` is `Linux` or `Macos`.
  `Windows` and `Other` are skipped without a link (MET-005). SSH off, no host key, no credential and a
  refused target come back from `sessions::link` as `LinkError` and are reported, not retried in a loop.
- **D-3 Commands (MET-002, CHK-012).** One `FixedCommand` per source file or tool, all static text, all
  read-only: Linux `cat /proc/stat`, `cat /proc/meminfo`, `cat /proc/net/dev`, `cat /proc/uptime`,
  `cat /proc/loadavg`, `df -P -B1`; macOS `sysctl -n hw.memsize hw.pagesize vm.loadavg kern.boottime`,
  `vm_stat`, `df -P -k`, `netstat -ib -n`, and CPU from the last `CPU usage:` line of
  `top -l 2 -n 0 -s 1` (macOS has no tick counter command; the second sample is the busy share over one
  second). The T1 builder records the exact forms it parses. Each command has a time limit; the table
  is one pure function of the operating system, tested by its exact lines.
- **D-4 Rates.** CPU percent and network bytes per second come from two counter readings. The collector
  keeps the previous reading per device in memory; the first collection after start (or after a
  counter goes back, such as a reboot or an interface reset) writes no CPU or network sample. Pure, with
  the elapsed time as a parameter. Ruling (T1): macOS CPU comes from `top -l 2`, which measures over
  one second itself, so it is written on the first reading too; D-4 applies to Linux CPU and network.
- **D-5 Series.** One `series` row per (device, kind, label). Labels: disk = mount point, network =
  interface name, others = empty text. Loopback and pseudo file systems (`tmpfs`, `devtmpfs`, `overlay`,
  `squashfs`, `/dev`, `/run`, `/sys`, `/proc`, macOS `devfs`, `map`, `/System/Volumes/*` except
  `/System/Volumes/Data`) are left out. At most 32 disk and 32 network series per device, so a device
  cannot grow the table without bound.
- **D-6 Storage (D-12, DB-004, DB-008, DB-009).** One `samples` row per value, partitioned by day on
  `at`, 7 days created ahead; `minute`, `hour` and `day` (avg, min, max, count) upserted in the same
  transaction as the samples. Retention: drop sample partitions older than 30 days (DB-005), delete
  aggregate rows past 7 d / 90 d / 2 y, delete samples whose series is gone (DEV-015, as checks). The
  partition functions are `SECURITY DEFINER`, owner role, `search_path = pg_catalog, pg_temp`, as K2.
  Aggregates have a foreign key to `series` with cascade; `samples` has none (as heartbeats).
- **D-7 Ranges (MET-003).** `HOUR`: the minute table, 60 points. `DAY`: the minute table binned to 10
  minutes (144 points, count-weighted avg, min of min, max of max). `WEEK`: the hour table, 168 points.
  Each point carries `min` and `max`.
- **D-8 Readings.** The latest sample per series in the last 2 minutes (four collections); older means
  `readings` returns no entry for the device. Disk: the fullest mount. VRAM fields stay null (D-1).
- **D-9 Feed (D-15).** `Feed` wraps a `tokio::sync::broadcast` of `MetricsAdded`, capacity 256. The
  subscription filters by `deviceId`; a lagged receiver skips the lost items and goes on.
- **D-10 Events.** The collector records one event when a device's collection starts failing and one
  when it works again (not every 30 s), severity Warning and Info. `events::Source` has no `Metrics`
  variant yet, so it uses `Source::Device` (handoff H-1).
- **D-11 Concurrency.** One collection round every 30 s (MET-001), at most 8 devices at once, each
  device's whole collection within 20 s; a round that overruns skips the next tick rather than
  stacking. Links are opened per collection and dropped after it (no long-lived SSH state).
