## Decisions

- **D-1 Secrets (DB-002, SEC-004, DNS-003).** Every secret is a Compose file secret under `deploy/secrets/` on the host (git-ignored by `secrets/`). The compose file names only paths. `deploy/bin/make-secrets` (run once by the operator, as root, on the host) makes the missing files with random values and never prints them or overwrites a file. The Cloudflare token is the operator's: the script asks for it with no echo, or the operator makes the file.

  | Secret file | Value | Mounted in | Host owner, mode |
  | --- | --- | --- | --- |
  | `postgres_password` | superuser password (`openssl rand -hex 32`) | `postgres` | `root:999`, `0440` |
  | `owner_password` | `anima_owner` password | `postgres` (init only) | `root:999`, `0440` |
  | `hub_password` | `anima_hub` password | `postgres` (init only) | `root:999`, `0440` |
  | `owner_database_url` | `postgres://anima_owner:<owner_password>@postgres:5432/anima` | `migrate` only | `root:10001`, `0440` |
  | `hub_database_url` | `postgres://anima_hub:<hub_password>@postgres:5432/anima` | `hub` only, target `database_url` | `root:10001`, `0440` |
  | `anima_key` | 32 random bytes, base64 (WP-07 D-1) | `hub` only | `root:10001`, `0440` |
  | `cloudflare_dns_token` | Cloudflare API token, "Zone DNS Edit" on `anima.ing` only | `certs` only | `root:root`, `0400` |

  Compose ignores `uid`/`gid`/`mode` for file secrets outside Swarm, so the host file owner decides who can read it. `999` is the `postgres` user of the official image; `10001` is the hub image user (D-6). Hex passwords need no URL encoding.
- **D-2 Roles (R-016, K2, DB-003).** On the first start of an empty volume, `deploy/postgres/init/10-anima-roles.sh` runs `deploy/postgres/roles.sql` as the superuser. It makes `anima_runtime` (NOLOGIN, plain group, so migration 0001 accepts it), `anima_owner` (LOGIN; no SUPERUSER, CREATEDB, CREATEROLE or BYPASSRLS), `anima_hub` (LOGIN, member of `anima_runtime`, owns nothing) and the database `anima` owned by `anima_owner`. CONNECT and TEMPORARY are revoked from PUBLIC on `anima`, CONNECT from PUBLIC on `postgres` and `template1`; `anima_runtime` gets CONNECT on `anima`. Passwords are read with psql `\set name \`cat "$FILE"\`` (never in argv), and the session sets `log_min_error_statement = panic` and `log_statement = none`, so a failing statement does not put a password in the server log. K2's example gives the owner CREATEROLE, needed only when the owner makes `anima_runtime` itself; here the superuser makes it first, so the owner has no CREATEROLE (least privilege; reported to the programme orchestrator).
- **D-3 Networks (DB-001, GW-002, GW-003, NET-003).** `database`: `internal: true`; `postgres`, `migrate`, `hub`. `gateway`: bridge with a fixed subnet (default `172.30.0.0/24`, `ANIMA_HUB_SUBNET`); `hub` at a fixed address (default `172.30.0.10`, `ANIMA_HUB_IP`) and `guacd`; egress is needed because guacd and the checks reach devices. `acme`: bridge; `certs` only. The only published port is the hub's: `${ANIMA_HUB_ADDRESS:?}:443:8443`, where `ANIMA_HUB_ADDRESS` is the hub's VPN address, so nothing binds a public interface. `ANIMA_LISTEN` is `${ANIMA_HUB_IP}:8443`, a private address, which WP-05 D-13 accepts. PostgreSQL 5432 and guacd 4822 have no `ports`.
- **D-4 Start order (R-016).** `postgres` healthy (`pg_isready`) → `migrate` (`anima-hub migrate`, hub image, `owner_database_url` only, `restart: "no"`) `service_completed_successfully` → `certs` healthy (key and certificate present) → `hub` (runtime secrets only). `guacd` `service_started` before `hub`.
- **D-5 Certificate (DNS-002, DNS-003, SEC-001).** `certs` runs `goacme/lego` with `--dns cloudflare`, `CF_DNS_API_TOKEN_FILE=/run/secrets/cloudflare_dns_token`, `--domains hub.anima.ing`, e-mail from `ANIMA_ACME_EMAIL` (required). It gets the certificate if none exists, then runs `lego renew --days 30` every 12 hours. A hook (`deploy/certs/install.sh`) copies the chain and key atomically to `/certs/hub/fullchain.pem` and `/certs/hub/key.pem`, owner `10001`, key mode `0400`. The `certs` volume is read-only in `hub` (`ANIMA_TLS_CERT_FILE`, `ANIMA_TLS_KEY_FILE`). The hub reads the files at start only; until it reloads them (handoff H-2), a renewed certificate takes effect at the next hub restart (operator step).
- **D-6 Images.** Hub: `deploy/hub/Dockerfile`, multi-stage (`rust` builder, `debian:bookworm-slim` runtime with `ca-certificates`), user `10001:10001`, entrypoint `anima-hub`; build context is the repository root with `deploy/hub/Dockerfile.dockerignore` (allow-list). Gateway: `deploy/gateway/Dockerfile` from the official `guacamole/guacd` image (GW-001) that adds only `OpenDyslexicMNerdFontMono-Regular.otf` and its licence (RA-011), through a Compose `additional_contexts` entry that points at `apps/client/src/styles/fonts` (WP-02's file; read only). Images use a fixed version tag; digest pinning is deferred.
- **D-7 Logs.** Every service uses the `json-file` driver with `max-size: 10m`, `max-file: "10"` (spec Section 3.8). `ANIMA_LOG` defaults to `info`.
- **D-8 Backups (DB-007, VPS-006).** `deploy/backup/backup.sh` runs `pg_dump -Fc` as `anima_owner` inside the `postgres` container over its Unix socket (the image trusts local socket connections, so no password is passed), writes `anima-<UTC time>.dump.partial`, checks it with `pg_restore --list`, then renames it; mode `0600`; deletes dumps older than `ANIMA_BACKUP_KEEP_DAYS` (default 14). `deploy/backup/restore.sh <dump>` restores into a new database; `--check` restores into `anima_restore_check`, compares row counts and privileges, and drops it (a restore drill without downtime). The vault key and the Cloudflare token are not in the dump; the operator keeps a copy of `anima_key` offline (without it the stored credentials cannot be opened). Both scripts take `ANIMA_PG_LOCAL=1` to run local `pg_*` binaries with libpq variables instead of `docker compose exec`, which is how the tests run them.
- **D-9 Checks (CQ-024).** A `deploy` bun workspace (`@anima/deploy`) runs in `bun run lint`, `check` and `test`. Tests: compose rules from the parsed YAML (no `ports` on `postgres`/`guacd`, only the hub port and only on `ANIMA_HUB_ADDRESS`, secrets are files and each service has exactly its secrets, no password-like value inline, start order, internal database network, log rotation); `make-secrets` in a temporary folder (all files, modes, URL matches password, key is 32 bytes, a second run changes nothing, nothing printed); roles, backup and restore against the with-postgres server (R-009, R-019). `deploy/test/smoke.sh` (manual, needs Docker) runs `docker compose config`, builds the gateway image and checks the font, and starts `postgres` with the init script to check the roles; it is not a gate because the gates do not need Docker.

## Handoffs (PKG-001)

- **H-1 WP-05 `migrate`.** Compose runs `anima-hub migrate` with `ANIMA_DATABASE_URL_FILE=/run/secrets/owner_database_url`. The subcommand must read the URL from that variable (as the hub does) and exit 0 when all migrations are applied.
- **H-2 WP-05 TLS reload.** DNS-002 renews automatically; the hub must load a renewed certificate without a restart (for example check the file's modification time each hour). Until then, the operator restarts the hub after a renewal.
- **H-3 Health probe.** The hub image has no HTTP client and the health route needs a token (WP-05 carry-over), so the hub service has no healthcheck. A token-free liveness probe (for example `anima-hub health`) is deferred.
- **H-4 Root `package.json`.** One line, `"deploy"` in `workspaces`, and the matching `bun.lock` change.
