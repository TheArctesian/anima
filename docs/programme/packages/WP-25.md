## Decisions

- **D-1 Mock types.** `lib/forms/hub-pending.ts` holds the K1 `@pending` shapes the forms use, by hand,
  with the names codegen will give them. After WP-20 merges, the package rebases, regenerates, and swaps
  the imports to `$lib/hub/generated/graphql`; the file then goes. Tests use synthetic fixtures (CON-003).
- **D-2 Phase 1 hub compatibility.** The form sends a K1 addition only when it differs from the K1 default
  (create) or from the saved value (update). An untouched form sends the Phase 1 input, so it keeps working
  against a hub that does not declare the additions.
- **D-3 Optional device fields.** The devices client (WP-26, `lib/devices/api.ts`) does not query the K1
  fields yet. `DeviceFields` takes them as optional; a missing one reads as its K1 default. They become
  required when the fragment has them (handoff H-1).
- **D-4 Wiring outside the owned paths.** GraphQL documents live in `lib/<domain>/api.ts` (CQ-045) and the
  edit save is `routes/devices/[id]/save.ts`; neither is owned. The form gives pure input builders and
  callback props; the handoffs give the exact wiring. A callback the route does not give yet hides its
  control, and a typed secret that cannot be stored is reported, never dropped.
- **D-5 Web interfaces are edit-only.** They are separate hub objects with their own mutations, and
  suggestions come from saved HTTP checks (WEB-002). The settings panel shows a "Web interfaces" section
  with per-row save and delete; Add device does not show it.
- **D-6 Staged and immediate actions.** As in Phase 1: device fields are staged until Save; removing a
  stored credential, accepting a certificate and accepting or dismissing a suggestion act at once.
- **D-7 New check types.** The check form offers Docker container, SNMP, Tailscale ping and systemd service.
  A Phase 1 hub refuses them with its validation error, which the form already shows.

## T5 follow-up

- The K1 enums and inputs the forms use (`RdpSecurity`, `RdpResizeMethod`, `MetricsSource`, `Protocol`, `SnmpVersion`, the check types, the RDP, VNC, transfer, password, check config and connection test inputs, `CreateDeviceInput`, `UpdateDeviceInput`) now come from `$lib/hub/generated/graphql`. The `& Pending*Input` intersections and the cast in `config-input.ts` are gone.
- Check config read shapes are four unexecuted fragments in `lib/checks/api.ts` (`DockerCheckConfig`, `SystemdCheckConfig`, `SnmpCheckConfig`, `TailscalePingCheckConfig`). Codegen reads them; nothing sends them, because the hub declares no K1 type yet and a live selection would fail validation. `CheckConfigFields` is `DeviceCheck['config'] | ProbeConfig`; `withConfig` has explicit cases for the four typenames and no cast. A bare union member (no fields) leaves the defaults.
- Stays in `hub-pending.ts`: the device read shapes (`RdpSettings`, `VncSettings`, `TransferPolicy`, `ServerCertificate`, `PendingDeviceFields`, `PendingConnectionTestResult`, `WebInterface`, `WebInterfaceSuggestion`) and the types no document reaches (`AccessWarning`, `OpenIn`, `WebInterfaceInput`). They need fields in `lib/devices/api.ts` (H-1), which the hub cannot serve yet. None is in `generated/graphql.ts`.
- H-2 done in `routes/devices/[id]/save.ts`: RDP and VNC passwords are stored after the update through optional `setRdpCredential` and `setVncCredential`. An absent call or a failure gives a failed result (shared `storePassword`, also used by `add-device.ts`), so the form keeps the password. The detail has no RDP or VNC settings, so no `credentialStored` is updated for them.
- New handoff: when WP-29's hub declares the K1 check types, spread the four fragments into the `config` selection of `CheckFields`, then drop `ProbeConfig` from `CheckConfigFields` and the bare-member handling in `withProbeConfig`. When H-1 lands, move the rest of `hub-pending.ts` and delete it.
