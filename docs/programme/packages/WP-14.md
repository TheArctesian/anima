## Decisions

- **D-1 Folder (CQ-044).** Everything lives in `apps/client/src/lib/sessions/`: `api.ts` (`sessionsApi(hub)`), `tunnel/` (the only importer of `guacamole-common-js`), pure logic beside each component (`ending.ts`, `tabs.ts`, `display.ts`, `keys.ts`), and the components (tab strip, session view, Keys menu, connection steps, ended panel, host key modal).
- **D-2 Library (E-1).** `guacamole-common-js` is the client (K4 §2). It is imported only in `$lib/sessions/tunnel/` (ESLint rule, as for `motion`). It ships no types: a small hand-written `.d.ts` covers only what we call. The npm package is a third-party repackaging of the Apache source; E-1 asks the programme which source to use.
- **D-3 Tunnel URL and token (SEC-002, LOG-007).** `Guacamole.WebSocketTunnel(<hub address with https→wss, http→ws> + ticket.tunnelPath)` and `client.connect("token=" + token)`. The token is used once, passed straight to `connect`, never stored in state, logged, put in an error or shown. No other connect data is sent (GW-013).
- **D-4 End reason (RA-007, K4 §5).** A pure `ending(closeCode, lastGatewayError, opened)` maps the K4 §5 table to a provisional reason and the text the operator sees. Because a close code alone is ambiguous (1000 is `OPERATOR` or `REMOTE_CLOSED`; a refusal before the upgrade is a 1006 with no status), the client then calls `endSession(sessionId)`. It returns an ended session unchanged with the hub's recorded `endReason`, and that reason wins. A tunnel that never opened shows "Could not open the session" plus the recorded reason.
- **D-5 Reconnect (RA-007).** "Reconnect" calls `startSession` again for the same device with the current display size and opens a new tunnel in the same tab. A ticket is single use, so nothing is reused.
- **D-6 Host key changed (SEC-007, K4 §6).** A close with 4001, or a recorded `HOST_KEY_MISMATCH`, opens the warning modal (`--status-warning`). The modal names the device and says the key changed and why that matters. "Review new key" calls `testConnection({deviceId})` and shows the new SHA-256 fingerprint, with the old one when the hub gives it. "Accept new key" calls `acceptHostKey(deviceId, fingerprint)` with exactly the fingerprint shown, after a second, explicit confirmation. "Reconnect" appears only after an accept. "Close" is the default and keeps the old key.
- **D-7 Display and size (RA-003, MAT-008).** The display element fills the session pane. `DisplayInput` takes the pane size in CSS px times `devicePixelRatio`, the DPI as 96 × `devicePixelRatio` (48..480), and the IANA zone from `Intl.DateTimeFormat().resolvedOptions().timeZone`. A `ResizeObserver` sends `size` (debounced, clamped to 1..8192, K4 §4). The remote display is never animated, blurred or covered by a material (MAT-008). The tab-open motion animates the tab and the connection-steps panel, and the display appears only after `ready`.
- **D-8 Keyboard and mouse.** A `Guacamole.Keyboard` binds to the focused session pane only, never the document. It is detached when the tab is hidden or closed. Mouse and touch go through `Guacamole.Mouse` on the display element. guacd keeps the 5000-line scroll-back; the wheel scrolls it (RA-003).
- **D-9 Clipboard (RA-003).**
  - **Copy:** text the gateway sends as `clipboard` is written to the system clipboard with `navigator.clipboard.writeText`.
  - **Paste:** a `paste` event on the pane, or "Paste" in the Keys menu, sends the text as a `clipboard` stream. Only `text/plain` is sent.
  - Clipboard text is never logged or kept beyond the latest value.
- **D-10 Keys menu (RA-006).** A menu (Section 5.7.3 "Menu and popover") sends key combinations as press and release keysym sequences: Ctrl+C, Ctrl+D, Ctrl+Z, Ctrl+L, Esc, Tab, Ctrl+Alt+Delete, and Paste. A pure table in `keys.ts` holds the keysyms.
- **D-11 Tabs (RA-001, E-2).** A session store (`sessions.svelte.ts`) holds the open sessions and the active one. `openSession({ deviceId, deviceName, protocol, origin })` is the one entry point; WP-12's SSH button calls it. The tab strip shows one tab per session. Sessions stay alive while hidden, so going to Devices or Settings does not end them. Closing a tab calls `endSession`. Placing the strip and the active session pane in the root layout needs a small edit in a WP-11 file (E-2).
- **D-12 Motion.**
  - A tab grows from the button that opened it with `spring-snappy` (MOT-005, `origin` rect), using `$lib/motion` helpers. With reduced motion it fades.
  - Reordering (Section 5.7.4) follows the pointer with a fixed grab offset (MOT-030) using pointer capture. On release the spring takes the pointer velocity (MOT-031), and other tabs move with `spring-move`.
  - The connection steps (request, gateway, device, ready) change marks with no easing (Section 5.7.3).
- **D-13 Pop out (RA-002).** A window is the Tauri shell's work (WP-16). The store takes an optional `popOut(sessionId)` port. Dragging a tab out of the strip, or "Pop out" in the tab menu, calls it only when the port is present. On the web nothing is offered. The tunnel moving into a new window is WP-16's (H-2).
- **D-14 Ambient motion.** The terminal cursor blink is guacd's own rendering; the client adds no ambient motion. The "Live" mark on a tab, if any, calls `ambientMotionAllowed` (WP-11 H-7).

## Contract proposals and questions (sent to the programme orchestrator)

- **E-1 (dependency source).** The npm `guacamole-common-js` (1.5.0, latest) is published by a third party (`padarom`) from the Apache Guacamole source; Apache publishes no npm package. The two options:
  - (a) Pin `guacamole-common-js@1.5.0` exactly, with its lockfile integrity, and check once that it matches the Apache 1.5.0 `guacamole-common-js` source.
  - (b) Vendor the Apache 1.5.0 source (Apache 2.0) into `apps/client/src/lib/sessions/tunnel/vendor/`, listed in `quality/generated.txt`.

  Proposal: (a), because 1.5.0 matches guacd 1.5 and an exact pin plus a source check limits the supply-chain risk. Either way, `apps/client/package.json`, `bun.lock` and `eslint.config.js` (the import boundary rule) change as handoff edits.
- **E-2 (tab placement).** The session tab strip and the active session pane need a place in the root layout (`routes/+layout.svelte`, WP-11). The proposal is a few lines there:
  - `provideSessions()`;
  - `<SessionTabs/>` above the page area;
  - the active `<SessionView/>` over the page area while a session tab is selected, with the pages still mounted beneath.

  The nav's Devices and Settings items deselect the session tab, which stays alive. Alternatively, a route `routes/sessions/[id]`, but navigating would then unmount live sessions.
