## Decisions

- **D-1. Shared live state (contract proposal E-1).** Tickets, open tunnels and recent host-key observations live in memory. Both GraphQL (`startSession`, `endSession`, `testConnection`, `acceptHostKey`) and the tunnel route use them. K3's `start` and `tunnel_router` have no parameter for that state, and a global would break Predictable (CQ-021). `sessions::Live` (cheap `Clone`, `Arc` inside) is built once in `main.rs`, put in the schema data and passed to `tunnel_router`.
- **D-2. Tickets (K4 §1).** 32 bytes from `getrandom`, base64url without padding. The store maps `SHA-256(token)` to `{operator, session, client, device, display, expires_at}`; the token itself is never stored or logged. Redemption removes the entry first, then checks expiry (`now >= expires_at` refuses) and client address; every refusal is 403 with no body detail. Expired, unredeemed tickets are swept lazily on every `start` and every tunnel request; their session row ends with `TIMEOUT` (audit `session.end`).
- **D-3. Session rows (K2).** `sessions.sessions` adds `operator_name` (a copied name, like the logs; K1 `Session.operatorName`) and an `end_reason` check from K1 `SessionEndReason`. `device_id` has no foreign key, so history survives device deletion; `device_name` is a copy. `live` means `ended_at is null`. At start, rows a crashed hub left open end with `HUB_SHUTDOWN` (`sessions::close_stale`, wiring only, E-4).
- **D-4. Host keys (SEC-006, SEC-007).** `sessions.host_keys` adds `public_key` (the OpenSSH key blob, base64) and `accepted_at`; `first_seen_at` is when the hub first saw the accepted key. Fingerprint text is OpenSSH's `SHA256:<base64 without padding>` of the key blob. guacd's `host-key` argument is one known_hosts line from the record: `<host> <algorithm> <base64>` for port 22, `[<host>]:<port> …` otherwise (libssh2 `knownhost_checkp`; builder verifies against the guacd source).
- **D-5. Connection test (DEV-013, K4 §6).** `testConnection` opens an SSH connection with `russh` (E-3), 10 s timeout, and reads the server's host key. It keeps the observation in `Live` keyed by `(host, port)` for 15 minutes, so test, save and `acceptHostKey` works for a new device. `hostKey` is set when no key is accepted or the key differs; `hostKeyChanged` when it differs from the accepted one. **A credential is sent only to the accepted key**, never to a first-seen or changed key, so a man in the middle never gets a password. Otherwise `authenticated` is false and `message` says to accept the key first. `ConnectionTestInput` has a hand-written `InputType::parse` that never quotes the input and uses `devices::graphql::SshCredential` (WP-06 H-4).
- **D-6. `acceptHostKey`.** Loads the device's host and port, finds the observation for them and compares the fingerprint; a missing or different one gives `CONFLICT`. Upserts `host_keys` and writes audit `accept` on `HostKey(device)` in one transaction. Replacing a key records the old and new fingerprints in `change`.
- **D-7. Handshake and relay (K4 §3–4, WP-08 H-3–H-9).** Before the upgrade: redeem the ticket, check the subprotocol, connect to guacd and complete the handshake (10 s); a guacd failure is 503 and the session ends `GATEWAY_ERROR`. Connect values come only from `devices::get`, `credentials::load_ssh`, `sessions.host_keys` and constants; `color-scheme` is `anima_theme::guac_color_scheme()`. Time zone: `DisplayInput.timezone` if `guac_protocol::is_zone_name`, else `UTC` (E-6). WebSocket message and frame size are capped at 64 KiB (H-3). The rest of the feed after `ready` goes to the relay (H-5). Client `size` parsing accepts digits only (H-6). Relay rules are pure functions (`Instruction` in, decision out); the tunnel task only does I/O.
- **D-8. Client instructions (GW-012, GW-013, GW-015).** The relay forwards only an allow-list of client opcodes (`key`, `mouse`, `touch`, `size`, `clipboard`, `blob`, `end`, `ack`, `sync`, `nop`, `disconnect`, `argv`). `argv` is forwarded only for a name guacd asked for in `required` (GW-015) or `color-scheme` (GW-012); its stream index is then allowed for `blob` and `end`. Any other client instruction closes the tunnel with 1002. The hub never stores a prompted value (GW-015).
- **D-9. End causes (K4 §5).** One pure table maps a cause to `(close code, EndReason, Severity)`. guacd reports a host-key mismatch as an `error` with libguac's fixed host-key text (builder takes the exact strings from tags 1.5.5 and 1.6.0). That error is not relayed: the hub sends `error "Host key changed" 0x0303`, closes 4001, ends `HOST_KEY_MISMATCH` and records an **Error** event (K4 §6; §5 says Warning, E-5). 0x0301/0x0303 give `AUTH_FAILED`; other statuses give `GATEWAY_ERROR`. Gateway `disconnect` or EOF gives `REMOTE_CLOSED`. Client idle 15 s gives 4002 `TIMEOUT`; the hub sends `nop` after 5 s of gateway silence. Every end sets `ended_at` and `end_reason`, records the event (`Source::Session`, device name copied) and writes audit `end` on `Session(id)`, exactly once (the first cause wins).
- **D-10. `endSession` and shutdown.** `endSession(id)` signals the live tunnel (close 1000, `OPERATOR`) and waits for the row to end, or ends a pending ticket's row directly; an ended session returns unchanged. `Live::shut_down()` ends every tunnel with 1001 `HUB_SHUTDOWN` (wiring handoff for graceful shutdown).
- **D-11. Never logged or sent (LOG-007, GW-014, RA-008).** No tunnel token, `HandshakeStep::Send` argument, connect value, gateway connection ID, guacd error text or session content reaches a log, an event, an audit `change`, a GraphQL error or the client. Only `Instruction`'s redacting `Debug` may be logged.
- **D-12. Lock order (WP-06 H-4).** Sessions only reads credentials and never locks a device row.

## Contract proposals and questions (sent to the programme orchestrator)

- **E-1.** `sessions::Live` shared state: `start(db, clock, live, op, client, req)`, `tunnel_router(db, vault, bus, clock, guacd, live)`; `main.rs` builds one and adds `.data(live.clone())`.
- **E-2.** `sessions::host_keys(db, &[DeviceId]) -> Result<HashMap<DeviceId, HostKey>, Error>`, one query, for the `SshSettings.hostKey` loader (API-005, like R-017). `host_key` stays.
- **E-3.** Manifest handoff lines (like R-028 E-6): the hub depends on `guac-protocol` and `anima-theme` (path), axum `ws`, tokio `time` and `io-util`, `russh` 0.65 (client; server in tests), `futures-util`; dev: `tokio-tungstenite`.
- **E-4.** Wiring only: `sessions::close_stale(db, now)` at start; `Live::shut_down()` on graceful shutdown; `/tunnel` mounted behind `access::permitted_networks_layer` (WP-05 T4) in `main.rs`/`lib.rs`.
- **E-5.** K4 §5 says Warning for `HOST_KEY_MISMATCH`, §6 says Error. Proposal: Error.
- **E-6.** K4 §3 time zone "else the device site's zone": sites have no zone in K1 or K2. Proposal: `DisplayInput.timezone` when valid, else `UTC`, until sites get a zone.
- **E-7 (note).** `testConnection` reaches any operator-entered host; the checks address policy (R-030) is not available to `sessions` (K3 edges). Phase 1 accepts it (operator-only API); recorded as a risk.

### Test plan

Every test that proves a requirement names its ID (K7). Database tests use `#[sqlx::test(migrations = "migrations")]`, the K6 fixtures, and `DATABASE_URL` unset (R-019 d).

- T1: migration columns and checks; `end_reason` refuses unknown text; host key cascades on device delete; a session row survives device delete; `sessions` paging is stable; `live` and `deviceId` filters; guard on the root field; `host_keys` is one query for many devices; `close_stale` ends only open rows.
- T2: property tests on `FixedClock`: expired (boundary `now == expires_at`), reused and wrong client address are refused; a refused redemption still removes the ticket; the token is never stored, logged or in an error; `startSession` refuses a missing device, SSH disabled, no accepted host key (`CONFLICT`) and a display out of bounds (`VALIDATION`); audit `session.start` with operator and client; `endSession` on a pending ticket ends the row `OPERATOR`; the sweep ends expired rows `TIMEOUT`.
- T3: with an in-process `russh` server: first seen gives `hostKey`, `authenticated` false, and the server receives no credential; an accepted key authenticates with a password and with a private key; a changed key gives `hostKeyChanged` and no credential is sent; `acceptHostKey` with a wrong or unseen fingerprint gives `CONFLICT`; accept writes audit; a parse error never echoes the credential; the `hostKey` loader batches.
- T4: both WP-08 `args` fixtures give the K4 §3 values from a device and secret; no client value reaches `connect`; size bounds with and without DPI, `+` and leading zeros; ping echoed and not forwarded; unknown opcode and `argv` for `hostname` give close 1002; `required` then `argv` is allowed; every row of the end table, including the guacd 1.5.5/1.6.0 host-key texts.
- T5: a fake guacd (TCP listener) and a `tokio-tungstenite` client run full sessions: the open instruction comes first and is not the connection ID; each K4 §5 cause gives its close code, row, event and audit; the 403 cases, 400 without the subprotocol, 503 when guacd is down; idle timeout and `nop` with short test intervals; an interrupted session (client drops mid-stream, guacd drops mid-handshake) ends once (MV-003); an oversize message is refused.
