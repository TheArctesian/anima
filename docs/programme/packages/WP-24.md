5. The SSH terminal (WP-18) keeps working, with its tests green.

## Decisions

- **D-1 Mock of the pending K1 parts (CON-003).** Codegen reads only `src/lib/*/api.ts` against
  `contracts/schema.graphql`, which is still the Phase 1 freeze. The K1 additions this package uses are typed by
  hand in one file, `sessions/pending.ts` (documents built with `parse`, result and variable types from the K1
  delta), and the widened `Protocol` and `SessionEndReason` unions live there too. Tests use a fake `Hub` that
  answers these operations as K1 and K4 describe. After WP-20 merges: rebase, move the documents into `api.ts`
  under `graphql()`, regenerate, delete `pending.ts`.
- **D-2 The root layout does not change.** `routes/+layout.svelte` calls `sessionStart(api, deviceId, origin)`
  and mounts `SessionPanes {api}`; both keep their call shape, and `sessionStart` returns the starts for every
  protocol. The device pages pass `protocol: 'RDP' | 'VNC'` to `openSession` (handoff to WP-26 / WP-33).
- **D-3 The transfer policy is read at each start and fails closed.** Each start reads the device's `transfer`
  (copy, paste) with the ticket. When it cannot be read, copy and paste are off for that session and a notice
  says why. Until WP-21 serves `transfer`, SSH sessions on `phase-2` therefore have copy and paste off (risk R-1).
- **D-4 "Save" stores the password only.** GW-015: the prompt sends every asked value to the gateway for this
  session. With "Save password" checked, the client calls `setRdpCredential` or `setVncCredential` with the
  password; username and domain are device settings (the device form, WP-25). Values are held only until sent.
- **D-5 Display size.** RDP sends the pane size after 150 ms of no change (RA-004, the existing `sizeSender`).
  VNC cannot change the remote size, so its display is scaled to fit the pane. Scaling is layout, not motion
  (MAT-008): the display is never animated, transformed by a transition, filtered or covered by a material.
- **D-6 Not in this package.** Microphone input, the shared drive (`file`, `get`, `put`, `filesystem`) and
  recording have no spec ID here. The client never opens audio input and ignores `filesystem`; audio output
  plays through the library's default players. Issue #1 entries.
- **D-7 Certificate change.** Close 4003 or a recorded `SERVER_CERTIFICATE_MISMATCH` opens a modal like the
  host key one: it reads the new certificate with `testConnection(protocol: RDP)`, shows its SHA-256, and
  "Accept" calls `acceptServerCertificate` with exactly that fingerprint, then reconnects. A `CONFLICT` from
  `startSession` for RDP (no accepted certificate) shows fixed text that points to the connection test.
