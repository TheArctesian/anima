# WP-19 — Checks that repair their method (CHK-013, R-064)

Package branch: `claude/wp-19-check-repair` from `phase-1`. Task branches: `wp/19-check-repair/<task>`.

Spec: CHK-001–013 (CHK-013 new), R-032 (target rule), R-063, LOG-005 (audit), LOG-007, Sections 12
and 13. Contracts: K1 unchanged unless the review shows a need (prefer none: the check's new
config is visible through the existing `Check` type; the event uses the existing events domain).

## Rule (R-064)

A check is a repair candidate when all hold: type ICMP; status Down; it has never had an Up
heartbeat; its failures reached its retries (CHK-002); the operator never edited it (its config
and type are as created; record this explicitly, do not infer it from timestamps another write
can move); not paused; device not in maintenance.

For a candidate, once, the hub tries a TCP connect (5 s) to each of the device's connection
ports that are enabled, SSH first (RDP and VNC later when they exist), under the R-032 target
rule, as the checks probes already do.

- One answers: in one transaction, change the check to `tcp` on that port (name "SSH port"
  for 22 or "<Service> port"), reset status and failures, keep interval and retries; write an
  Info event "Ping never answered on <device>; <service> port <n> does, so its check now uses
  TCP <n>." and an audit entry (old and new config). The scheduler runs it at once.
- None answers: change nothing; write one Warning event "Ping never answered on <device>, and
  no connection port answers either." and do not try again for that check until it is edited
  or recreated.

Never change a check that was ever Up, or that the operator edited, or any non-ICMP check.

## Where

`crates/hub/src/checks/`: a pure decision (`repair.rs` or a name from the domain) that takes the
check, its history facts and the device's ports and returns the action; the I/O (probe, store,
events, audit) at the edge in the scheduler path. The device's ports come through the devices
domain's public face, never its store.

## Acceptance

- Gates 12/12. Tests: each rule condition (ever Up, edited, paused, maintenance, not ICMP,
  retries not reached) blocks the repair; a fake TCP listener makes the repair happen with
  the event and audit entry; no listener gives the single Warning and no retry loop.
- reviewer (correctness, CUPID) and reviewer-security (the probe follows R-032; no new reach).
- After deploy, the operator's Mac device (ICMP, Down since creation, SSH 22) turns Up by itself.

## Decisions (package orchestrator)

- **D-1 "Edited" is a stored flag.** Migration `0302_checks_method_repair.sql` adds
  `checks.checks.operator_edited boolean not null default false`. The `updateCheck` mutation's
  store write (`store::writes::update`) sets it true on every operator update, whatever field
  changed (a superset of "config and type as created", so fewer checks are ever repaired).
  Pause, resume and regrouping by the group's update do not set it. Existing rows: the default
  makes them not edited; the migration then marks as edited every check with an `update` entry
  in `events.audit_log` (target type `check`), which is the real record of operator edits. The
  backfill runs only when `events.audit_log` exists, because on a fresh database 0302 runs
  before 0500 and there are no checks yet.
- **D-2 "Tried once" is a stored timestamp.** The same migration adds
  `repair_tried_at timestamptz null`. A repair that wrote its outcome (changed the check, or
  wrote the Warning) sets it, so the hub never tries the same check again. An edit makes the
  check non-candidate for good (D-1); a recreated check is a new row with null.
- **D-3 "Ever Up" comes from history, not a new column.** A check has answered when any
  heartbeat or any uptime bucket (minute, hour, day; kept 7 days, 90 days, 2 years) has an Up
  or Degraded result, or its stored status is Up or Degraded. Degraded counts as answered: the
  device replied, so the method works and a slow reply is a real fault, never repaired.
- **D-4 The hub as the audit actor.** The audit entry of a repair names operator id
  `00000000-0000-0000-0000-000000000000`, operator name `Anima`, client `127.0.0.1` (the hub
  itself), action `update`, target `check`, change `{ "repairedBy": "hub", "before": {type,
  config, name}, "after": {type, config, name} }` (LOG-005: who, what, when, where; no secret,
  LOG-007). No schema change: `audit_log.operator_id` has no foreign key.
- **D-5 Name.** The repaired check is named "SSH port" (port 22) or "SSH port <n>"; when that
  name is taken on the device, "<that name> (was <old name>)" cut to 200 characters.
- **D-6 Where.** `checks/` already holds 12 measured files (the folder limit), and
  `scheduler/tests/` holds 12, so the code goes in `checks/scheduler/repair.rs` (the I/O edge,
  called from `attempt::run` after a Down beat of an ICMP check) with
  `checks/scheduler/repair/rule.rs` (the pure decision) and `repair/tests.rs`; the SQL goes in
  `checks/store/repairs.rs`. The ports come from `devices::get` (public face): today only SSH
  (`ssh.enabled`, `ssh.port`); RDP and VNC slot into the same list when they exist.
- **D-7 Probe.** The TCP connect is the existing `probe::probe` with
  `CheckConfig::Tcp { port, timeout_ms: 5000 }`, the device host and the scheduler's
  `AddressPolicy` (R-032 target rule: resolve once, keep allowed addresses, connect to one of
  those). No new reach.
- **D-8 Write.** Under `SELECT … FOR UPDATE` the hub re-checks every stored condition (type
  icmp, config unchanged, not edited, not tried, not paused, status down) before it writes, so a
  concurrent operator edit wins. Change: type `tcp`, config `{port, timeoutMs: 5000}`, the name,
  status `unknown`, failures 0, `next_due_at = now` (due at once, not spread), interval and
  retries kept, `repair_tried_at = now`; Info event, audit entry, one transaction. None
  answers: `repair_tried_at = now` and one Warning event, one transaction.

## Test plan

- Rule (pure): repair only when all conditions hold; each of ever answered, edited, tried,
  paused, maintenance, not ICMP, status not Down, retries not reached, no port blocks it; SSH
  disabled gives "no port"; port order SSH first.
- Edge (database + fake listener on loopback with `allowing_loopback`): listener answers →
  check is TCP on that port, Unknown, failures 0, due now, interval and retries kept, one Info
  event with the R-064 text, one audit entry with before and after; no listener → nothing
  changed, one Warning event, and a second Down beat neither probes nor writes again.
- An edit between the decision and the write wins (the locked re-check refuses).
- Migration: default false; backfill marks a check with an `update` audit entry.
