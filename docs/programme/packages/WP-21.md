## Decisions

- **D-1 Who declares what.** WP-21 declares the K1 devices members whose data lives in `devices` or
  `credentials`: enums `RdpSecurity`, `RdpResizeMethod`, `MetricsSource`, `AccessWarning`; types `RdpSettings`
  (without `serverCertificate`), `VncSettings`, `TransferPolicy`; `Device.rdp`, `vnc`, `macAddress`,
  `metricsSource`, `transfer`, `accessWarnings`; `Site.wakeRelay`; inputs `RdpSettingsInput`,
  `VncSettingsInput`, `TransferPolicyInput`, `PasswordCredentialInput` and their fields in
  `CreateDeviceInput` and `UpdateDeviceInput`; mutations `setSiteWakeRelay`, `setRdpCredential`,
  `clearRdpCredential`, `setVncCredential`, `clearVncCredential`. WP-22 declares what lives in
  `sessions.server_certificates` or the connection test: `ServerCertificate`, `RdpSettings.serverCertificate`
  (an R-011 composition edit in `devices/graphql/`, as WP-10 added `SshSettings.hostKey`),
  `acceptServerCertificate`, the `ConnectionTestInput`/`ConnectionTestResult` additions, `Protocol.RDP/VNC`.
- **D-2 Clearing (WP-25 assumption 1).** `rdp`, `vnc` and `transfer` in `UpdateDeviceInput` replace the whole
  settings object when present and leave it unchanged when absent or null, as `ssh` does. Inside a present
  object, a null or empty (after trim) `domain` or VNC `username` clears it; an absent field with a K1 default
  takes that default. `macAddress`: absent or null leaves it unchanged, `""` clears it, any other text must
  parse. On create, absent, null or `""` means no address.
- **D-3 New certificate (WP-25 assumption 2).** `ConnectionTestResult.serverCertificate` follows the
  `hostKey` rule already in K1 and in `sessions/trust/connection_test.rs`: present only when no certificate
  is accepted (`certificateChanged: false`, "new") or the server presented a different one
  (`certificateChanged: true`); null when it equals the accepted one. The client's reading ("new unless equal
  to the accepted one or `certificateChanged`") gives the same answer. Handoff H-1 to WP-22.
- **D-4 Defaults in the schema (DB-011).** `rdp_settings` and `vnc_settings` hold every K1 default as a column
  default; a create without `rdp`/`vnc` inserts `DEFAULT VALUES` rows. The Rust `Default` impls equal them and a
  test compares them with the database.
- **D-5 Access warnings (RA-020).** Pure, from the saved settings, in enum order: `IGNORED_CERTIFICATE` when RDP
  is on and `ignoreCertificate`; `RDP_SECURITY` when RDP is on and `security = RDP`; `UNENCRYPTED_VNC` when VNC
  is on (Phase 2 VNC has no TLS option). A protocol that is off earns no warning.
- **D-6 MAC address (RA-031).** Six hex pairs split by `:` or `-`, any case; stored as `macaddr`, read back as
  text, rendered `aa:bb:cc:dd:ee:ff`. All-zero and group (multicast or broadcast) addresses are refused: a
  Wake-on-LAN target is one unicast card. Field path `macAddress`.
- **D-7 Wake relay (D-2 of the plan).** `setSiteWakeRelay(siteId, deviceId)` needs a device at that site with
  SSH on (the relay runs one fixed command over the SSH link); `deviceId: null` clears. Moving a relay device
  to another site, or turning its SSH off, clears its relay role in the same transaction (final review). Audited
  (LOG-005); the automatic clear has no audit entry of its own, only the device update's (a could).
- **D-8 Credentials share one table and one lock.** RDP and VNC passwords are rows of `credentials.secrets`
  with kinds `rdp_password`, `vnc_password`, context `credentials.secrets:<device_id>:<kind>` (R-010), and
  the same per-device advisory lock as SSH, so the R-026 lock order holds for every kind. Every SSH query is
  scoped to the SSH kinds, so an RDP password never counts as, opens as, or is deleted with an SSH secret.
  Device deletion removes password rows through the foreign-key cascade after `clear_ssh` took the lock.
- **D-9 Field paths.** `rdp.port`, `rdp.username`, `rdp.domain`, `vnc.port`, `vnc.username`, `macAddress`,
  `credential.password` (the SSH password path, reused). RDP `username` is required when RDP is on.
- **D-10 Other domains' test literals.** Adding fields to `devices::Device` breaks two `Device { .. }` literals
  in other domains' tests (`checks/scheduler/repair/tests/rule.rs`, `sessions/tunnel/tests.rs`). T1 adds the
  new fields there with their `Default` values only; recorded as handoff edits H-3, reviewed at merge.
- **D-11 Interim merge for WP-22.** T1 (devices face) and T2 (credential kinds) run at once; when both are
  accepted the package head is reported to the programme orchestrator for an early merge (R-027).
