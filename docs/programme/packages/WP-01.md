## Decisions

- **D-1. Quality tools language.** The quality checks are TypeScript modules in `quality/`, run with `bun`, and tested with `bun test`. Reason: no new heavy dependency, and bun is already the workspace tool (R-001). Rust domain sources are read as text; the import-graph check needs only `use crate::...` paths.
- **D-2. Limits split.** Clippy and ESLint measure what they already measure. The `quality` limits check measures what they do not.

  | Limit | Rust | TypeScript and Svelte |
  | --- | --- | --- |
  | File code lines 300 | `quality` limits check | `quality` limits check |
  | Function lines 60 | Clippy `too_many_lines` (threshold 60) | ESLint `max-lines-per-function` |
  | Params 4 | Clippy `too_many_arguments` (threshold 4) | ESLint `max-params` |
  | Complexity 15 | Clippy `cognitive_complexity` (threshold 15) | ESLint `complexity` |
  | Nesting 4 | Clippy `excessive_nesting` (threshold 4) | ESLint `max-depth` |
  | Files per folder 12 | `quality` limits check | `quality` limits check |

- **D-3. Baseline.** `quality/baseline.json` maps a file path to the signals it exceeds and the measured value. The limits check passes a file over a limit only when the baseline holds an entry with a value equal or higher. The baseline check compares `quality/baseline.json` with the version on the base ref (`phase-1` by default): no new entry and no larger value.
- **D-4. No `rust-toolchain.toml`.** Rust comes from Homebrew (1.99) on the build host; CI uses `dtolnay/rust-toolchain@stable`. A pinned toolchain file would make the local gates need rustup. Revisit when the toolchain must be pinned.
- **D-5. Package branch.** Task branches are local `wp/01-skeleton/<task>` branches in separate worktrees, merged into the package branch after acceptance. Nothing is pushed.

- **D-6. Hub `lib.rs`.** The hub has `src/lib.rs` (router and module tree) and a thin `src/main.rs`. Reason: the integration test crate (`tests/it`, CQ-042) cannot import a binary. `lib.rs` is wiring like `main.rs` and `schema.rs` (REPO-002); WP-01 owns it, and domain packages ask for their `mod` line through a handoff note (PKG-001).
- **D-7. Nesting threshold.** Clippy counts the function body as nesting level 1, so `excessive-nesting-threshold = 5` means "at most 4 nested blocks inside a function body" (the limit). Verified by the builder and independently by the T1 reviewer.
- **D-8. SvelteKit 2.** The client uses SvelteKit 2.x with `svelte.config.js`. SvelteKit 3 is the current stable major but rejects `svelte.config.js` (configuration moves into the Vite plugin). Kept 2.x because the package brief and the later client packages assume `svelte.config.js`. Raised to the programme orchestrator as a decision.
- **D-9. `Status::worst` order.** Most severe first: `Down` > `Degraded` > `Unknown` > `Maintenance` > `Up`. Reason: CHK-004 (worst of the checks); a check in maintenance hides only its own Down (CHK-006), so a Down check elsewhere still wins; `Unknown` (no data) is worse than a deliberate maintenance. Raised for confirmation.
- **D-10. Config defaults.** `ANIMA_PERMITTED_NETWORKS` unset → the Tailscale/Headscale address range `100.64.0.0/10` only (K7 says "VPN range + site subnets"; site subnets are not known to the hub at start). TLS files are optional in `Config`; the package that serves TLS (WP-05) enforces them.

### Test plan (mutation evidence)

Each check has one test that fails on a bad input:

- File lines, files per folder, baseline, banned names, import graph: `bun test` in `quality/` with fixture trees.
- Clippy limits: a `quality` test builds a throwaway crate in a temp dir with the root `[workspace.lints]` and `CLIPPY_CONF_DIR` set to the repo root, and expects Clippy to reject a 61-line function, 5 parameters and nesting depth 5 (T4, after T1 is merged).
- ESLint limits and Stylelint raw values: `bun test` / Vitest cases in `apps/client` that lint a bad source string and expect errors.
