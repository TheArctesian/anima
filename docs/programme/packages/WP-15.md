# WP-15 Client Settings page (package plan)

Package orchestrator plan. Branch `claude/wp-15-settings`, from `phase-1` `cd91aae` (WP-16 merged; later `phase-1` `b264fe6` merged in), worked in the reused WP-11/WP-16 worktree (R-027). Task branches are `wp/15-settings/<task>`.

Spec: SET-001–002, UPD-006 (the slot only), CLI-002, CLI-003, API-003, NET-005, OD-2, Sections 5.5, 12 and 13.

Handoffs that apply:

- WP-11: H-3 (`useHub()` with a `<domain>Api(hub)` client), H-5 (an unreadable token is a typed `UNAUTHENTICATED`; the "sign in needed" surface belongs with sign-in) and H-7 (reserve heading height).
- WP-16: H-1 (`writeAccessToken(hub.address, …)`, `clearAccessToken(hub.address)`, `storeHubAddress`; an address change takes effect on reload; a provider uses its `address` argument).
- R-043: WP-15 builds no store of its own.

## Decisions

- **D-1 Settings page content (SET-001, SET-002).** In Phase 1, `routes/settings/+page.svelte` shows only the page title "Settings". In the desktop app it also has a place for the "Updates" row. WP-04 stage B fills that place (R-006: "the Updates row in WP-15's Settings page"), so WP-15 adds no Updates code. The nav bar already links to Settings (WP-11, NAV-001). WP-15 adds a test that the link reaches the page, which is SET-001.
- **D-2 Heading height (WP-11 H-7, R-042).** The title uses the type tokens and reserves its line height, so it does not move when the font loads.
- **D-3 Sign-in (P-1 accepted as R-048, with `lib/access/` in place of `lib/session/`; sign-out option (a)).** WP-15 owns `apps/client/src/routes/sign-in/` and `apps/client/src/lib/access/`.
  - `lib/access/api.ts`: `accessApi(hub)` with `login`, `logout` and `me`, following WP-11 H-3.
  - Pure form rules and outcome mapping live beside the components.
  - The sign-in page has three fields: user name, password (hidden, DEV-011) and TOTP code (OD-2; `login` takes `totpCode`, WP-05 T6).
  - When login succeeds, the page calls `writeAccessToken(hub.address, token)`, then goes to `/devices`.
  - The hub address field shows the current address. Saving calls `storeHubAddress(localStorage, text)`, then reloads (WP-16 H-1). An address `parseHubAddress` refuses shows its error and is not stored.
  - The password and TOTP code fields are emptied on every submit. The token is never in component state. Neither goes into logs or error text (LOG-007).
  - Outside the desktop app, sign-in is refused before anything is sent (no key store to keep the token).
- **D-4 Sign in needed (WP-11 H-5).** `lib/access` exports two things:
  - a start guard: the root layout calls it in one added line, and it goes to `/sign-in` when no token is stored and the path is not `/sign-in`;
  - `signInNeeded(error)`: pages call it on an `UNAUTHENTICATED` result, and it goes to `/sign-in`.

  Settings uses `signInNeeded` for its `me` query. WP-12 and WP-13 pages get it as a handoff. Outside the desktop app (no key store), the guard does nothing; the browser has no token provider (WP-16 deferred C2).
- **D-5 Sign-out (SET-002 as amended by R-048).** The Settings page adds a "Signed in as <name>" row, with the name from `me.username`, and a "Sign out" button. Sign-out calls `logout`, then `clearAccessToken(hub.address)`, then goes to `/sign-in`. The token is cleared even if `logout` fails, because an unreachable hub must not keep the operator signed in on this machine.

## Proposal P-1 (to the programme)

Accepted as R-048 (see D-3 to D-5).

## Handoffs

- **H-1 WP-12, WP-13 (pages):** on a failed hub result, call `signInNeeded(error, goToSignIn)` (`$lib/access/guard`, `$lib/access/navigation`); it returns true when it navigated, and then the page shows no error.
- **H-2 WP-04 stage B:** mount the desktop Updates row at the marked comment in `routes/settings/+page.svelte`, after `<SignOutRow />`; use `keyStoreAvailable()` from `$lib/desktop/token` for the desktop check.
- **H-3 WP-16 owners (`lib/desktop`):** `keyStoreAvailable()` (wraps `isTauri()`) was added for the guard and sign-in. Sign-in relies on `AccessTokenError` `not-desktop` and on `TOKEN_UNREADABLE` from `$lib/hub/error` compared by identity; keep both stable.
