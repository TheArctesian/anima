## Decisions

- **D-1 Test on port 5900, not the stored port.** R-079 names port 5900. The flow calls `testConnection` with
  `{ host, protocol: VNC, vnc: { enabled: true, port: 5900 } }` (the unsaved subject in
  `sessions/trust/desktop_test.rs`), so a stale stored VNC port cannot make the test lie. The hub sends no
  credential in a VNC test.
- **D-2 Client only.** Every piece exists: the test, the update, the session start, the credential prompt, the
  this-computer read and the Sharing pane command. The card list query gains `os`, which the schema already
  serves; that is a client document change only.
- **D-3 Rename the shell command (T2).** `remote_login_settings_open` now opens Sharing for Screen Sharing too,
  so the name lies (Section 12, Predictable). T2 renames it `sharing_settings_open` with its permission, the
  client wrapper and their callers. It is a Rust change, so it runs all 12 gates. R-059's wording is updated by
  the programme orchestrator from the report.
- **D-4 Review cap (R-066).** Two review rounds per task; only must findings block.
- **D-5 Security reviewer.** T1 neither stores nor sends a credential (it sends a username only when the device
  is this computer, and the username is not a secret), so reviewer-security is not added; the reviewer checks
  that claim. T2 changes no behaviour.

### T1 test plan

Behaviour tests (vitest, jsdom), with a fake clock and fake hub calls:

- The action shows for macOS and Linux devices with VNC off, and not for Windows, Other, or VNC on (header and card).
- A device that answers: VNC is turned on with port 5900 and no password; the username is this computer's user
  only when the device is this computer; then the session opens for VNC.
- This Mac that does not answer: the Sharing pane opens once, "Turn on Screen Sharing" shows, the test repeats on
  the interval, and when it answers the flow carries on as above. Cancel stops the repeats; unmount stops them.
- Any other device that does not answer: the R-079 text names port 5900 and both causes; no update is made.
- A failed update or a refused host shows its message and opens no session.
- Reduced motion: the waiting indicator does not move.
