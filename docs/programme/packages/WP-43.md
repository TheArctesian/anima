## Decisions

- **A-1 Static files through `tower-http` `ServeDir`.** It handles path traversal, ranges and content types.
  It needs the `fs` feature of the workspace `tower-http` (handoff line in `Cargo.toml`). A hand-written file
  server would repeat vetted code in a security path (CUPID Composable).
- **A-2 CSP hashes from `index.html`.** `web_client` reads `index.html` once when it is built, takes the
  SHA-256 of each inline `<script>` body, and puts the hashes in `script-src`. This needs no build-time
  hand-off from WP-44 and stays true for each build. `connect-src` is `'self'` plus `wss://<host[:port]>` of
  the public origin (`ws://` for a loopback `http` origin in tests). Missing `/_app/...` files are 404, never
  `index.html`, so HTML is never served as a script.
- **A-3 Token kinds bind to their transport.** A `browser` token is accepted only from the cookie; a `login`
  or `api_key` token only from `Authorization: Bearer` or the `connection_init` payload. An `api_key` secret
  must have the `anima_` prefix and a `login` token must not; a mismatch is "no identity". So a browser token
  leaked from a cookie jar cannot be replayed as a bearer from another origin, and a cookie cannot carry an API
  key.
- **A-4 The Origin mark.** The `/graphql` edge adds `access::SameOrigin` (private constructor) to the request
  data only when the one `Origin` header equals `ANIMA_PUBLIC_ORIGIN` byte for byte. `signInBrowser` refuses
  with FORBIDDEN without it, before the attempt is recorded. The cookie is read only when the request has no
  `Authorization` header and the mark is present (K7).
- **A-5 One migration for K2.** Migration `0010_access_token_kinds.sql` (T2) adds every K2 column and check:
  `kind`, `name`, `display_prefix`, the scope check, the partial unique index on `name` for `api_key`, the index
  `(kind, operator_id)`. T3 uses it. Prune: expired `login` and `browser` rows at once, expired `api_key` rows
  30 days after expiry (T2).
- **A-6 D-23 list, as root fields refused for an `api_key` identity.** Mutations `createApiKey`,
  `revokeApiKey`, `signInBrowser`, `startSession`, `openFiles`, `shareSession`, `joinShare`, `openRecording`,
  `setSshCredential`, `clearSshCredential`, `setRdpCredential`, `clearRdpCredential`, `setVncCredential`,
  `clearVncCredential`; also `logout` (it would delete the key: managing a key) and the query `apiKeys`
  (managing keys). Any root fragment is refused for an API key, so an inline fragment cannot hide a field. The
  refusal is FORBIDDEN in `parse_query`, before any resolver (K7). A READ key also gets the existing READ rule.
  Extended by CR-8/R-084 (`enrolAgent`, `revokeAgentToken`) and R-100 (`acceptHostKey`,
  `acceptServerCertificate`, `acceptWebCertificate`, `updateDevice`, `deleteDevice`, `setRetention`,
  `deleteRecording`): 25 roots. A test checks the list against K1 both ways (every listed name is a K1 root;
  every K1 root documented closed to API keys is listed).
- **A-7 `joinShare` in the signed-out backstop.** The backstop lives in `access`, so T2 adds `signInBrowser`
  and `joinShare` to the one-root-field rule (API-003). `joinShare` has no resolver until WP-47; until then the
  document fails validation and the backstop answers UNAUTHENTICATED, as for any unknown field.
- **A-8 `logout` clears the cookie** with `Max-Age=0` and the same attributes, only for a `browser` identity.
- **A-9 `bearer_layer`** reads only `Authorization: Bearer`, never the cookie, accepts `login` and `api_key`
  tokens of at least the scope, and answers 401 with an empty body and no `WWW-Authenticate` detail otherwise.
