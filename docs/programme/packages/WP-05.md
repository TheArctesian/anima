## Decisions

- **D-1. `Operator`, `ClientAddr` and `HeartbeatSummary` are defined in `events`.** K3 gives `events::NewAudit` an `Operator` and a `ClientAddr` field and `events::Signal::Heartbeat` a `HeartbeatSummary`, but `events` may import no domain, while `Operator`/`ClientAddr` are listed under `access` and `HeartbeatSummary` under `checks`. Every K3 path stays valid: `events` defines the three types, `access` re-exports `Operator` and `ClientAddr` (`pub use`), and `checks` (WP-09) uses `events::HeartbeatSummary`. No signature changes. Raised to the programme orchestrator for confirmation.
- **D-2. `AuditAction` and `AuditTarget` shape.** K3 names them without a definition. `AuditAction` is a closed enum of verbs (`Login`, `Logout`, `Create`, `Update`, `Delete`, `Start`, `End`, `Accept`, `Pause`, `Resume`, `Activate`, `Deactivate`); `AuditTarget` is an enum over the leaf ID types (`Operator(OperatorId)`, `Site(SiteId)`, `Device(DeviceId)`, `Check(CheckId)`, `Window(WindowId)`, `Session(SessionId)`, `Credential(DeviceId)`, `HostKey(DeviceId)`), which gives `target_type` and `target_id` text. Other packages add no variants without a handoff to WP-05.
- **D-3. Redaction in `audit`.** Before it writes, `audit` replaces secrets in `change` with `"[redacted]"`, at any depth and inside arrays (K1 `AuditEntry.change`, LOG-007). Callers should not pass secrets; this is the backstop, and it prefers over-matching to letting a secret through. *Names.* A key is normalised with NFKD, combining marks dropped (`pässword` gives `password`), split into words at every character that is not an ASCII letter or digit and at case changes (`apiKey`, `api_key`, `APIKey` give `api`, `key`), lower-cased; a plural `s` on the last word is dropped (`apiKeys`), a double `ss` is not (`pass`). The key names a secret when the joined words contain `password`, `passwd`, `passphrase`, `secret`, `token`, `credential`, `authorization`, `cookie`, `bearer`, `privatekey`, `keymaterial`, `totp` or `otpauth`; or a whole word is `otp`, `pem`, `auth`, `pin`, `pass` or `pwd` (`otpCode`, `sshKeyPem`; not `notPaused`, `footprint`, `hotplug`); or the last word is `key`; or the joined form ends with `apikey`, `sshkey`, `accesskey`, `signingkey` or `encryptionkey`. Exactly `hostkey`, `publickey` and `nodekey` are exempt (public keys; the host-key fingerprint is SEC-006 evidence). `keyboard`, `monkey` and `keyId` are kept. *Labels.* In an object whose `field`, `path`, `key`, `setting` or `property` value names a secret (for a path, its last `/` or `.` segment that is not an array index, as in JSON Patch `/ssh/password` or `/secrets/0`), every sibling except the label and `op` is redacted, whole subtrees included. `name` is not a label (a device may be called `secret-lab`). *Values.* Any string containing `-----BEGIN` and `PRIVATE KEY`, or starting with `otpauth://`, is redacted wherever it is. A boolean is never redacted (`hasPassword: true`, `credentialStored`). *Accepted over-matches:* strings under names like `tokenExpiresAt` or `passwordChangedAt`, the SSH settings field `auth`, and the value of a plain `key` field that is not a label (`{"key": "port"}`).
- **D-4. Partitions.** `event_log` and `audit_log` are partitioned by day (DB-004) with no default partition. A SQL function `events.ensure_day_partition(parent, at)` creates the day's partition if it is missing; `record` and `audit` call it before the insert, so an insert never fails for a missing partition (also in other domains' `#[sqlx::test]`s at fixture dates). A daily job creates the next days ahead and drops partitions older than retention (90 days, 1 year; DB-005).
- **D-5. Bus publish timing.** `record` publishes `Signal::Event` after its insert, inside the caller's transaction. A rolled-back transaction can leave a published event that is not stored. Accepted for Phase 1 (the subscription is a live view; the list query is the truth); documented on `record`.
- **D-6. Operator in the request.** An async-graphql guard cannot add data to the context. The HTTP and WebSocket edges resolve the bearer token once per request (`access::operator_for_token`) and put the `Operator` in the request data; `Authenticated` checks that it is there and returns `UNAUTHENTICATED` otherwise. Resolvers read `ctx.data::<Operator>()`. An access schema extension refuses any operation without an operator unless every root field is `login` (API-003 backstop for a resolver that forgets the guard).
- **D-7. Tokens.** 32 random bytes, base64url, shown once; the database keeps SHA-256 of the token (high entropy, so a fast hash is enough). Login tokens have scope `write` and expire after 30 days; `logout` deletes the token. `last_used_at` is updated at most once a minute.
- **D-8. Login throttle.** Each attempt is written to `access.login_attempts`. Five failed attempts for one username or one client address in 15 minutes refuse further attempts for 15 minutes with the same error as a wrong password. An unknown username still runs one argon2id verification (against a fixed dummy hash) so timing does not reveal it.
- **D-9. Operator bootstrap.** The spec has one operator account (OD-2) and no sign-up. The hub binary gets a subcommand `anima-hub operator set <username>` that reads the password from standard input and creates or replaces the operator (argon2id). `anima-hub operator totp <username>` enrols TOTP and prints the `otpauth://` URI once. Logic is in `access`; `main.rs` only dispatches (handoff).
- **D-10. Permitted networks.** The effective list is the rows of `access.permitted_networks`. At start `main.rs` calls `access::permit_networks(&db, &config.permitted_networks)` to upsert the `ANIMA_PERMITTED_NETWORKS` entries (label `ANIMA_PERMITTED_NETWORKS`). The layer caches the list for 30 seconds (clock passed in). Site subnets are not added automatically: `access` may not read `devices.sites` (K2, K3). The operator lists them in `ANIMA_PERMITTED_NETWORKS`. Open question for the programme orchestrator.
- **D-11. Client address.** The client address is the TCP peer (`ConnectInfo<SocketAddr>`); the hub is reached directly over the VPN, so `X-Forwarded-For` is never trusted. An IPv4-mapped IPv6 peer is normalised to IPv4. Refusals are written to the event log (source `ACCESS`, severity `WARNING`) at most once a minute per address, so a scan cannot flood the log.
- **D-12. Layer return type.** K3 writes `-> impl tower::Layer<Route> + Clone`. A bare `impl Layer` hides the service type, which `Router::layer` needs, so the function returns `impl Layer<Route, Service: …> + Clone` with the associated-type bounds spelled out (or a named layer type). Callers write the same `.layer(access::permitted_networks_layer(db, bus, clock))`.
- **D-13. Bind and TLS.** At start the hub refuses a listen address that is unspecified (`0.0.0.0`, `::`) or public (NET-003, SEC-008), and serves TLS with rustls from `ANIMA_TLS_CERT_FILE`/`ANIMA_TLS_KEY_FILE` (SEC-001). Plain HTTP only when both TLS variables are unset and the listen address is loopback (tests and local development).
- **D-14. Test database.** Superseded by R-009: `bun run gates` runs `cargo test` against a throwaway PostgreSQL 17 (`quality/bin/with-postgres.ts`). Database tests never skip without a database (CQ-024) and never create tables in another domain's schema (CQ-032). Builders use the package's scratch server (`127.0.0.1:55432`) by exporting `DATABASE_URL`, which `with-postgres` respects.
- **D-15. Out of hub scope.** NET-004 ("Not on the network" in the navigation bar) is client work (WP-11); SEC-009 (client never logs tokens) is client work (WP-11, WP-16). The hub side of both: GraphQL errors and the process log never contain tokens (LOG-007), tested here.

### Test plan

Every test that proves a requirement names its ID (K7). Database tests use `#[sqlx::test(migrations = "migrations")]` with K6 fixture names.

- T1: `record` stores the row and publishes one `Signal::Event` to a subscriber; a device event keeps the copied name; `audit` stores operator name, client address and change (LOG-005); redaction at depth (LOG-007); an insert at any date succeeds (partition function); `Authenticated` refuses a context without `Operator` with `UNAUTHENTICATED`.
- T2: filter by severity, source, device and since; pagination stable across pages; `eventAdded` delivers only at or above `minSeverity`; retention drops old partitions and keeps the newer ones (fixed clock).
- T3: wrong password, unknown user and throttled user give the same error; throttle after five failures, released after 15 minutes (fixed clock); token stored only as hash; expired token refused; `logout` revokes; every root field except `login` refuses without a token (mutation: remove the extension or a guard → test fails); `login`/`logout` audited; token never in a GraphQL error or log line.
- T4: an address outside every network gets 403 and one `ACCESS` warning event; inside passes; IPv4-mapped IPv6 handled; refusal events limited per minute; bind check refuses `0.0.0.0` and a public address.
- T5: `UPDATE`, `DELETE`, `TRUNCATE` on `audit_log` fail; partition drop after retention works.
- T6: RFC 6238 test vectors; ±1 step accepted, ±2 refused; a reused step refused; login with TOTP enabled and no code refused.
- T7: depth 11 refused; introspection refused when production mode is set; an internal error shows only the generic message; log line has `request_id`.
