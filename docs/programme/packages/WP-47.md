## Decisions

- **S-1 Shares live in memory only.** K2 has no share table and K4 §10 keeps the token's SHA-256 "in memory,
  with the share". A hub restart ends every session (`close_stale`), so nothing is lost. `SessionShare` and
  `Session.shares` read the registry.
- **S-2 One registry beside the tickets.** `share::Shares` sits in `Live` as `files::Tickets` does, with its own
  lock; every method is a short synchronous section, never across an `.await`; time comes in as a parameter.
  The share token reuses `tickets::TicketToken` and `tickets::hash_of` (32 OS-random bytes, base64url, SHA-256
  kept), so one token rule serves tickets and shares.
- **S-3 Limits (D-9).** `expiresInMinutes` 5..1440 (default 60), `maxViewers` 1..10 (default 3): VALIDATION on
  the field. At most 32 live shares per hub: UNAVAILABLE beyond. `CONTROL` is accepted as given; the confirm is
  the client's (D-9).
- **S-4 Who may share.** `shareSession` needs the session to be live, to be the caller's (operator ID), and to
  have an open tunnel (a redeemed ticket). Unknown session: NOT_FOUND. Another operator's: FORBIDDEN. Ended, or
  not yet opened: CONFLICT. `endShare` by the share's owner only, with the same answers.
- **S-5 One keeper per share.** `shareSession` spawns one task per share that waits for the first of: expiry,
  `endShare`, the owner's tunnel deregistering (owner session end, K4 §5). It removes the share, tells each
  viewer (4004, SSH `end` `SHARE_ENDED`), frees the replay buffer, then writes `share.end` (cause `expired`,
  `ended` or `session_ended`) and an Info event with `Source::Session`. Bounded by S-3's 32.
- **S-6 Audit.** `share.create`: `AuditAction::Create`, `AuditTarget::Share`, change `{sessionId, access,
  expiresAt, maxViewers}`. `share.join`: new `AuditAction::Join` ("join"), operator = the share's owner (a
  viewer is not an operator, and `audit_log.operator_id` is not null), client = the viewer's address, change
  `{name}` (cleaned). `share.end`: `AuditAction::End`, change `{cause}`. Each with an Info event. No token in any.
- **S-7 `joinShare` (K4 §10).** In order: the client address must not be throttled; hash the token; look it up.
  A miss counts as one failed login attempt for the address. A hit that is expired, ended or full is refused
  too. Every refusal is FORBIDDEN with one text ("This share link is not valid or has ended."). `name` is
  `text::clean(name, 32)`, empty becomes `viewer`. `display` uses `start`'s `checked_display` bounds.
- **S-8 Viewer slots.** A slot is taken when `joinShare` issues the watch ticket and freed when the ticket
  expires unredeemed or the viewer's socket ends; `maxViewers` bounds taken slots. `SessionShare.viewers` counts
  connected viewers only.
- **S-9 Watch tickets.** Their own table in the share registry (as `files::Tickets`), with every K4 §1
  property: 32 bytes, SHA-256 in memory, 30 s, single use, bound to the client address and to `/watch`. A watch
  ticket names its share, never the owner's session, to the viewer.
- **S-10 RDP and VNC viewers join guacd (K4 §3, §10, GW-014).** The owner's tunnel registers guacd's connection
  ID with the session's audience when `ready` arrives and drops it at the end; it never leaves the hub. A viewer
  gets its own guacd connection: `select $<id>`, the viewer's `size`, `audio` and `video` empty, the owner's
  `image` list, `timezone` UTC, `name` the cleaned viewer name, `connect` with `read-only` `true` for VIEW and
  empty for CONTROL, every other value empty. The viewer relay forwards only `sync`, `ack`, `nop`, `disconnect`
  and checked `size` (VIEW), plus `key`, `mouse`, `touch` (CONTROL); anything else closes 1002. From guacd it
  drops `clipboard`, `file`, `audio`, `argv`, `pipe` and `required` and their streams (D-9), keeps the BMP guard
  and the fixed `error` text.
- **S-11 Reading of K4 §4 "also passes it to the session's viewers".** Read with §10 ("which have their own guacd
  connections"): guacd feeds each RDP/VNC viewer through its join connection, so the owner's relay copies
  nothing to viewers. The owner's tunnel's fan-out part is the connection-ID registration and the end. (Asked of
  the programme orchestrator, Q-2.)
- **S-12 SSH viewers (K4 §8.8, §10, D-10).** While a share is live, each output frame goes to a 64 KiB replay
  ring (oldest bytes dropped; memory only; freed when the last share of the session ends; never written, logged
  or recorded) and to each viewer's queue of at most 8 frames with `try_send`; a full queue closes that viewer
  4002. The owner's relay never awaits a viewer. A viewer gets `joined` with the owner's size, the replay, then
  live frames, `resize` when the owner resizes, `ping`, and `end` `SHARE_ENDED` before 4004. CONTROL viewer
  input goes through a bounded channel that the owner's relay reads only when no write is in flight, and is
  written as the owner's input is (K4 §8.5 limits). A viewer never sends `resize`.
- **S-13 The session limit (RA-036, K4 §1 step 1).** In `start`'s transaction, before the insert:
  `pg_advisory_xact_lock` on a key derived from the device ID, then count the device's rows with
  `ended_at is null`; at or over the limit is CONFLICT `Conflict::SessionLimit` ("This device has reached its
  session limit."). Viewers and files tunnels make no session row, so they never count.
- **S-14 Devices columns (K2 0120).** `session_limit int null check (session_limit between 1 and 100)`,
  `record_sessions bool not null default false`. Create: `null` is no limit, 1..100 sets, anything else is
  VALIDATION. Update: `null` keeps, `0` clears, 1..100 sets. `recordSessions` create default false, update
  `null` keeps. Both appear in the device audit change. WP-48 adds what the flag does.
- **S-15 The share URL.** `<public origin>/shared#<token>` from `Config.public_origin` (K7), or from
  `access::PublicOrigin` if WP-43 has put it in the schema data by T3's build.
- **S-16 `WatchTicket.recording`.** Served as `false` until WP-48 wires recording; noted for WP-48.
