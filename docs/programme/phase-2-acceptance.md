## Operator steps

Run these on the operator's machines after the hub, with the WP-23 gateway steps applied, has been redeployed. Each
step names what to look for. Record the result in `docs/programme/operator-changes.md`.

- **O-1 RDP (criterion 1). Hardware: a Windows machine with RDP and NLA on, reachable by the hub.** First add a Headscale
  grant `tag:hub` → `device-<name>` on tcp:3389, with policy tests (WP-23 could). Then:
  1. Add the device as Windows with RDP on, the security mode left at ANY, and a username and password. Save.
  2. In Settings → RDP → Test connection, check that the hub shows the server certificate. Choose Accept certificate.
  3. On the card, choose RDP. Check that the tab grows from the button and the desktop draws.
  4. Resize the window. About 150 ms after the window stops, the Windows resolution must follow (RA-004).
  5. Copy text on Windows and paste it on the Mac, then the other way (RA-005). In the macOS app, check that WebKit allows the device-to-system clipboard write (WP-24 risk).
  6. Choose Keys → Ctrl+Alt+Delete. The Windows security screen must open (RA-006).
- **O-2 RDP certificate (criterion 2). Same machine.**
  1. With the certificate accepted (O-1 step 2), regenerate the RDP certificate on Windows: delete it in `certlm.msc` → Remote Desktop, then restart the TermService service.
  2. Open RDP again. The session must stop with close 4003, the certificate warning and "Check certificate". It must not show "You ended the session." (motion report, settled item 8).
  3. Check certificate must show the new fingerprint. Accept it, and the session must open.
  4. Turn on Ignore certificate, or set security to RDP. The card and header must show the Warning badge (RA-020).
  5. Confirm that guacd accepted the `sha256:` `cert-fingerprints` value in step 1. If it did not, the session is refused even with a matching pin: report it to the programme.
- **O-3 VNC (criterion 3). Hardware: a Mac with Screen Sharing on, and a Linux desktop with a VNC server.** The VPN grant for tcp:5900 to `device-stephens-mac` exists (WP-23 T3). For each machine:
  1. Turn VNC on in Settings. Enter the username (needed for macOS) and password, and save.
  2. The card and header must show "VNC". Choose VNC; the desktop must draw scaled to fit, and keyboard and pointer must work.
  3. Repeat with paste off and then copy off in Files and clipboard. The clipboard must not cross in the direction that is off (criterion 5, live).
  - **Linux run, 2026-11-07 (pop-os, 100.64.0.3).** VPN grant `device-pop-os` tcp:22 and tcp:5900 (b33788f8). On COSMIC 1.11 no VNC server can take input: krfb and any other server that uses the xdg screen-share portal crash `xdg-desktop-portal-cosmic` 1.11.0 ("create_frame sent before the previous frame was destroyed", upstream #389; fix proposed in cosmic-protocols PR #95), and wayvnc cannot inject input because cosmic-comp lacks `zwlr_virtual_pointer_manager_v1`. The operator chose wayvnc `--disable-input` bound to the VPN address, with control over SSH, until COSMIC ships native remote desktop. wayvnc's `username` must equal the VNC user name stored in Anima, or the session fails with only "Unable to connect" (#53). The Linux desktop build needs `RUSTFLAGS=--cap-lints=warn` (#52). Retest step 2 on Linux when apt offers a fixed portal.
- **O-4 SFTP (criterion 6). Hardware: a real SSH server (OpenSSH) with an accepted host key.**
  1. Open SSH, then choose Files. The home folder must list.
  2. Upload a small file and download it again. The bytes must match.
  3. Turn upload off in Settings and try again. The panel must show the refusal. Do the same for download.
  4. In the device Logs, each transfer must have one audit entry with path and size, and no content.
  5. In the desktop app, check that the download is saved, and where (wry saves to `~/Downloads` under the suggested name; WP-32 could).
- **O-5 Wake-on-LAN (criterion 8). Hardware: a device that sleeps on a LAN, and a relay device at that site with SSH, an accepted host key and `wakeonlan` installed.**

  2. Put the device to sleep and wait until it shows Down.
  3. Open a session from its card. The steps must show "Waking <device>", and the session must connect when the device answers, within 120 s.
  4. Check that the Logs show one Info event and the audit entry `device.wake` naming the relay.
