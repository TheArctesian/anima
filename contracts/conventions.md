# K7 — Conventions

Status: **frozen for Phase 3** (change only through a programme ruling, CON-001). Phase 2 additions are marked (Phase 2). Phase 3 additions are marked (Phase 3).

## IDs

- Every entity ID is a UUID v7 (time-ordered), generated by the hub.
- Rust: one newtype per entity, all in the leaf module `crates/hub/src/ids.rs` (see `hub-domains.md`), so that domains do not import each other only for an ID:
  `OperatorId`, `SiteId`, `DeviceId`, `CheckId`, `WindowId`, `SessionId`, `EventId`, and (Phase 2) `WebInterfaceId`, `MetricSeriesId`, and (Phase 3) `ApiKeyId`, `ChannelId`, `DeliveryId`.
  Shape: `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize, sqlx::Type)] #[sqlx(transparent)] pub struct DeviceId(Uuid);`
- GraphQL: the `ID` scalar, as the UUID string. Parse with the newtype's `FromStr` at the API boundary.
- TypeScript: branded strings, e.g. `type DeviceId = string & { readonly __brand: 'DeviceId' }`.

## Time

- All stored and transmitted times are UTC. GraphQL scalar `DateTime` = RFC 3339 in UTC; the hub writes it as `2026-11-04T09:00:00+00:00` (async-graphql's chrono scalar, R-012). Readers accept any RFC 3339 offset and compare instants, never text (R-033).
- Durations in the API are integers with the unit in the field name: `intervalSeconds`, `responseTimeMs`.
- Core logic takes `now: DateTime<Utc>` as a parameter (CQ-021). Only `main.rs` and I/O edges read the clock, through `Clock` (see `hub-domains.md`).

## Errors

- Each hub domain has `pub enum Error` with `thiserror` (CQ-022). No `anyhow` in domains.
- Each domain error maps to one GraphQL error code in its `graphql.rs`:

  | `extensions.code` | Meaning |
  | --- | --- |
  | `UNAUTHENTICATED` | No valid token |
  | `FORBIDDEN` | Valid token, not permitted (or address not in a permitted network) |
  | `NOT_FOUND` | Entity does not exist |
  | `VALIDATION` | Input rejected; `extensions.fields` lists `{ field, message }` |
  | `CONFLICT` | Duplicate or stale state (e.g. host key mismatch) |
  | `UNAVAILABLE` | A dependency (database, gateway, device) is unreachable |
  | `INTERNAL` | Anything else; the message is generic, details go to the process log only (API-010) |

- (Phase 3) No new codes. A token-kind refusal and a READ refusal are FORBIDDEN. A refused notification target is a delivery with `ok: false` and the fixed message "The target address is not permitted.", never an error that names the address.
- Messages are plain sentences for the operator. They never contain SQL, file paths, secrets or stack traces.

## Authentication transport (R-020)

- HTTP `POST /graphql`: header `Authorization: Bearer <token>`.
- `graphql-transport-ws` (API-002): the client sends the token in the `connection_init` payload as `{ "authorization": "Bearer <token>" }`. Browsers cannot set headers on a WebSocket, and a query parameter would put the token in logs (LOG-007). The hub resolves it in its connection-init handler with `access::operator_for_token` and closes the socket with code `4403` (Forbidden) when the token is missing or not valid.
- The token never goes in a URL. The tunnel (K4) uses its own single-use ticket instead.

(Phase 3) Authentication transport adds:
  - **Browser:** the cookie `__Host-anima` (`Secure; HttpOnly; SameSite=Strict; Path=/`, `Max-Age` 7 days),
    set only by `signInBrowser` and cleared by `logout`. The hub uses the cookie only when the request has no
    `Authorization` header and its `Origin` equals `ANIMA_PUBLIC_ORIGIN`. That applies to `POST /graphql` and
    to the `GET /graphql` WebSocket upgrade. A socket that signed in by cookie may send an empty
    `connection_init` payload. A cookie with any other Origin, or with none, is ignored: the request is
    signed out.
  - **API keys:** the same `Authorization: Bearer` header. The secret is `anima_` plus 43 base64url characters.
    The kind rules of D-23 are enforced in the access guard, before any resolver, with FORBIDDEN.

(Phase 3) **HTTP surface.** Every route sits behind the NET-002 layer and is logged by its template only.

  | Route | Authentication | Owner |
  | --- | --- | --- |
  | `POST /graphql`, `GET /graphql` (WebSocket) | Bearer header or browser cookie; signed out only for one `login` or `signInBrowser` (R-111) | `access`, each domain |
  | `/terminal`, `/tunnel`, `/files` | Single-use ticket (K4 §1) | `sessions` |
  | `GET\|POST /push/{token}` | Push token | `checks` |
  | `GET /metrics` | Bearer token, READ or higher | `checks`, behind `access::bearer_layer` |
  | `POST /agent/v1/enrol`, `POST /agent/v1/push`, `POST /agent/v1/renew` | Enrolment code in the body, or agent token (K8) | `metrics` |
  | `GET /health` | None; body `ok` | wiring |
  | Any other `GET` (the web client) | None; static files only, `index.html` for unknown paths | `web_client.rs` |

  Static file headers: `Content-Security-Policy: default-src 'self'; script-src 'self' <SvelteKit hashes>;
  connect-src 'self' wss://<public host>; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline';
  font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`;
  `X-Content-Type-Options: nosniff`; `Referrer-Policy: no-referrer`; `Cross-Origin-Opener-Policy: same-origin`;
  `Strict-Transport-Security: max-age=31536000`; `Cache-Control: no-cache` for `index.html` and
  `public, max-age=31536000, immutable` under `/_app/immutable/`. CORS (`CLIENT_ORIGINS`) does not change.

## Logging (process log)

- `tracing` with JSON output (LOG-001). Standard fields: `request_id`, `operator_id`, `device_id`, `session_id`, `domain`.
- Spans at I/O boundaries only (CQ-026): GraphQL request, SQL call, probe, gateway connection, tunnel.
- Never log: passwords, private keys, passphrases, tokens, tunnel tokens, session content (LOG-007). (Phase 2) Also never log: RDP and VNC passwords, SNMP communities and v3 passwords, file content, and file paths in the process log (paths go only to the audit log). Secret types implement neither `Debug` nor `Display` (see `hub-domains.md`).
- (Phase 3) Never log API key secrets, browser tokens and cookie values, notification secrets (whole webhook URLs, webhook header values, ntfy topics and tokens, SMTP passwords, Apprise URLs and keys), email recipient addresses in the process log, a notification target's reply body, agent tokens and agent enrolment codes (K8).

## Prometheus series (Phase 3, INT-001, INT-002)

Content type `text/plain; version=0.0.4; charset=utf-8`. Labels
`check_id`, `check_name`, `check_type`, `device_id`, `device_name`, `site`. Label values are cleaned with
`text::clean` and escaped as the format requires. No label holds a status, a time, an address or a message.

| Series | Type | Value |
| --- | --- | --- |
| `anima_check_status` | gauge | 0 Down, 1 Up, 2 Degraded, 3 Maintenance, 4 Unknown (also paused) |
| `anima_check_up` | gauge | 1 for Up or Degraded, else 0 |
| `anima_check_response_time_seconds` | gauge | The last heartbeat; absent when it has none |
| `anima_check_uptime_ratio` | gauge | 0..1, with label `window` = `1d`, `7d` or `30d`, from the aggregates (CHK-011) |
| `anima_check_certificate_days_left` | gauge | Only for checks with a certificate |
| `anima_check_domain_days_left` | gauge | Only for domain expiry checks |
| `anima_device_status` | gauge | As `anima_check_status`; labels `device_id`, `device_name`, `site` |

## Naming

- Follow CQ-030 (banned words) and the domain folder shape in spec Section 13.
- GraphQL: types `PascalCase`, fields `camelCase`, enums `SCREAMING_SNAKE_CASE`.
- SQL: one PostgreSQL schema per domain (see `database.md`), tables and columns `snake_case`.

## Tests

- A test that proves a requirement names the ID: Rust `fn chk_002_down_only_after_retries()`, TypeScript `it('CHK-002: down only after retries', …)`.
- Database tests use a throwaway database per test (`#[sqlx::test]`), never a shared one.
- Use the fixtures in `contracts/fixtures/` for synthetic data. Never real device data.
- (Phase 3) A test that proves a Phase 3 requirement names the ID, for example `fn not_005_resend_after_n_down_beats()` or `it('RA-036: the start past the session limit is refused', …)`.
